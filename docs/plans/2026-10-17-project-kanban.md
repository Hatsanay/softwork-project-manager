# แบบระบบ: บอร์ดงานแบบ Trello (Kanban) ในหน้าโปรเจกต์ — 17 ต.ค. 2026

สถานะ: **เสร็จ B-1 ถึง B-3 (17 ต.ค. 2026)** — ความคืบหน้าดูหัวข้อ 7
เกี่ยวข้อง: หน้าโปรเจกต์ `frontend/app/(protected)/projects/view/page.tsx` (ตาราง "งาน (Task)") · `backend/src/controllers/task.controller.js`

ตอนนี้งานในโปรเจกต์แสดงเป็นตาราง ต้องเปิดงานทีละอันเพื่อเปลี่ยนสถานะ — มองไม่เห็นว่างานกองอยู่ขั้นไหน
บอร์ดแบบ Trello ให้เห็นงานทั้งโปรเจกต์เป็น 4 คอลัมน์ตามสถานะที่มีอยู่แล้ว (รอทำ · กำลังทำ · รอตรวจ · เสร็จ) และลากการ์ดข้ามคอลัมน์เพื่อเปลี่ยนสถานะ

หลัก: **ไม่สร้างสถานะ/สิทธิ์ใหม่** — ใช้สถานะ 4 แบบและบิตสิทธิ์ในโปรเจกต์เดิมทั้งหมด (changeTaskStatus / changeOwnTaskStatus / …)
ลากการ์ด = เรียกเส้นทางเปลี่ยนสถานะเดิม → ประวัติงาน, ความคืบหน้าโปรเจกต์, KPI แดชบอร์ด ทำงานเหมือนเดิมทุกอย่าง

## 0. คำถามที่ต้องตัดสินใจ (ผู้ใช้)

**K8 ป้ายใช้สีครบชุดแบบ Trello** (รวมเขียว/เหลือง/แดง) — เป็น **ข้อยกเว้นของกติกาธีม เฉพาะป้ายบนการ์ดบอร์ดงาน** ตามที่เจ้าของระบบเลือก (หัวข้อ 2.1)

ค่าแนะนำที่ไม่ได้ถาม (แจ้งเปลี่ยนได้):
- **K5 มุมมองเริ่มต้น** — ตาราง/บอร์ด สลับได้ในหัวการ์ด "งาน" · จำค่าที่เลือกไว้ต่อเครื่อง (localStorage) · ตารางเดิมยังอยู่ครบ
- **K6 คอลัมน์ "เสร็จ"** — แสดง 20 ใบล่าสุด (ตามวันที่เสร็จ) + ปุ่ม "ดูทั้งหมด" กันบอร์ดยาวเมื่อโปรเจกต์ใหญ่
- **K7 ไม่ทำ** — จำกัดจำนวนงานต่อคอลัมน์ (WIP limit) · คอลัมน์ตั้งชื่อเอง · อัปเดตสดแบบ real-time (ใช้โหลดใหม่เมื่อกลับมาที่แท็บ + หลังทุกการกระทำแทน)

## 1. หน้าตา

```
┌ งาน (Task) ───────────────────────────── [ตาราง | บอร์ด]  [+ เพิ่ม Task] ┐
│ ตัวกรอง: [เฉพาะงานของฉัน] [ผู้รับผิดชอบ ▾] [เลยกำหนด] [ค้นหา…]  [Task | Task+Subtask] │
│                                                                         │
│ รอทำ (5)        กำลังทำ (3)      รอตรวจ (1)       เสร็จ (12)             │
│ ┌───────────┐   ┌───────────┐    ┌───────────┐    ┌───────────┐         │
│ │ ออกแบบ API │   │ หน้า login │    │ รายงานขาย │    │ ตั้งค่า DB │         │
│ │ ●● 2 คน    │   │ ● สมชาย    │    │ ⚠ 2 ปัญหา │    │ ✓ 18 ต.ค.  │         │
│ │ 📅 20 ต.ค.  │   │ ▓▓▓░ 3/4   │    │           │    │           │         │
│ └───────────┘   └───────────┘    └───────────┘    └───────────┘         │
│ + เพิ่มในคอลัมน์นี้                                   ดูทั้งหมด (12) │
└─────────────────────────────────────────────────────────────────────────┘
```

**การ์ด** (ข้อมูลที่มีอยู่แล้วทั้งหมด): ชื่องาน · ผู้รับผิดชอบ (วงกลมอักษรย่อ สูงสุด 3 + "+2") · วันครบกำหนด (แดงเมื่อเลยกำหนดและยังไม่เสร็จ — สีแดงตามกติกาธีม) ·
ป้ายปัญหาแดง/ฟ้า และแชทยังไม่อ่าน (แบบเดียวกับตาราง) · แถบ subtask เสร็จ x/y · ป้าย "ยังไม่มีคนรับ" + ปุ่ม "รับงาน" ในโปรเจกต์ Agile ·
น้ำหนักงานเมื่อเปิดถ่วงน้ำหนัก · กดการ์ด = เปิดหน้าต่างรายละเอียดงานเดิม (subtask/ปัญหา/แชท/ประวัติ)

**มือถือ (ผู้ใช้หลัก — ตรวจ 360/400px)**: คอลัมน์กว้างเกือบเต็มจอ เลื่อนซ้าย-ขวาทีละคอลัมน์ (scroll snap) · แถบหัวคอลัมน์ด้านบนกดกระโดดไปคอลัมน์นั้นได้ ·
ลากด้วยการกดค้างการ์ด (กันลากโดยบังเอิญตอนเลื่อนจอ) · ทุกการ์ดมีปุ่ม "ย้ายไป…" เปิดแผ่นจากล่างเลือกสถานะ — ใช้ได้แม้ลากไม่ถนัด

**ข้อความกำกับ (ร่าง)**
- ใต้หัวบอร์ด: "ลากการ์ดข้ามคอลัมน์เพื่อเปลี่ยนสถานะ (มือถือ: กดค้างแล้วลาก หรือกด ⋯ → ย้ายไป) · การ์ดที่มีรูปกุญแจ = คุณเปลี่ยนสถานะงานนั้นไม่ได้"
- การ์ดที่ลากไม่ได้ (กดค้าง): แถบด้านล่าง "เปลี่ยนสถานะไม่ได้ — ต้องเป็นผู้รับผิดชอบงานนี้ หรือมีสิทธิ์เปลี่ยนสถานะทุกงานในตำแหน่งของคุณ"
- เรียงลำดับไม่ได้: "ลำดับในคอลัมน์ตั้งได้เฉพาะผู้มีสิทธิ์แก้ไขงาน — การ์ดที่คุณย้ายมาจะอยู่ท้ายคอลัมน์"
- ลากไปเสร็จทั้งที่ subtask ยังไม่ครบ: ถามยืนยัน "subtask ยังไม่เสร็จ 2 จาก 5 — ยังย้ายไป 'เสร็จ' ไหม?" (ระบบเดิมไม่บังคับ — คงไว้ แค่เตือน)
- มีคนย้ายไปก่อน: แถบ "งานนี้ถูกย้ายไป 'รอตรวจ' โดยคนอื่นแล้ว — โหลดบอร์ดใหม่ให้แล้ว"

## 2.1 ป้ายสี (label) และ checklist (K1-ข)

**ป้ายสี — ของแต่ละโปรเจกต์ (แบบ Trello ที่ป้ายอยู่กับบอร์ด)**
- `tb_project_labels`: `pl_id` (int auto) · `pl_project_id` (FK cascade) · `pl_name` varchar(50) · `pl_color` enum 10 สี · `pl_sort_order` · ผู้สร้าง/เวลา · unique (โปรเจกต์, ชื่อ) · สูงสุด 30 ป้ายต่อโปรเจกต์
- `tb_task_labels`: (`tl_task_id`, `tl_label_id`) PK · ลบงาน/ลบป้าย = ลบความผูกตาม (cascade) · สูงสุด 10 ป้ายต่องาน
- สี (K8 — ชุด Trello 10 สี): เขียว · เหลือง · ส้ม · แดง · ม่วง · น้ำเงิน · ฟ้า · เขียวมะนาว · ชมพู · ดำ — เก็บเป็นรหัส (`green` … `black`) ไม่เก็บค่า hex (เปลี่ยนเฉดทีหลังได้ที่เดียว)
  - **ข้อยกเว้นธีม (เจ้าของระบบเลือก 17 ต.ค. 2026):** ใช้ได้เฉพาะป้ายบนการ์ด/ในหน้าต่างงาน/ตัวกรองป้าย · ส่วนอื่นของระบบยังใช้กติกาสีเดิม (เขียว/เหลือง/แดง = สถานะเท่านั้น)
  - กันสับสนกับสีสถานะ: ป้ายเป็นแถบสีทึบมี **ชื่อป้ายเขียนบนป้ายเสมอ** (ต่างจากป้ายสถานะที่เป็นจุดสี+ขอบอ่อน) · ตัวหนังสือบนป้ายเลือกขาว/ดำตามความเข้มของสีให้อ่านออก (contrast ≥ 4.5:1)
  - เพิ่มบรรทัดข้อยกเว้นนี้ใน `docs/CODING_GUIDELINES.md` หัวข้อ 6 ตอนเขียนโค้ด
- สิทธิ์: สร้าง/แก้/ลบป้ายของโปรเจกต์ = `editProjectInfo` · ติด/เอาป้ายออกจากงาน = คนที่แก้ไขงานนั้นได้ (`editTask` หรือผู้รับผิดชอบ — กติกาเดิมของการแก้งาน)
- ลบป้ายที่ติดอยู่หลายงาน: หน้าต่างยืนยันบอกจำนวนงานที่จะหลุดป้าย

**checklist — รายการย่อยเบาๆ ในงาน (ต่างจาก subtask)**
- `tb_task_checklist_items`: `tci_id` (int auto) · `tci_task_id` (FK cascade) · `tci_text` varchar(200) · `tci_is_done` · `tci_sort_order` · `tci_done_by`/`tci_done_at` · ผู้สร้าง/เวลา · สูงสุด 50 ข้อต่องาน
- **ไม่นับเข้าความคืบหน้าโปรเจกต์/KPI** (subtask นับ) — ข้อความกำกับ: "checklist ไว้จดสิ่งที่ต้องทำย่อยๆ ไม่มีผู้รับผิดชอบ/สถานะ และไม่นับในความคืบหน้าโปรเจกต์ — งานที่ต้องติดตามจริงให้สร้างเป็น subtask"
- สิทธิ์: ติ๊ก/เอาติ๊กออก = คนที่เปลี่ยนสถานะงานนั้นได้ (กติกาเดิม) · เพิ่ม/แก้ข้อความ/ลบ/เรียง = คนที่แก้ไขงานนั้นได้
- ประวัติงาน (task log): บันทึกเพิ่ม/ลบข้อ และติ๊กเสร็จ/เอาออก (เห็นในประวัติงานเดิม)
- การ์ดแสดง "☑ 3/5" (ครบแล้วเป็นตัวเลขสีเขียว — เป็น "เสร็จ" ตามความหมายสีสถานะ)

**ไม่แสดงในลิงก์ลูกค้า (share)** ทั้งป้ายและ checklist — เป็นข้อมูลภายในทีม

## 2. Backend (เปลี่ยนน้อยที่สุด)

| เส้นทาง | เปลี่ยน |
|---|---|
| `PUT /projects/:projectId/tasks/:id/status` | รับ `expected_status` (ไม่บังคับ — หน้าเดิมไม่ส่งก็ทำงานเหมือนเดิม) · ถ้าส่งมาแล้วสถานะปัจจุบันไม่ตรง → 409 `TASK_STATUS_CHANGED` (สองคนลากการ์ดใบเดียวกันพร้อมกัน) · ล็อกแถวงาน (`FOR UPDATE`) ก่อนอ่าน · ย้ายไปคอลัมน์ใหม่ = ลำดับท้ายคอลัมน์ |
| `PUT /projects/:projectId/tasks/reorder` (ใหม่) | `{ status, task_ids: [...] }` เรียงใหม่เฉพาะงานในคอลัมน์นั้น (ระดับเดียวกัน: task หลัก หรือ subtask ใต้แม่เดียวกัน) · ต้องมี `editTask` (K4-ก) · id ต้องอยู่ในโปรเจกต์และสถานะนั้นครบทุกตัว ไม่งั้น 409 ให้โหลดใหม่ |
| `GET /projects/:projectId/tasks` | ไม่เปลี่ยน — มีสถานะ/ผู้รับผิดชอบ/ลำดับ/subtask อยู่แล้ว · เพิ่ม `subtask_done`/`subtask_total` ต่อ task หลักถ้ายังไม่มี |

| `GET/POST/PUT/DELETE /projects/:projectId/labels(/:labelId)` (ใหม่) | ป้ายของโปรเจกต์ · อ่าน = สมาชิก · แก้ = `editProjectInfo` |
| `PUT /projects/:projectId/tasks/:id/labels` (ใหม่) | `{ label_ids: [...] }` แทนที่ทั้งชุด · ป้ายต้องเป็นของโปรเจกต์เดียวกัน |
| `POST/PUT/DELETE /projects/:projectId/tasks/:id/checklist(/:itemId)` + `PUT …/checklist/:itemId/toggle` + `PUT …/checklist/reorder` (ใหม่) | checklist ตามสิทธิ์หัวข้อ 2.1 |
| `GET /projects/:projectId/tasks` | เพิ่มต่อแถว: `labels` (id/ชื่อ/สี) · `checklist_done`/`checklist_total` · `subtask_done`/`subtask_total` (คำนวณใน query เดียว ไม่วนทีละงาน) |

- ลำดับในคอลัมน์ใช้ `task_sort_order` เดิม (ตารางก็เรียงตามนี้)
- audit: "เปลี่ยนสถานะงาน (บอร์ด)" ใช้ของเดิม · เพิ่ม "เรียงลำดับงานในบอร์ด" · "เพิ่ม/แก้/ลบป้ายของโปรเจกต์" · "ติดป้ายงาน" · "แก้ checklist ของงาน"
- deploy_schema: **3 ตารางใหม่** (`tb_project_labels`, `tb_task_labels`, `tb_task_checklist_items`) + `create_project_manager.sql` + manifest · ไม่แก้ตารางเดิม

## 3. Frontend
- แยก component ใหม่ใน `projects/view/_components/` (`task-board.tsx`, `board-column.tsx`, `board-card.tsx`, `move-to-sheet.tsx`) — **ไม่เพิ่มบรรทัดใน `page.tsx` ที่ยาว 2,700 บรรทัดเกินจำเป็น** (CODING_GUIDELINES 2) · ส่งตัวเปิดรายละเอียดงาน/รับงาน/สิทธิ์เข้ามาเป็น props
- อัปเดตแบบมองโลกในแง่ดี: การ์ดย้ายทันที → เรียก API → ผิดพลาดย้ายกลับที่เดิม + แถบบอกเหตุผล (ไม่ใช่ toast)
- สิทธิ์บนหน้าเว็บใช้แค่ซ่อน/ล็อกการ์ด — backend ตรวจจริงเสมอ (ใช้ฟังก์ชันเดียวกับปุ่มเปลี่ยนสถานะเดิม)
- โหลดบอร์ดใหม่เมื่อกลับมาที่แท็บ (visibilitychange) — เห็นงานที่คนอื่นย้ายโดยไม่ต้องกดรีเฟรช

## 5. เทสต์
- API: เปลี่ยนสถานะด้วย `expected_status` ตรง/ไม่ตรง (409) · ไม่ส่ง `expected_status` ทำงานเหมือนเดิม · ลำดับ: ไม่มีสิทธิ์ (403) · id ไม่ครบ/ปนคอลัมน์อื่น (409) · ลำดับใหม่ถูกต้อง · ย้ายคอลัมน์แล้วอยู่ท้าย
- หน้าจอ: 1440 / 400 / 360px · ลากด้วยเมาส์ · ปุ่มย้ายไป… บนมือถือ · การ์ดล็อก · คอลัมน์เสร็จ 20 ใบ
- เทสต์เดิมของงาน/แดชบอร์ด/ความคืบหน้าโปรเจกต์ต้องผ่านครบ

## 7. ความคืบหน้า
- ✅ **B-1 backend** (17 ต.ค.) — `PUT …/tasks/:id/status` รับ `expected_status` + ล็อกแถว (409 `TASK_STATUS_CHANGED`) · ย้ายไปสถานะเดิม = ไม่เขียนประวัติซ้ำ · `PUT /projects/:id/task-order` (editTask · ต้องส่งครบคอลัมน์ ไม่งั้น 409 `ORDER_CHANGED`) · ป้ายของโปรเจกต์ + ติดป้ายงาน + checklist (`services/task-board.service.js`, `controllers/task-board.controller.js`, `routes/task-board.routes.js`, `shared/schemas/task-board.mjs`) · 3 ตารางใหม่ใน `create_project_manager.sql` + `deploy_schema.sql` · รายการงานมี `labels`, `checklist_*`, `subtask_*` · รายละเอียดงานมี `labels`, `checklist` · audit ครบ · เทสต์ `api-task-board.test.js` (5) + ต้นแบบรูปร่าง API ใหม่
- ✅ **B-2 บอร์ด** (17 ต.ค.) — `projects/view/_components/board/` (task-board · board-column · board-card · move-to-sheet · label-colors · board-types) · สลับตาราง/บอร์ดจำต่อเครื่อง · ลากด้วยเมาส์/กดค้าง 250ms บนมือถือ/คีย์บอร์ด · ปุ่ม ⋯ ย้ายไป… · ตัวกรอง งานของฉัน/เลยกำหนด/ค้นหา/ป้าย · โหมดแสดง subtask · คอลัมน์เสร็จ 20 ใบล่าสุด · ถามยืนยันเมื่อย้ายไปเสร็จทั้งที่ subtask ไม่ครบ · โหลดใหม่เมื่อกลับมาที่แท็บ · ติดตั้ง `@dnd-kit/core` 6.3.1 · `@dnd-kit/sortable` 10.0.0 · `@dnd-kit/utilities` 3.2.2 (ล็อกเวอร์ชัน)
- ✅ **B-3 ป้าย + checklist ในหน้าต่างงาน** (17 ต.ค.) — `task-labels-checklist.tsx` + `label-manager.tsx` · ประวัติงาน/กิจกรรมโปรเจกต์แสดงรายละเอียดการแก้ป้าย/checklist · ข้อยกเว้นธีมเพิ่มใน `docs/CODING_GUIDELINES.md` หัวข้อ 6 · ภาพหน้าจอ 1440/360px ไม่มีของล้น ส่วนที่เพิ่มใหม่ปุ่มสูง ≥ 40px
- ตัดสินตอนเขียน:
  - ย้ายการ์ดข้ามคอลัมน์ **คงลำดับความสำคัญเดิม** (ไม่ยัดไปท้ายคอลัมน์ตามที่ร่างไว้) — ลำดับใช้ร่วมกับมุมมองตาราง ถ้ายัดท้ายทุกครั้งลำดับในตารางจะเพี้ยน · ผู้มีสิทธิ์เรียงลำดับวางตรงตำแหน่งที่ปล่อยได้
  - เรียงลำดับได้เฉพาะโหมด task หลักที่ไม่ได้เปิดตัวกรอง (ต้องส่งครบทั้งคอลัมน์ — R-K2) · ข้อความกำกับบอกเหตุผล
  - การแก้ป้าย/checklist ลงประวัติงานเป็น `edited` + ข้อความ (ไม่แก้ ENUM ของตารางประวัติเดิม)
  - checklist เรียงลำดับด้วยปุ่มขึ้น/ลง (ใช้ง่ายบนมือถือกว่าการลากในหน้าต่าง)
- ข้อสังเกต (ของเดิม ไม่ได้แก้รอบนี้): ปุ่ม "แชท", "+ เพิ่ม Subtask", "+ แจ้งปัญหา" และชื่อ subtask ในหน้าต่างรายละเอียดงานสูงไม่ถึง 40px บนมือถือ
