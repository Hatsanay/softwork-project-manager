# คำถามลูกค้า: ตั้งง่าย ครอบคลุม ลูกค้าไม่งง กำหนดได้ว่าใครเห็นข้อไหน

สถานะ: **Q-1 ถึง Q-5 เสร็จ (26-27 ต.ค. 2026) · ดูข้อ 12-15** · เหลือผู้ใช้แก้คำถามบน production เอง (ข้อ 15) · ผู้ใช้ตอบ "ตามที่แนะนำ" ทุกข้อ (Q1-ก Q2-ก Q3-ก Q4-ก Q5-ก) · สั่ง "เริ่มเขียนโค๊ด" 26 ต.ค.

ผู้ใช้สั่ง 26 ต.ค. 2026: "อยากให้หน้าสินค้า/บริการ คำถามของลูกค้าใช้งานง่าย ครอบคลุม ทำให้ลูกค้าไม่งง สามารถกำหนดได้ว่าลูกค้าควรจะเห็นคำถามไหน ขอทุก usecase"

ต่อจาก `docs/plans/2026-10-25-client-order-link.md` ข้อ 4 (S-2 คำถามความต้องการ) และข้อ 21 (คำถามผูกชุด)

## 1. สภาพตอนนี้

### 1.1 ระบบมีอะไร

- **กลุ่มคำถาม** (`tb_requirement_groups`) ขึ้นให้ลูกค้าเมื่อ: ตั้งเป็น "ถามทุกคำขอ" **หรือ** ลูกค้าเลือกสินค้าในหมวดที่ผูกไว้ **หรือ** เลือกชุดบริการที่ผูกไว้ (`applicableGroups` ใน `shared/requirement-answers.mjs`)
- **คำถาม** 9 ชนิด: ข้อความสั้น/ยาว · เลือกหนึ่งข้อ · เลือกหลายข้อ · ใช่/ไม่ใช่ · ตัวเลข · วันที่ · ลิงก์ · แนบไฟล์ (PNG/JPG/PDF ไฟล์ละ 10 MB ไม่เกิน 5 ไฟล์) · ต้องตอบ/ไม่ต้อง · ปิดใช้งานได้
- คำตอบเก็บข้อความคำถาม ณ วันส่ง (`tb_service_request_answers`) แก้/ลบคำถามทีหลังคำตอบเดิมยังอ่านได้
- หน้าตั้งค่า: แท็บ "คำถามลูกค้า" ในหน้าสินค้า/บริการ (`questions-tab.tsx`) · ลำดับกลุ่มเป็นช่องตัวเลข · ลำดับคำถามเป็นปุ่มขึ้น/ลง
- ตัวคิดราคา Fastwork คัดลอกคำถามเป็นข้อความไปวางในแชต (`fastwork/price/page.tsx`)

### 1.2 ปัญหาที่เห็นจากข้อมูลจริง (ฐาน dev 26 ต.ค.)

ลูกค้าเลือก "เว็บธุรกิจ" ตอนนี้เจอ **17 ข้อ**: ทั่วไป 6 + ข้อมูลสำหรับทำเว็บ 10 + ชื่อเว็บของร้าน 1

| ปัญหา | ตัวอย่างจริง | ต้นเหตุในระบบ |
|---|---|---|
| ถามซ้ำ | "ต้องการระบบไหน" อยู่ทั้งกลุ่ม #6 และ #7 · "ชื่อเว็บที่อยากได้" อยู่ทั้ง #6 และ #8 | ผูกเงื่อนไขได้แค่ระดับกลุ่ม คนตั้งเลยใส่ซ้ำเผื่อไว้ |
| บังคับตอบข้อที่ไม่เกี่ยว | #6 "ถ้าเลือกแพ็กเว็บ + ระบบ ต้องการระบบไหน" (ต้องตอบ) มีตัวเลือก "ไม่ได้เลือกแพ็กนี้" | ไม่มีคำถามแบบมีเงื่อนไข |
| ถามข้อต่อทั้งที่ข้อก่อนตอบไม่ | "ไฟล์โลโก้ (ถ้ามี)" ขึ้นแม้ตอบว่ายังไม่มีโลโก้ · "ลิงก์เว็บไซต์เดิม (ถ้ามี)" | ไม่มีเงื่อนไขตามคำตอบ |
| ผิดกติกา Fastwork | กลุ่มทั่วไปถาม "ช่องทางที่สะดวกให้ติดต่อ: โทร / LINE / อีเมล" ในลิงก์ Fastwork ด้วย | กำหนดตามชนิดลิงก์ไม่ได้ |
| ถามเรื่องที่ตกลงแล้ว | "งบประมาณที่ตั้งไว้" ขึ้นแม้ทีมงานล็อกแพ็กและราคาให้แล้ว | ไม่รู้ว่าลิงก์มีรายการที่ทีมเลือกให้ |
| กลุ่มที่ไม่มีใครเห็น | #3 แอปมือถือ · #5 ระบบงาน (ไม่ผูกอะไร) · #2 เว็บไซต์ ผูกหมวด "พัฒนาซอฟต์แวร์" ที่ไม่มีสินค้าแสดงบนหน้าร้าน | ไม่มีคำเตือน · ใส่กลุ่มเพิ่มเฉพาะลิงก์ไม่ได้ |
| "อื่นๆ" ไม่มีช่องให้พิมพ์ | "เป้าหมายของงาน: …, อื่นๆ" | ไม่มีตัวเลือก "อื่นๆ (ระบุ)" |
| คนตั้งไม่รู้ว่าลูกค้าเห็นอะไร | ต้องเปิดลิงก์จริงแล้วลองเลือกเอง | ไม่มีตัวอย่างมุมมองลูกค้า |
| ลูกค้าไม่รู้ว่าทำไมถาม และต้องตอบอีกกี่ข้อ | กลุ่มขึ้นมาโดยไม่บอกเหตุผล · ไม่มีความคืบหน้า | หน้าลูกค้าไม่ได้บอก |
| คำตอบหายง่าย | ปิดหน้าแล้วกลับมา ตะกร้ายังอยู่แต่คำตอบหาย · ไม่มีหน้าทบทวนคำตอบก่อนส่ง | ไม่ได้เก็บคำตอบในเครื่อง |

## 2. หลักของแบบนี้

1. **เงื่อนไขมี 2 ชั้นเท่านั้น** ให้คนตั้งจำง่าย:
   - **กลุ่ม = ถามเมื่อเลือกอะไร** (หมวด · ชุด · สินค้ารายตัว · ทุกคำขอ) + ชนิดลิงก์
   - **คำถาม = ถามเมื่อคำตอบข้อก่อนหน้าเป็นอะไร** + ชนิดลิงก์ + ไม่ถามเมื่อทีมงานเลือกรายการให้แล้ว
2. **กติกาเดียวทุกที่**: ฟังก์ชันเดียว `visibleQuestionnaire()` ใน `shared/requirement-answers.mjs` ใช้ทั้งหน้าลูกค้า backend ตรวจตอนส่ง ตัวอย่างมุมมองลูกค้า ฟอร์มลิงก์ และข้อความคัดลอก Fastwork · ไม่มีที่ไหนคิดเอง
3. **ทุกเงื่อนไขอ่านเป็นประโยค** บนหน้าตั้งค่า เช่น "ถามเมื่อลูกค้าเลือกหมวดแพ็กเกจเว็บไซต์ · ไม่ถามในลิงก์ Fastwork" ไม่ต้องเดาจากช่องติ๊ก
4. **คนตั้งเห็นสิ่งที่ลูกค้าเห็นก่อนส่งลิงก์ทุกครั้ง** (ตัวอย่างมุมมองลูกค้า)
5. **ลูกค้าเห็นน้อยที่สุดที่จำเป็น** และรู้เสมอว่าทำไมถาม เหลืออีกกี่ข้อ

### 3.2 ลูกค้า (หน้าลิงก์เลือกบริการ · มือถือก่อน)

| B4 | ข้อต่อขึ้นเมื่อเกี่ยว ไม่ขึ้นเมื่อไม่เกี่ยว | ข้อลูกโผล่ใต้ข้อแม่ทันทีที่ตอบตรงเงื่อนไข (ย่อหน้าเข้าเล็กน้อย) · ตอบเปลี่ยน ข้อลูกหาย คำตอบในข้อลูกไม่ถูกส่ง |

| B6 | กลับไปแก้ตะกร้า คำตอบไม่หาย | คำตอบเก็บตามรหัสคำถาม กลุ่มที่ยังขึ้นอยู่ได้คำตอบเดิม · กลุ่มที่หายไป คำตอบไม่ถูกส่ง |
| B7 | ปิดหน้าแล้วกลับมาต่อได้ | เก็บคำตอบ (ไม่รวมไฟล์) ในเครื่องตามลิงก์ เหมือนตะกร้า · ส่งแล้วล้าง · ไฟล์ต้องแนบใหม่ (บอกไว้ใต้ช่อง) |
| B8 | ลูกค้าเดิมไม่ต้องพิมพ์ซ้ำ | ลิงก์เฉพาะลูกค้า: ข้อที่ตั้งให้เติม ใส่คำตอบล่าสุดของลูกค้าคนนี้ไว้ + ป้าย "จากคำขอครั้งก่อน แก้ได้" |
| B9 | ทบทวนก่อนส่ง | ขั้นตรวจและส่งมีการ์ด "คำตอบของคุณ" + ปุ่มกลับไปแก้ |
| B10 | ตอบผิดรูปแบบ รู้ทันทีว่าผิดตรงไหน | มีแล้ว (เลื่อนไปข้อแรกที่ผิด) + ข้อความตามชนิดใหม่ (ช่วงตัวเลข · วันที่ผ่านแล้ว) |
| B11 | มือถือกดง่าย | มีแล้ว (ปุ่ม 44px · ช่อง 16px) · ตัวเลขใช้แป้นตัวเลข · หน่วยต่อท้ายช่อง |
| B12 | ไม่มีคำถามเลย ไม่ต้องผ่านขั้นนี้ | มีแล้ว (ข้ามขั้นคำถาม) |

| C2 | Fastwork ก่อนจ้าง: คัดลอกคำถามไปวางในแชต | ใช้กติกาเดียวกันแบบลิงก์ Fastwork · ข้อลูกเขียนเป็น "(ถ้าตอบว่า มีแล้ว) แนบไฟล์โลโก้" ใต้ข้อแม่ |
| C3 | ส่งลิงก์แล้วรู้ว่าลูกค้าจะถูกถามกี่ข้อ | ฟอร์มลิงก์แสดงตัวอย่าง + จำนวนข้อ ตามรายการที่ทีมเลือกให้ |
| C4 | คำถามเปลี่ยนระหว่างที่ลูกค้ากำลังตอบ | ส่งแล้ว backend ตอบ `QUESTIONNAIRE_CHANGED` + ชุดคำถามล่าสุด · หน้าลูกค้าโหลดคำถามใหม่ คงคำตอบเดิม แล้วบอกข้อที่ต้องตอบเพิ่ม |

## 4. หน้าตั้งค่า (สินค้า/บริการ > คำถามลูกค้า)

### 4.1 รายการกลุ่ม

แต่ละกลุ่มเป็นการ์ด:
- ชื่อกลุ่ม · จำนวนข้อ (ต้องตอบกี่ข้อ) · ปุ่มขึ้น/ลง
- **ประโยค "ใครเห็น"** เช่น "ถามเมื่อลูกค้าเลือกหมวด แพ็กเกจเว็บไซต์ หรือชุด เว็บธุรกิจ · ทุกชนิดลิงก์" / "ถามทุกคำขอ · ไม่ถามในลิงก์ Fastwork" / "ไม่ผูกอะไร: ถามเฉพาะลิงก์ที่เลือกถามเพิ่ม"
- ป้ายเตือน (ข้อ 4.3)
- คำถามเรียงตามลำดับ ข้อลูกย่อหน้าใต้ข้อแม่ พร้อมประโยค "ถามเมื่อข้อ 1 ตอบว่า มีแล้ว" · ป้ายเล็ก "ไม่ถามใน Fastwork" / "ไม่ถามเมื่อล็อกแพ็ก" / "เติมคำตอบเดิม"
- เมนูของกลุ่ม: แก้ · คัดลอกกลุ่ม · ปิด/เปิด · ลบ · เมนูของคำถาม: แก้ · คัดลอก · ย้ายไปกลุ่มอื่น · ลบ

บนสุดของแท็บ: แถบค้นหาคำถาม + ตัวกรอง "มีคำเตือน" + ปุ่ม **"ดูมุมมองลูกค้า"**

### 4.2 แผ่นแก้กลุ่ม

1. ชื่อกลุ่ม (ลูกค้าเห็น)
2. **คำอธิบายสำหรับลูกค้า** (ใหม่ ไม่บังคับ 300 ตัวอักษร) เช่น "ใช้ออกแบบหน้าเว็บให้ตรงกับร้าน"
3. โน้ตภายใน (ช่องเดิม `rqg_description` เปลี่ยนชื่อให้ชัด)
4. **ถามเมื่อไหร่** (ตัวเลือก 3 แบบ):
   - ถามทุกคำขอ
   - ถามเมื่อลูกค้าเลือก… → เลือกหมวด / ชุด / สินค้า (ช่องค้นหาเลือกได้หลายรายการ แต่ละรายการมีป้ายถ้าไม่ได้แสดงบนหน้าร้าน)
   - ไม่ถามเอง ใช้เฉพาะลิงก์ที่เลือกถามเพิ่ม
5. **ถามในลิงก์แบบไหน**: ทุกแบบ / เฉพาะลิงก์ลูกค้าตรง (เฉพาะลูกค้า + สาธารณะ) / เฉพาะลิงก์ Fastwork
6. สถานะ ใช้งาน/ปิด
7. ประโยคสรุปใต้ฟอร์มอัปเดตทันทีที่เลือก ("ลูกค้าที่เลือก เว็บธุรกิจ จะเห็นกลุ่มนี้ใน ลิงก์ทุกแบบ")

### 4.3 แผ่นแก้คำถาม

1. คำถาม · ชนิดคำตอบ (รายการมีตัวอย่างหน้าตาแต่ละชนิด) · ตัวเลือก (บรรทัดละข้อ) + สวิตช์ "มีตัวเลือกอื่นๆ (ระบุ)"
2. ข้อความตัวอย่างในช่อง · ข้อความช่วยใต้คำถาม
3. ตามชนิด: ตัวเลข = หน่วย ต่ำสุด สูงสุด · วันที่ = ต้องเป็นวันหลังวันนี้ · แนบไฟล์ = "รูปหรือ PDF (10 MB)" หรือ "ไฟล์งานออกแบบ: เพิ่ม AI PSD SVG ZIP (20 MB · ทีมงานดาวน์โหลดไปเปิดเอง)" · ข้อความ = (คงความยาวเดิม)
4. ต้องตอบ
5. **ถามเมื่อไหร่** (กล่องพับได้ ค่าเริ่มต้น "ทุกครั้งที่กลุ่มนี้ขึ้น"):
   - ถามเมื่อข้อ [เลือกข้อแม่: เฉพาะข้อด้านบนในกลุ่มเดียวกัน ชนิดเลือก/ใช่-ไม่ใช่] ตอบว่า [ติ๊กตัวเลือกได้หลายค่า]
   - ถามในลิงก์แบบไหน: ตามกลุ่ม / เฉพาะลูกค้าตรง / เฉพาะ Fastwork
   - ไม่ถามเมื่อทีมงานเลือกรายการให้แล้ว
6. เติมคำตอบเดิมของลูกค้าคนนี้ (ถ้าได้คำตอบ Q2)
7. "มีคนตอบข้อนี้แล้ว N คำขอ · แก้ข้อความแล้วคำตอบเดิมยังแสดงตามคำถามเดิม"

### 4.4 ป้ายเตือน (ระบบตรวจให้ ไม่ต้องจำกติกา)

| เตือน | เมื่อไหร่ |
|---|---|
| ลูกค้ายังไม่เห็นกลุ่มนี้ | ไม่ผูกอะไร และไม่มีลิงก์ไหนถามเพิ่ม · หรือทุกหมวด/ชุด/สินค้าที่ผูกไม่ได้แสดงบนหน้าร้านและไม่ได้ถูกล็อกในลิงก์ไหน |
| คำถามซ้ำ | ข้อความคำถาม (ตัดช่องว่าง ไม่สนตัวพิมพ์) ตรงกับข้ออื่นที่ลูกค้าคนเดียวกันอาจเห็นพร้อมกัน |
| ข้อลูกไม่มีวันขึ้น | ข้อแม่ปิดใช้งาน หรือค่าที่ตั้งไว้ไม่มีในตัวเลือกแล้ว |
| ถามช่องทางติดต่อในลิงก์ Fastwork | คำถามที่ขึ้นในลิงก์ Fastwork มีคำว่า LINE / โทร / เบอร์ / อีเมล / Facebook / IG (เตือนเฉยๆ คนตั้งยืนยันได้) |
| ถามเยอะ | ลูกค้าแบบหนึ่งเห็นเกิน 15 ข้อ หรือต้องตอบเกิน 8 ข้อ (ดูจากมุมมองลูกค้า) |
| กลุ่มว่าง | กลุ่มใช้งานแต่ไม่มีคำถามที่ใช้งาน |

### 4.5 ดูมุมมองลูกค้า

แผ่นเต็มจอ ซ้าย = สถานการณ์ ขวา = หน้าคำถามแบบที่ลูกค้าเห็นจริง (ใช้คอมโพเนนต์เดียวกับหน้าลูกค้า ตอบเล่นได้ ข้อลูกโผล่จริง ไม่บันทึก)
- ชนิดลิงก์: ลูกค้าตรง / Fastwork
- เลือกชุดและสินค้า (เหมือนตะกร้า) · หรือ "ใช้ลิงก์ที่มีอยู่" เลือกจากรายการลิงก์
- ติ๊ก "ทีมงานเลือกรายการให้แล้ว"
- สรุปบนสุด: "เห็น 3 กลุ่ม 12 ข้อ · ต้องตอบ 4 ข้อ · ราว 5 นาที" + ป้ายเตือนของสถานการณ์นี้
- มือถือ: สถานการณ์พับเป็นแถบบน

### 4.6 หน้าสินค้า / ชุดบริการ

ในแผ่นแก้สินค้าและชุด เพิ่มส่วน "คำถามที่ลูกค้าจะเห็นเมื่อเลือกรายการนี้": รายชื่อกลุ่มพร้อมเหตุผล (ผูกหมวด / ผูกชุด / ผูกรายการนี้ตรง / ถามทุกคำขอ) + จำนวนข้อ + ปุ่ม "แก้คำถาม" ไปแท็บคำถามที่กลุ่มนั้น · ไม่มีกลุ่มเฉพาะ = "ถามแค่คำถามทั่วไป · เพิ่มกลุ่มสำหรับรายการนี้" (เปิดแผ่นเพิ่มกลุ่มโดยเลือกรายการนี้ให้แล้ว)

### 4.7 ฟอร์มลิงก์เลือกบริการ

ส่วนใหม่ "คำถามที่ลิงก์นี้จะถาม" (ใต้รายการที่ทีมเลือกให้):
- รายการกลุ่มที่จะขึ้นตามรายการที่ล็อกไว้ (ลูกค้าเลือกเพิ่มได้ = บอกว่า "อาจมีกลุ่มเพิ่มตามที่ลูกค้าเลือก")
- แต่ละกลุ่มมีสวิตช์ "ไม่ถามในลิงก์นี้"
- ปุ่ม "ถามกลุ่มเพิ่ม" เลือกกลุ่มไหนก็ได้ (รวมกลุ่มที่ไม่ผูกอะไร)
- ปุ่ม "ดูมุมมองลูกค้า" เปิดข้อ 4.5 โดยตั้งสถานการณ์จากลิงก์นี้ให้แล้ว

## 5. หน้าลูกค้า (ขั้น "บอกความต้องการ")

- หัวขั้น: "เล่าความต้องการให้ทีมงานฟัง" + "12 ข้อ · ต้องตอบ 4 ข้อ · ราว 5 นาที" (นาที = ปัดขึ้นจาก ข้อความสั้น/ตัวเลือก 15 วินาที · ข้อความยาว 60 วินาที · ไฟล์ 30 วินาที)
- แถบความคืบหน้า "ตอบข้อที่ต้องตอบแล้ว 2/4" ติดใต้หัว (มือถือติดบน)
- การ์ดกลุ่ม: เลขลำดับ · ชื่อ · คำอธิบายสำหรับลูกค้า · บรรทัดเล็ก "ถามเพราะคุณเลือก เว็บธุรกิจ" (กลุ่มทั่วไปไม่ต้องมี)
- ข้อลูก: ขึ้นใต้ข้อแม่ ย่อหน้าเข้า มีเส้นซ้าย · ปรากฏแบบนุ่ม (ปิดเมื่อเครื่องตั้งลดการเคลื่อนไหว)
- "อื่นๆ (ระบุ)": ชิปสุดท้าย เลือกแล้วช่องพิมพ์ขึ้นใต้ชิป
- ตัวเลข: หน่วยต่อท้ายช่อง · บอกช่วงใต้ช่อง · วันที่: เลือกวันก่อนพรุ่งนี้ไม่ได้ (เมื่อตั้งไว้)
- คำตอบที่เติมจากคำขอครั้งก่อน: ป้ายเล็ก "จากคำขอครั้งก่อน" ใต้ช่อง หายเมื่อแก้
- ขั้นตรวจและส่ง: การ์ด "คำตอบของคุณ" (กลุ่ม → ข้อ → คำตอบ · ไฟล์บอกชื่อ) + ปุ่ม "แก้คำตอบ"
- เก็บคำตอบในเครื่อง `order-answers:<รหัสลิงก์>` (ลองอ่าน/เขียนใน try/catch · ส่งสำเร็จแล้วลบ)

## 6. ฐานข้อมูล (อัปเดต `deploy_schema.sql` ให้รันซ้ำได้ · prefix ไม่ชน ตรวจแล้ว)

**`tb_requirement_groups`** เพิ่ม:
- `rqg_customer_intro` varchar(300) NULL: คำอธิบายที่ลูกค้าเห็น
- `rqg_audience` enum('all','direct','fastwork') NOT NULL DEFAULT 'all': ชนิดลิงก์ที่ถาม (direct = เฉพาะลูกค้า + สาธารณะ)
- `rqg_trigger` enum('always','selection','link_only') NOT NULL DEFAULT 'selection': แทน `rqg_is_general` (always = ถามทุกคำขอ · selection = ตามที่เลือก · link_only = เฉพาะลิงก์ที่ถามเพิ่ม) · ย้ายค่าเดิม: is_general 1 → always · ไม่ผูกอะไร → link_only · อื่นๆ → selection · เก็บ `rqg_is_general` ไว้หนึ่งรอบ deploy แล้วค่อยลบ (กันโค้ดเก่าบนเซิร์ฟเวอร์ระหว่าง deploy)

**ตารางใหม่ `tb_requirement_group_products`** (rgr_): `rgr_group_id` + `rgr_product_id` · PK คู่ · FK cascade ทั้งสองฝั่ง (แบบเดียวกับ `tb_requirement_group_packages`)

**`tb_requirement_questions`** เพิ่ม:
- `rqq_placeholder` varchar(150) NULL
- `rqq_allow_other` tinyint(1) NOT NULL DEFAULT 0 (single/multi เท่านั้น)
- `rqq_unit` varchar(30) NULL · `rqq_min` decimal(12,2) NULL · `rqq_max` decimal(12,2) NULL (number เท่านั้น)
- `rqq_future_only` tinyint(1) NOT NULL DEFAULT 0 (date เท่านั้น)
- `rqq_parent_id` int unsigned NULL FK → `tb_requirement_questions.rqq_id` (ON DELETE RESTRICT: ลบข้อแม่ที่มีข้อลูกไม่ได้ ระบบบอกให้แก้ข้อลูกก่อน)
- `rqq_parent_values` json NULL: ค่าคำตอบของข้อแม่ที่ทำให้ถามข้อนี้ (yes_no ใช้ "yes"/"no")
- `rqq_audience` enum('group','direct','fastwork') NOT NULL DEFAULT 'group'
- `rqq_skip_when_preset` tinyint(1) NOT NULL DEFAULT 0
- `rqq_prefill` tinyint(1) NOT NULL DEFAULT 0: เติมคำตอบเดิมของลูกค้าคนนี้ (Q2-ก)
- `rqq_file_kind` enum('document','design') NOT NULL DEFAULT 'document' (file เท่านั้น · Q3-ก): document = PNG JPG PDF ไฟล์ละ 10 MB (เดิม) · design = เพิ่ม AI PSD SVG ZIP ไฟล์ละ 20 MB

**ตารางใหม่ `tb_order_link_requirement_groups`** (olq_): `olq_link_id` + `olq_group_id` + `olq_mode` enum('include','exclude') · PK (link, group) · FK cascade

**`tb_service_request_answers`** เพิ่ม `sva_other_text` varchar(300) NULL: ข้อความที่ลูกค้าพิมพ์ใน "อื่นๆ" (ไม่ปนกับตัวเลือก ค้นและนับได้)

ไม่เก็บซ้ำ: จำนวนข้อ เวลาโดยประมาณ ป้ายเตือน และ "ใครเห็น" คิดจากข้อมูลทุกครั้ง ไม่เก็บ

## 7. กติกา (backend ตรวจตอนส่งเสมอ ไม่เชื่อหน้าเว็บ)

`visibleQuestionnaire({ groups, linkKind, categoryIds, packageIds, productIds, hasPreset, linkIncludes, linkExcludes, answers })` คืนกลุ่มและคำถามที่ต้องแสดง เรียงตามลำดับ:

1. กลุ่มขึ้นเมื่อ: ใช้งาน · มีคำถามที่ใช้งาน · ชนิดลิงก์ตรง · ไม่อยู่ใน linkExcludes · และ (trigger = always **หรือ** (selection และตรงหมวด/ชุด/สินค้าในตะกร้ารวมรายการล็อก) **หรือ** อยู่ใน linkIncludes) · linkExcludes ชนะทุกกรณี
2. คำถามขึ้นเมื่อ: ใช้งาน · ชนิดลิงก์ตรง (group = ตามกลุ่ม) · ไม่ใช่ (skip_when_preset และลิงก์มีรายการล็อก) · ไม่มีข้อแม่ **หรือ** ข้อแม่ขึ้นอยู่และคำตอบข้อแม่ตรงค่าที่ตั้ง (multi = มีค่าใดค่าหนึ่ง)
3. คำถามที่ไม่ขึ้น: ไม่ตรวจ ไม่บังคับ คำตอบที่ส่งมาถูกทิ้ง ไม่บันทึก
4. "อื่นๆ": เลือก "อื่นๆ" ต้องมีข้อความ (ไม่เกิน 300) · ไม่เลือก ข้อความถูกทิ้ง
5. ตัวเลข: อยู่ในช่วงที่ตั้ง · วันที่ future_only: หลังวันนี้ (เวลาไทย `todayBangkok()`)
6. ชุดคำถามที่ลูกค้าเห็นไม่ตรงกับปัจจุบัน (มีข้อบังคับใหม่ที่ไม่ได้ตอบ) → `QUESTIONNAIRE_CHANGED` 409 + ชุดคำถามล่าสุด
7. ไฟล์ (Q3-ก): ชนิดตรวจจากเนื้อไฟล์ ไม่เชื่อนามสกุลหรือชนิดที่เบราว์เซอร์บอก · PDF/AI = `%PDF` (AI รุ่นใหม่เป็น PDF ข้างใน) · PSD = `8BPS` · ZIP = `PK\x03\x04` · SVG = ข้อความ XML ที่มีแท็ก `<svg` · ไฟล์ชนิด design ข้อ document ไม่รับ · ขนาดรวมต่อคำขอไม่เกิน 60 MB · เปิดไฟล์ AI PSD SVG ZIP = ดาวน์โหลดเท่านั้น (`Content-Disposition: attachment` + `application/octet-stream` + `X-Content-Type-Options: nosniff`) ไม่แสดงในหน้า ไม่ทำรูปย่อ · PNG JPG PDF เปิดดูในหน้าได้เหมือนเดิม

กติกาของข้อแม่ (ตรวจตอนบันทึกคำถาม):
- ข้อแม่ต้องอยู่กลุ่มเดียวกัน อยู่เหนือข้อลูก ชนิด single / multi / yes_no และไม่ใช่ตัวมันเองหรือลูกหลานของมัน (กันวน)
- ค่าที่ตั้งต้องมีอยู่ในตัวเลือกของข้อแม่
- แก้ข้อแม่: เอาตัวเลือกที่ข้อลูกใช้อยู่ออก หรือเปลี่ยนชนิด → บันทึกไม่ได้ บอกชื่อข้อลูกที่ต้องแก้ก่อน
- เรียงลำดับจนข้อลูกอยู่เหนือข้อแม่ → บันทึกไม่ได้ · ย้ายข้อแม่ไปกลุ่มอื่น → ต้องย้ายข้อลูกตาม (ระบบถาม)
- ปิดใช้ข้อแม่ → ข้อลูกไม่ขึ้นด้วย (ป้ายเตือน)

## 8. จุดที่ต้องระวัง

- **ลูกค้าตอบข้อลูกแล้วเปลี่ยนคำตอบข้อแม่**: ข้อลูกหาย หน้าจอเก็บคำตอบไว้ในเครื่อง (เปลี่ยนกลับแล้วได้คืน) แต่ไม่ส่ง · ไฟล์ของข้อลูกที่หายก็ไม่ส่ง (ไม่อัปโหลดไฟล์ที่ไม่ใช้)
- **ลูกค้าเปลี่ยนตะกร้าหลังตอบ**: เหมือนข้อบน ระดับกลุ่ม
- **คำถามเปลี่ยนระหว่างตอบ**: ข้อ 7.6 · ข้อที่ถูกลบระหว่างนั้น คำตอบถูกทิ้งเงียบๆ (ไม่ใช่ error)
- **ตัวเลือกถูกเปลี่ยนชื่อหลังมีคนตอบ**: คำตอบเดิมเก็บเป็นข้อความ อ่านได้ตามเดิม · ข้อลูกที่ผูกค่าเดิมถูกกันไว้ที่ข้อ 7
- **ลิงก์เก่าไม่มีการตั้งค่ากลุ่ม**: ไม่มีแถวใน `tb_order_link_requirement_groups` = ใช้กติกาปกติ ไม่ต้องย้ายข้อมูล
- **กลุ่มที่ลิงก์ถามเพิ่มถูกลบ**: แถวในลิงก์ถูกลบตาม (cascade) · ถูกปิดใช้งาน = ไม่ถาม ฟอร์มลิงก์บอก "กลุ่มนี้ปิดอยู่"
- **ตัวคิดราคา Fastwork และข้อความคัดลอก**: ใช้ linkKind = fastwork · hasPreset = false (ยังไม่ได้ตกลง)
- **คำตอบเดิมของลูกค้า (B8)**: เฉพาะลิงก์เฉพาะลูกค้าที่ผูกลูกค้าไว้ · หาจากคำขอล่าสุดของลูกค้าคนนั้นที่ตอบข้อเดียวกัน (รหัสคำถามเดียวกัน) · ไม่เติมไฟล์ · ลิงก์สาธารณะไม่เติม (ไม่รู้ว่าใคร และกันข้อมูลรั่วไปคนอื่น) · หน้าสถานะไม่แสดงคำตอบที่เติมให้คนอื่น
- **เก็บคำตอบในเครื่องลูกค้า**: มีข้อมูลธุรกิจ เก็บเฉพาะเบราว์เซอร์นั้น ลบเมื่อส่ง · เครื่องสาธารณะเสี่ยงเล็กน้อย (บอกใต้ขั้นตอบคำถาม "คำตอบจำไว้ในเครื่องนี้จนกว่าจะส่ง")
- **เวลาโดยประมาณ**: เป็นค่าประมาณ ปัดขึ้นเป็นนาที ต่ำสุด 1 นาที ไม่ใช่สัญญา
- **ข้อความเตือนช่องทางติดต่อ**: เป็นการเดาจากคำ อาจเตือนผิด · เตือนอย่างเดียว ไม่บล็อกการบันทึก และไม่มีปุ่มปิดป้าย (ไม่ต้องเพิ่มคอลัมน์เก็บ) · แก้ได้ด้วยการตั้งข้อนั้นเป็น "เฉพาะลิงก์ลูกค้าตรง"
- **ไฟล์ SVG**: ฝังสคริปต์ได้ ถ้าเปิดในโดเมนเราจะรันสคริปต์ด้วยสิทธิ์ของคนที่ login อยู่ · กันด้วยดาวน์โหลดเท่านั้น (ข้อ 7.7) ห้ามใส่ใน `<img>` หรือเปิดแบบ inline ทุกที่
- **ขนาดอัปโหลดบน Plesk**: ไฟล์ 20 MB และรวม 60 MB ต้องไม่ติดเพดานของเว็บเซิร์ฟเวอร์บน Plesk (nginx `client_max_body_size`) · ตรวจบน production ตอน deploy Q-1 ถ้าติด ลดเพดานในระบบให้ตรง (ไม่ปล่อยให้ลูกค้าเจอ error ที่ระบบไม่ได้บอก)
- **ไฟล์ใหญ่บนมือถือ**: ส่ง 60 MB ผ่านเน็ตมือถือช้า · ปุ่มส่งบอก "กำลังอัปโหลดไฟล์ 3 ไฟล์ (45 MB)" ไม่เงียบ
- **สิทธิ์**: ตั้งคำถาม = productManagement (เดิม) · ตั้งกลุ่มรายลิงก์ = manageServiceRequests (ฟอร์มลิงก์เดิม)
- **audit log**: ทุก endpoint ใหม่ลง audit (คัดลอก/ย้าย/ลิงก์ถามเพิ่ม)
- **มือถือ**: แผ่นมุมมองลูกค้าและแผ่นแก้คำถามใช้ได้ที่ 360px · ข้อลูกย่อหน้าไม่เกิน 12px ที่ 360px
