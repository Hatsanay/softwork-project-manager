- **H9 ภาษีเงินได้** คิดแบบ "ประมาณการทั้งปีหาร 12" (วิธีที่กรมสรรพากรแนะนำ) · เดือนธันวาคมปรับให้ภาษีทั้งปีตรง (true-up) · พนักงานกรอกค่าลดหย่อน (ล.ย.01) รายปีในระบบ

## 1. ขอบเขต (ตาม H1-ก)

**ทำในเฟส 4**
1. **ทะเบียนพนักงาน** — คำนำหน้า ชื่อ (ไทย/อังกฤษ) เลขประจำตัวประชาชน (= เลขผู้เสียภาษี) ที่อยู่ วันเริ่มงาน/วันพ้นสภาพ แผนก ตำแหน่ง สาขา เลขบัญชีรับเงินเดือน เลขประกันสังคม ผูกบัญชีผู้ใช้ (ไม่บังคับ)
2. **ค่าจ้างตามวันที่มีผล** — เงินเดือนฐาน + ค่าตอบแทนประจำ (ค่าตำแหน่ง ค่าเดินทาง ฯลฯ) เปลี่ยนได้โดยเพิ่มแถวใหม่ มีผลวันที่ระบุ (ประวัติขึ้นเงินเดือนไม่หาย)
3. **ลงเวลาทำงาน (timesheet)** — พนักงานลงชั่วโมงรายวันต่อโปรเจกต์/งาน (ไม่บังคับเลือกงาน) · ส่งรายสัปดาห์ · หัวหน้า/ผู้จัดการโปรเจกต์อนุมัติ · ล็อกเมื่อปิดรอบเงินเดือนของเดือนนั้น
4. **ต้นทุนค่าแรงโปรเจกต์ (H2-ก)** — ชั่วโมงที่อนุมัติ × ต้นทุนต่อชั่วโมงของเดือนนั้น → การ์ดการเงินในหน้าโปรเจกต์ (รวม ไม่แยกรายคน — H3) · กำไรขั้นต้นหักค่าแรงด้วย
5. **ลา (H4-ก)** — ประเภทลา + โควตาต่อปี · ขอลา (ครึ่งวันได้) · อนุมัติ · ยอดคงเหลือ · ปฏิทินลาของทีม (ไม่บอกเหตุผล)
6. **รอบเงินเดือน (PR)** — สร้างรอบของเดือน → ระบบคิดทุกคนอัตโนมัติ (สัดส่วนเข้า/ออกกลางเดือน · หักลาไม่รับค่าจ้าง · ประกันสังคม · ภาษี) → แก้รายการเพิ่ม/หักรายคน → ส่งอนุมัติ → อนุมัติ (ล็อก) → บันทึกจ่ายแล้ว
7. **สลิปเงินเดือน** — พนักงานเปิดของตัวเองบนมือถือ/พิมพ์ PDF · ฝ่ายบุคคลพิมพ์ทั้งรอบ
8. **รายงาน/แบบยื่น** — ภ.ง.ด.1 รายเดือน · สปส.1-10 รายเดือน · ภ.ง.ด.1ก รายปี · 50 ทวิ ประจำปีรายคน (แบบเดียวกับเฟส 2 แถว 1 "เงินเดือน") · ชีตเงินเดือนในไฟล์ส่งนักบัญชี

**ไม่ทำในเฟส 4**
- กดเข้า-ออกงาน / GPS (H5) · ลูกจ้างรายวัน/รายชั่วโมง (H8) · กองทุนสำรองเลี้ยงชีพแบบอัตโนมัติ / OT ตามกฎหมายแรงงาน / ค่าชดเชยอัตโนมัติ (H11 — กรอกเป็นรายการอื่นๆ ได้)
- ไฟล์โอนเงินเดือนของธนาคาร (H6 — รอ Y7) · ไฟล์นำเข้า e-filing (รอ Y5) · ประเมินผล/KPI · สวัสดิการ/เบิกค่ารักษา (ใช้ใบเบิกเงินของเฟส 2)

## 2. ภาพรวม flow

```
ผู้ดูแล ─► ทะเบียนพนักงาน + ค่าจ้าง (วันที่มีผล) + อัตราประกันสังคม/ภาษี (วันที่มีผล) + วันหยุดบริษัท + ประเภทลา
พนักงาน ─► ลงเวลารายวันต่อโปรเจกต์ ─► ส่งรายสัปดาห์ ─► หัวหน้าอนุมัติ ─────────────┐
พนักงาน ─► ขอลา ─► อนุมัติ ─► (ลาไม่รับค่าจ้าง → หักในรอบเงินเดือน) ──────────────┤
                                                                                   ▼
ฝ่ายบุคคล ─► สร้างรอบเงินเดือน ม.ค. ─► ระบบคิดทุกคน ─► แก้รายการเพิ่ม/หัก ─► ส่งอนุมัติ ─► อนุมัติ (ล็อก + ล็อกลงเวลาของเดือน)
                                                                                   │      └─► ต้นทุนค่าแรงลงโปรเจกต์ (snapshot)
                                                                                   ▼
                                                        บันทึกจ่ายแล้ว ─► สลิปเปิดให้พนักงาน ─► ภ.ง.ด.1 / สปส.1-10 ของเดือน
สิ้นปี ─► ภ.ง.ด.1ก + 50 ทวิ ประจำปีของทุกคน
```

## 3. ข้อมูล (ตาราง) — ทุกตารางเข้า `create_people.sql` (ใหม่) + `deploy_schema.sql` + manifest

### 3.1 `tb_employees` — ทะเบียนพนักงาน
`emp_id`, `emp_code` (รหัสพนักงาน ห้ามซ้ำ), `emp_user_id` (ผูกบัญชีผู้ใช้ — unique, ว่างได้), `emp_title` (นาย/นาง/นางสาว/อื่นๆ), `emp_first_name_th/last_name_th/…_en`,
`emp_national_id` (13 หลัก ตรวจหลักตรวจสอบ — ใช้เป็นเลขผู้เสียภาษี), `emp_birth_date`, `emp_address`, `emp_phone`, `emp_email`,
`emp_department_id`, `emp_position`, `emp_branch_id`, `emp_hire_date`, `emp_termination_date`, `emp_termination_reason`,
`emp_bank_name`, `emp_bank_account_no`, `emp_bank_account_name`, `emp_sso_number`, `emp_sso_enrolled` (เข้าประกันสังคมไหม),
`emp_status` (active / terminated) · ลบได้จนกว่าจะมีรอบเงินเดือน/ลงเวลา — หลังจากนั้นใช้ "พ้นสภาพ"

### 3.2 `tb_employee_compensations` — ค่าจ้างตามวันที่มีผล
PK (`ecm_employee_id`, `ecm_effective_from`) · `ecm_base_salary` · `ecm_note` (เหตุผล เช่น ปรับประจำปี) · รายการประจำแยกตาราง `tb_employee_recurring_items`
(`eri_employee_id`, `eri_code`, `eri_label`, `eri_kind` earning/deduction, `eri_amount`, `eri_taxable`, `eri_sso_wage`, `eri_effective_from`, `eri_effective_to`)
· แก้ได้เฉพาะวันที่มีผลที่ยังไม่อยู่ในรอบเงินเดือนที่อนุมัติแล้ว (แบบอัตรา VAT/หัก ณ ที่จ่าย)

### 3.3 อัตราตามวันที่มีผล (ตั้งค่าเงินเดือน)
- `tb_sso_rates`: `sr_effective_from`, `sr_employee_rate`, `sr_employer_rate`, `sr_wage_floor`, `sr_wage_ceiling` (seed 5% / 5% / 1,650 / 15,000 — **รอยืนยัน Y1**)
- `tb_income_tax_brackets`: `itb_effective_year`, `itb_from_amount`, `itb_rate` (seed ขั้นบันไดปัจจุบัน 0/5/10/15/20/25/30/35%)
- `tb_payroll_settings`: หักค่าใช้จ่าย 50% สูงสุด 100,000 · ลดหย่อนส่วนตัว 60,000 · ชั่วโมงต่อวัน 8 · วันจ่ายเงินเดือน · วิธีหักลาไม่รับค่าจ้าง (Y3)
- `tb_company_holidays`: `hd_date`, `hd_name` (ใช้คิดวันทำงานมาตรฐาน H10)

### 3.4 `tb_employee_tax_profiles` — ค่าลดหย่อนรายปี (ล.ย.01)
PK (`etp_employee_id`, `etp_tax_year`) · คู่สมรส · บุตร (จำนวน/ปีเกิด) · บิดามารดา · ประกันชีวิต/สุขภาพ · กองทุน · ดอกเบี้ยบ้าน · อื่นๆ (จำนวนเงิน)
· พนักงานกรอกเองได้ (ของตัวเอง) ฝ่ายบุคคลตรวจ · เปลี่ยนกลางปี = ภาษีเดือนถัดไปคิดใหม่ทั้งปี

### 3.5 ลงเวลา

## 4. กติกาธุรกิจ

### 4.1 ลงเวลา
- ลงย้อนหลังได้ไม่เกิน 14 วัน (ตั้งได้) · ห้ามลงวันในอนาคต · รวมต่อวันไม่เกิน 24 ชม. · ลงในวันลาเต็มวันไม่ได้
- ส่งรายสัปดาห์ · ผู้อนุมัติ = ผู้มีสิทธิ์ `approveTimesheet` หรือ PM ของโปรเจกต์นั้น (เฉพาะแถวของโปรเจกต์ตัวเอง) · ตีกลับพร้อมเหตุผล · อนุมัติตัวเองไม่ได้
- รอบเงินเดือนของเดือนนั้นอนุมัติแล้ว → สัปดาห์ที่ทับเดือนนั้นล็อก (แก้ไม่ได้ — ผิดให้แจ้งฝ่ายบุคคลปรับในรอบถัดไป)

### 4.2 ต้นทุนค่าแรง (H2-ก)
- ต้นทุนต่อชั่วโมงของเดือน = (เงินเดือนตามสัดส่วน + รายรับประจำที่เป็นค่าจ้าง + ประกันสังคมส่วนบริษัท) ÷ ชั่วโมงมาตรฐานของคนนั้นในเดือน
- ค่าแรงโปรเจกต์ = ชั่วโมงที่อนุมัติของเดือน × ต้นทุนต่อชั่วโมง · ชั่วโมงที่ไม่ได้ลง = ต้นทุนส่วนกลาง (เห็นเป็น % ลงเวลาไม่ครบ)
- ลงเวลาเกินชั่วโมงมาตรฐาน (ทำงานเกิน) → ต้นทุนรวมเกินเงินเดือนจริงได้ — แสดงเตือน · **คำนวณ snapshot ตอนอนุมัติรอบเงินเดือน** (เดือนที่ยังไม่ปิดแสดงเป็น "ประมาณการ" จากค่าจ้างปัจจุบัน)
- หน้าโปรเจกต์: ค่าแรงรวมต่อเดือน + ชั่วโมงรวม · ไม่มีรายคน (H3) · กำไรขั้นต้น = ออกบิลก่อน VAT − ค่าใช้จ่าย − ค่าแรง

### 4.3 รอบเงินเดือน
- เดือนละหนึ่งรอบที่ไม่ยกเลิก · สร้างได้เมื่อรอบเดือนก่อนอนุมัติแล้ว (ภาษีสะสมต้องต่อเนื่อง) — ยกเว้นรอบแรกของระบบ (กรอกเงินได้/ภาษีสะสมยกมาของปีได้)
- คิดใหม่ได้ตลอดตอนเป็นร่าง (ดึงค่าจ้าง/ลา/อัตราล่าสุด) · ส่งอนุมัติแล้วตัวเลขล็อก · อนุมัติ = ล็อกถาวร · ผิดหลังอนุมัติ → รายการปรับในรอบถัดไป (ไม่แก้ย้อนหลัง)
- **สัดส่วนเข้า/ออกกลางเดือน** = เงินเดือน × วันปฏิทินที่เป็นพนักงาน ÷ วันในเดือน (รอ Y4) · **ลาไม่รับค่าจ้าง** หัก = เงินเดือน ÷ 30 × วัน (รอ Y3)
- **ประกันสังคม** = ฐาน (ค่าจ้าง + รายการที่ติ๊ก "เป็นค่าจ้าง") จำกัดระหว่างขั้นต่ำ–เพดาน × อัตรา ปัดตามกติกา (รอ Y1) · คนที่ไม่เข้าประกันสังคม = 0
- **ภาษี (H9)**: เงินได้ทั้งปีประมาณ = สะสมก่อนเดือนนี้ + (เงินได้เดือนนี้ × เดือนที่เหลือรวมเดือนนี้) → หักค่าใช้จ่าย/ลดหย่อน/ประกันสังคมทั้งปี → ภาษีทั้งปีตามขั้นบันได
  → ภาษีเดือนนี้ = (ภาษีทั้งปี − ภาษีสะสมที่หักแล้ว) ÷ เดือนที่เหลือรวมเดือนนี้ · ธันวาคม = ภาษีทั้งปี − สะสม (true-up) · ติดลบ = 0 (คืนตอนยื่นภาษีเอง — แสดงเตือน)
- สุทธิติดลบ → ส่งอนุมัติไม่ได้ (ต้องแก้รายการหัก) · ผู้สร้างรอบอนุมัติเองไม่ได้ (ยกเว้นตั้งค่าอนุมัติเอง) · ผู้มีชื่อในรอบอนุมัติรายการของตัวเองได้ไหม → ไม่ได้ ถ้ามีผู้อนุมัติอื่น (R-H4)
- บันทึกจ่ายแล้ว: วันที่ + บัญชีบริษัท · หลังจ่ายแล้วสลิปเปิดให้พนักงาน · ยกเลิกรอบที่จ่ายแล้วไม่ได้ (ปรับในรอบถัดไป)

### 4.4 ลา
- วันลาคิดเฉพาะวันทำงาน (ไม่นับเสาร์-อาทิตย์/วันหยุดบริษัท) · ครึ่งวัน = 0.5 · เกินโควตา → ส่งได้แต่แสดงเตือนผู้อนุมัติ · ลาย้อนหลังได้ (ลาป่วย) ภายในรอบเงินเดือนที่ยังไม่อนุมัติ
- ยกเลิกลาที่อนุมัติแล้ว: ได้ถ้าวันลายังไม่อยู่ในรอบเงินเดือนที่อนุมัติ · ทับซ้อนกับลาที่มีอยู่ = ไม่ได้
- ปฏิทินทีมแสดงชื่อ + ช่วงวัน + ประเภทแบบกว้าง (ลา) เท่านั้น — เหตุผล/ไฟล์ใบรับรองแพทย์เห็นเฉพาะผู้อนุมัติ/ฝ่ายบุคคล

| R-H9 | พนักงานพ้นสภาพแล้วยังถูกคิดเงินเดือน / ลงเวลาได้ | ตรวจวันพ้นสภาพทุกจุด · บัญชีผู้ใช้ที่ผูกปิดใช้งานแยกต่างหาก (ไม่ผูกอัตโนมัติ — บอกในหน้า) |
| R-H10 | ลบโปรเจกต์/งานที่มีชั่วโมงลงไว้ | FK ไม่ cascade · ตอบ 409 พร้อมเหตุผล (แบบค่าใช้จ่าย) |
| R-H11 | ต้นทุนต่อชั่วโมงเดือนที่ชั่วโมงมาตรฐาน = 0 (เข้างานวันสุดท้ายที่เป็นวันหยุด) | ชั่วโมงมาตรฐาน 0 → ต้นทุนทั้งหมดเป็นส่วนกลาง · เทสต์ |
| R-H12 | บิตสิทธิ์รวม 54 ใกล้แผนย้ายเป็นตารางสิทธิ์ (แผนแม่บทข้อ 7) | ยังพอ (varchar 255) · ย้ายเป็นตารางสิทธิ์แบบรหัสก่อนเฟส 5 |

## 7. เทสต์ที่ต้องผ่าน
- หน่วย: ประกันสังคม (ขั้นต่ำ/เพดาน/ปัดเศษ) · ภาษีขั้นบันได · ภาษีทั้งปี 12 เดือน (ขึ้นเงินเดือนกลางปี, เข้างานกลางปี, ลดหย่อนเปลี่ยนกลางปี) ผลรวมตรงภาษีจริงทั้งปี · สัดส่วนเข้า/ออกกลางเดือน · วันลา (ข้ามวันหยุด/ครึ่งวัน) · ต้นทุนต่อชั่วโมง
- API: สิทธิ์ทุกเส้น (คนนอกไม่เห็นเงินเดือน — R-H1) · พนักงานเห็นสลิปตัวเองเท่านั้น · รอบซ้ำพร้อมกัน (R-H2) · ล็อกหลังอนุมัติ (R-H3/R-H7) · ลงเวลาเกิน 24 ชม./ลงวันลา · ลาทับซ้อน · ค่าแรงลงโปรเจกต์ (ไม่แยกรายคน) · audit ไม่มีค่าเงินเดือน
- deploy_schema: อัปเกรดจากโครงสร้าง deploy ล่าสุด · ข้อมูลเริ่มต้น (อัตรา/ประเภทลา) ไม่ทับของที่แก้
- ภาพหน้าจอ: มือถือ 360/400px (ลงเวลา/ลา/สลิป) · หน้าพิมพ์สลิป/ภ.ง.ด.1/50 ทวิ ประจำปี
