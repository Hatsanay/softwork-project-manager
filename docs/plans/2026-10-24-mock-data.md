## 2. แนวทาง (แนะนำ)

**สคริปต์เดิมเป็นตัวสร้าง → ส่งออกเป็นไฟล์ SQL**
1. ขยาย seed-company-data ให้ใส่ครบทุกตาราง (ผ่าน API เหมือนเดิม · ตารางที่เป็นบันทึกดิบใส่ตรงได้ เช่น การอ่านแชต)
2. รันบนฐานชั่วคราว `tmp_mock_*` ใน MySQL เครื่อง dev (reset → seed)
3. ส่งออกข้อมูลด้วย mysqldump (เฉพาะข้อมูล ไม่มีโครงสร้าง) → `database/mock_data.sql`
4. ไฟล์รูป/ไฟล์แนบที่ข้อมูลอ้างถึง → `database/mock_uploads/` (คัดลอกไปไว้ใน `backend/uploads/` และ `backend/storage/`)

ทำไมไม่เขียน SQL ด้วยมือ: ยอดเอกสาร ภาษี หัก ณ ที่จ่าย เงินเดือน ประกันสังคม เลขที่เอกสาร และสถานะการอนุมัติ ต้องสอดคล้องกันหลายตาราง เขียนเองผิดง่ายและหน้าจอจะแสดงตัวเลขขัดกัน · ให้ระบบคำนวณเองแล้วค่อยส่งออก ถูกแน่นอน และสร้างใหม่ได้ทุกครั้งที่โครงสร้างเปลี่ยน

## 5. จุดที่ต้องระวัง

- **ลงฐานผิดตัว:** mock_data.sql มี `@confirm_database` แบบเดียวกับ reset (ชื่อไม่ตรง = หยุดก่อนใส่อะไร) · ค่าเริ่มต้นเป็นชื่อฐาน production ตาม Q2-ข · ลงฐานอื่นให้แก้ชื่อบรรทัดเดียว
- **รหัสผ่านที่ทุกคนรู้บนเว็บจริง (Q2-ข):** บัญชีจำลองทุกบัญชีใช้ 12345678 · ลงบน production แล้วใครรู้ชื่อผู้ใช้ก็เข้าได้ รวมถึงบัญชีที่อนุมัติเงินเดือน · ลดความเสี่ยง: หัวไฟล์เตือน · ใช้ช่วงสาธิตสั้นๆ แล้วรัน reset ทันที · ข้อมูลจำลองไม่มีข้อมูลจริงของใคร (ชื่อ เลขบัตร บัญชีธนาคาร เป็นของสมมติทั้งหมด เลขบัตรประชาชนผ่านสูตรตรวจแต่ไม่ใช่ของคนจริง)
- **ไฟล์บนเซิร์ฟเวอร์ (Q2-ข + Q3-ก):** บน Plesk ต้องอัปโหลด mock_uploads ไปไว้ใน backend/uploads และ backend/storage ของเซิร์ฟเวอร์เอง (SQL คัดลอกไฟล์ไม่ได้) · reset ไม่ลบไฟล์เหล่านี้ ต้องลบเอง
- **ต้องลงบนฐานว่างที่โครงสร้างล่าสุด:** ไฟล์ขึ้นต้นด้วยการตรวจว่าเหลือแค่ admin (เหมือนสคริปต์เดิม) · โครงสร้างเก่ากว่าไฟล์ = INSERT ล้มที่คอลัมน์ที่ไม่มี
- **วันที่ตายตัว:** ข้อมูลเป็นของ เม.ย. ถึง 24 ต.ค. 2026 · เปิดดูทีหลัง วันหลังจากนั้นจะขึ้น "ขาด" ในหน้าลงเวลา เพราะไม่มีการกด → ตั้ง `ps_attendance_start_date` ไว้ และเขียนในหัวไฟล์ว่าต้องสร้างใหม่ถ้าอยากให้ข้อมูลถึงวันปัจจุบัน
- **เงินเดือนกับลงเวลาต้องตรงกัน:** ใส่การกดของเดือนให้เสร็จก่อนคิดรอบเงินเดือนเดือนนั้น (รอบที่จ่ายแล้วแก้ไม่ได้)
- **นาฬิกาจำลองต้องระบุนาที:** การกดเข้า 09:07 ต้องได้ 09:07 จริง (ตอนนี้ setToday รับแค่ชั่วโมง) · การกดใช้เวลาเซิร์ฟเวอร์ จึงต้องเลื่อนนาฬิกาทุกครั้งที่กด
- **เวลาที่ MySQL ใส่เอง** (DEFAULT CURRENT_TIMESTAMP) เป็นเวลาที่รันจริง ไม่ใช่วันที่จำลอง · กระทบเฉพาะคอลัมน์ created_at บางตัว ไม่กระทบวันที่เอกสาร
- **ไฟล์อัปโหลด:** SQL เก็บแค่ชื่อไฟล์ · ไม่คัดลอก mock_uploads = รูปและไฟล์แนบแตก
- **ขนาดไฟล์:** การกดราว 13 คน × 100 วัน × 2 = 2,600 แถว + audit log · คาดไม่เกิน 10-20 MB (phpMyAdmin นำเข้าได้ ถ้าเกินเพดานอัปโหลดของ Plesk ต้องบีบอัดเป็น .gz)
- **AUTO_INCREMENT:** dump ใส่ id ตรงตามที่สร้าง ต่อจากนั้นระบบนับต่อเอง
- **เวลารันสคริปต์:** การกดผ่าน API ทีละครั้งราว 2,600 ครั้ง + เอกสารเดิม · ประมาณ 5-10 นาที แสดงความคืบหน้ารายเดือน

- สคริปต์เดิมรันไม่ผ่านแล้ว เพราะลงชั่วโมงต่อโปรเจกต์ปิดเป็นค่าเริ่มต้นตั้งแต่ A-1 → เปิดในตั้งค่าตอนตั้งบริษัท
- เวลาที่ MySQL ใส่เอง (แชต issue คำขอ) เคยเป็นวันที่รันสคริปต์ → SET TIMESTAMP ตามนาฬิกาจำลอง
- ตัวส่งออกเคยตัดคอลัมน์ `DEFAULT CURRENT_TIMESTAMP` ทิ้ง (MySQL 8 ติดป้าย DEFAULT_GENERATED) → กรองเฉพาะคอลัมน์คำนวณจริง (VIRTUAL/STORED) · ตัวตรวจจับได้จากการเช็กเวลาเลยวันสุดท้าย
- พนักงานที่ไม่มีบัญชี (แม่บ้าน คนขับรถ) กดไม่ได้ ถ้าตั้งให้ต้องลงเวลาจะขึ้นขาดทุกวันและถูกหักเงิน → ตั้งไม่ต้องลงเวลา
- วันขาดงานไม่ลงชั่วโมงต่อโปรเจกต์ด้วย (state.absentDays)

**ข้อจำกัด**
- ข้อมูลตายตัวถึง 23 ต.ค. 2026 · เปิดดูวันหลังจากนั้นหน้าลงเวลาจะขึ้น "ขาด" (ไม่มีการกด) → สร้างไฟล์ใหม่ได้แต่วันที่ในเรื่องยังเป็นชุดเดิม ถ้าต้องการเลื่อนช่วงต้องแก้วันที่ใน timeline
