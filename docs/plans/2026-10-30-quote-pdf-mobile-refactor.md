## 1. ส่วน A: เปิด/บันทึก PDF ใบเสนอราคาจากลิงก์ลูกค้า

ค้างจาก [2026-10-25-client-order-link.md](2026-10-25-client-order-link.md) ข้อ 17 ("หน้าพิมพ์ใบต้อง login")

### 1.1 ตอนนี้
- หน้าสถานะคำขอ `/order/r/[token]` แสดงสรุปใบเสนอราคา (รายการ ยอด งวด เงื่อนไข) แต่ลูกค้าเก็บเป็นไฟล์ไม่ได้
- หน้าพิมพ์ A4 `/sales/quotations/print?id=` อยู่หลัง login · ลายเซ็นโหลดจาก `GET /signatures/:id` ที่ต้อง login

### 1.2 ที่จะทำ
- **ปุ่ม "ดู / บันทึก PDF ใบเสนอราคา"** ในการ์ดใบเสนอราคาของหน้าสถานะ เปิดแท็บใหม่ `/order/r/[token]/quotation`
- หน้านั้นหน้าตาเดียวกับหน้าพิมพ์ภายในทุกอย่าง (หัวบริษัท ลูกค้า รายการ ยอดรวมย่อยต่อหัวข้อ งวด เงื่อนไข ลายเซ็น ตัวหนังสือบาทถ้วน ภาษาไทย/อังกฤษตามใบ) + ปุ่ม "พิมพ์ / บันทึก PDF" + คำแนะนำตั้งค่าพิมพ์
- มือถือ: กระดาษกว้างเท่า A4 เลื่อนซ้ายขวาดู (แบบหน้าพิมพ์ภายใน) · ปุ่มพิมพ์ใช้ "บันทึกเป็น PDF" ของมือถือได้ · คำแนะนำบอกวิธีสำหรับมือถือด้วย

### 1.3 ใครเห็นได้ เมื่อไร
- ใช้ token ของหน้าสถานะ (คนที่มีลิงก์ = คนที่เห็นสรุปใบอยู่แล้ว ไม่ได้เปิดข้อมูลเพิ่มเกินใบ)
- เปิดได้เฉพาะขั้นที่ลูกค้าเห็นใบอยู่แล้ว: **"ใบพร้อม รอยอมรับ" และ "ยอมรับแล้ว"**
- ไม่เปิด: ทีมยังทำใบ/ออก revision ใหม่อยู่ (ร่าง รออนุมัติ) · ใบหมดอายุ · ปฏิเสธ/ยกเลิก · ลิงก์ Fastwork (ใบเป็นเอกสารภายใน) → หน้าบอกเหตุผลและพากลับหน้าสถานะ
- ใบที่เห็น = ฉบับล่าสุดตาม `qt_root_id` เสมอ (กติกาเดียวกับหน้าสถานะ)

### 1.4 Backend
- `GET /V1/order/requests/:token/quotation-document` (สาธารณะ · นับในตัวจำกัดการเดาลิงก์เดียวกับหน้าสถานะ)
- ส่ง **เฉพาะที่พิมพ์บนใบ** (เลือกฟิลด์ทีละตัว ไม่ส่งแถวจากตารางทั้งแถว): เลขที่ + revision · ชื่อเรื่อง · วันที่ · ยืนราคาถึง · ภาษา · สกุลเงิน (รหัส ทศนิยม) · การคิด VAT · ยอดต่างๆ · เงื่อนไข · รายการ (ชนิด รายละเอียด จำนวน หน่วย ราคา ส่วนลด ยอด) · งวด · ข้อมูลบริษัท/ลูกค้า ณ วันอนุมัติ (snapshot) · ชื่อ/ตำแหน่งผู้เสนอและผู้อนุมัติ (เท่าที่หน้าพิมพ์ภายในแสดง)
- **ไม่ส่ง**: บันทึกภายใน · ประวัติอนุมัติ · ผู้สร้าง/ผู้แก้ · รหัสภายใน (qt_id ลูกค้า โปรเจกต์) · ปุ่ม/สิทธิ์
- ลายเซ็น: ฝังเป็น data URL ในคำตอบ (ไฟล์เล็ก ไม่ต้องเปิดเส้นทางรูปลายเซ็นสาธารณะ)
- เทสต์: ลิงก์ผิด 404 · ขั้นที่ไม่เปิด (ร่าง/revision ใหม่/หมดอายุ/Fastwork) ได้รหัส error ที่บอกเหตุผล · ฟิลด์ภายในไม่หลุด · ยอมรับแล้วยังเปิดได้ · ฉบับล่าสุดเสมอ

### 1.5 หน้าเว็บ
- แยกตัวเอกสาร A4 ออกจาก `(print)/sales/quotations/print/page.tsx` เป็น component กลาง `QuotationDocument` (รับข้อมูล + วิธีแสดงลายเซ็น) ใช้ทั้งหน้าพิมพ์ภายในและหน้าลูกค้า · หน้าภายในต้องออกมาเหมือนเดิมทุกจุด
- หน้าลูกค้า `/order/r/[token]/quotation` อยู่ใต้ `/order/` ที่ proxy เปิดสาธารณะอยู่แล้ว · ชื่อแท็บ = เลขที่ใบ (ตั้งเป็นชื่อไฟล์ตอนบันทึก PDF)

### 1.6 จุดที่ต้องระวัง
- ทีมออก revision ใหม่ระหว่างลูกค้าเปิดหน้าค้างไว้: เปิดใหม่เห็นฉบับใหม่ หรือขึ้น "ทีมกำลังปรับปรุงใบ"
- ลายเซ็นถูกลบ/เปลี่ยนภายหลัง: ใบที่อนุมัติแล้วใช้ลายเซ็นตามรหัสที่บันทึกไว้ในใบ ถ้าไฟล์หายแสดงช่องว่างแทน ไม่ทำให้หน้าพัง
- ใบภาษาอังกฤษ สกุลเงินเยน (ทศนิยม 0) ต้องเหมือนหน้าพิมพ์ภายใน

## 2. ส่วน B: มือถือทั้งระบบ

### 2.1 ผลตรวจ (30 ต.ค. 2026 · จอ 360px · 88 หน้า ทั้งหน้ารายการ หน้าเพิ่ม หน้าดู/แก้)
| ตรวจ | ผล |
|---|---|
| หน้าเลื่อนแนวนอน | **0 หน้า** |
| ช่องกรอกเล็กกว่า 16px (iPhone ซูม) | 0 (กฎกลางใน globals.css คุมอยู่แล้ว) |
| เนื้อหาถูกตัดขาด | **Dashboard** การ์ด "โปรเจกต์ที่กำลังทำ": % และ "ครบกำหนด ..." ล้นขวาถูกตัด |
| ปุ่ม/ลิงก์เล็กกว่า 32px | ลิงก์ชื่องานในหน้า Fastwork 4 หน้า (ศูนย์รวม รายการเงิน ส่วนแบ่ง เงินทุน) · ลิงก์ "เพิ่มเป็นพนักงาน" หน้าแก้ผู้ใช้ |
| ความยาวหน้า (ดูจากภาพ) | **หน้ารายการยาวมาก**: ทุกตาราง (24 หน้า) บนมือถือเป็นการ์ดที่ทุกคอลัมน์เป็นแถว "หัวข้อ : ค่า" · ค่าใช้จ่าย 25 รายการยาว ~7,000px · การชำระเงิน ~5,700px · ใบแจ้งหนี้ ~4,900px |
| ฟอร์มแก้ไขบนสุดของหน้า | ตั้งค่าบริษัท: บัญชีธนาคาร · สาขา · สกุลเงิน · หน้าสินค้า: แท็บหมวดหมู่ |
| เครื่องหมาย "—" ในข้อความที่ผู้ใช้เห็น | ยังเหลือ ~370 บรรทัดหน้าเว็บ ~270 บรรทัดข้อความจาก backend (กติกาห้ามใช้มาทีหลัง) |

### 2.2 ที่จะทำ
- **B1** Dashboard: แถวโปรเจกต์ที่กำลังทำ จัดใหม่ให้ % และวันครบกำหนดอยู่ในการ์ด (มือถือขึ้นบรรทัดใหม่)
- **B2** ลิงก์ที่เล็ก: ชื่องานใน Fastwork 4 หน้า + "เพิ่มเป็นพนักงาน" ให้พื้นที่กดสูงอย่างน้อย 40px
- **B3 การ์ดมือถือแบบกะทัดรัดของตาราง** (ได้ผลมากที่สุด):
  - คอลัมน์บอกได้ว่าบนมือถืออยู่ตรงไหน: `trailing` (ชิดขวาข้างชื่อ เช่น ยอดเงิน) · `meta` (บรรทัดเล็กใต้ชื่อ รวมหลายค่าด้วย "·") · `badge` (แถวป้ายสถานะ) · `hidden` · ไม่ตั้ง = แบบเดิม (หน้าที่ยังไม่ปรับไม่เปลี่ยน)
  - ไล่ตั้งทั้ง 24 หน้า · เป้า: การ์ดสูง 3 บรรทัด จากเดิม 5-7 · หน้ารายการสั้นลงราวครึ่ง
  - ปุ่มแก้/ลบของแถวบนมือถือ: อยู่บรรทัดเดียวกับป้าย ไม่กินบรรทัดเพิ่ม
- **B4** ฟอร์มแก้บนสุดของหน้า → แผงด้านขวาแบบหน้าสินค้า (ย้าย `editor-drawer` ไป `components/ui` ใช้ร่วมกัน): บัญชีธนาคาร · สาขา · สกุลเงิน · หมวดหมู่สินค้า
- **B5** เอา "—" ออกจากข้อความที่ผู้ใช้เห็นทั้งระบบ (หน้าเว็บ + ข้อความ error/คำแนะนำจาก backend) แทนด้วย "·" หรือ ":" ตามความหมาย · ไม่แตะ comment ในโค้ด · เทสต์ที่ตรวจข้อความตามแก้

### 2.3 ตรวจหลังทำ
รันสคริปต์ตรวจ 88 หน้าซ้ำ (ไม่มีเลื่อนแนวนอน ไม่มีถูกตัด ไม่มีปุ่มเล็ก) + เทียบความยาวหน้ารายการก่อน/หลัง + ภาพ 400/1440px ของหน้าที่แก้
