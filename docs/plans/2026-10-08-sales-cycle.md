## การตัดสินใจของผู้ใช้ (8 ต.ค. 2026)
1. เป็น **ระบบบริหารภายใน** — ส่งข้อมูลต่อให้นักบัญชี (ยังไม่ทำบัญชีแยกประเภท/งบการเงินทางการ)
2. **ยังไม่จด VAT** — คาดว่าจดใน ~1 ปี → ต้องเปิด VAT ได้ตาม "วันที่มีผล" โดยไม่แตะเอกสารเก่า
3. บริษัทเดียว แต่ **อาจมีศูนย์บริการหลายแห่ง** → เอกสารผูกกับสาขา
4. เริ่มที่ **วงจรขาย** (ผูกกับโปรเจกต์ที่มีอยู่)

## ภาพรวม flow
```
ลูกค้า ─► ใบเสนอราคา (QT) ──อนุมัติ (1–n ชั้น) → ส่ง → ลูกค้าตอบรับ──► โปรเจกต์ (สร้างใหม่ / ผูกของเดิม / ไม่ผูก)
                │ แก้ไขหลังอนุมัติ (ก่อนตอบรับ) = ออก revision ใหม่ (Rev.1, Rev.2) ไม่แก้ทับ           + สร้างงานจากรายการ (ถ้าติ๊ก)
                │ หลังตอบรับมีงานเพิ่ม/ลด = ออกใบเสนอราคาใหม่ผูกโปรเจกต์เดิม
                ▼
          งวดชำระ (ตามที่ตกลงในใบเสนอราคา)
                ▼
   ใบแจ้งหนี้ (IV) ต่องวด
                ▼  (รวมหลายใบแจ้งหนี้เป็น ใบวางบิล (BN) ได้ ถ้าลูกค้าต้องการ)
   ใบเสร็จรับเงิน (RE) — รับบางส่วนได้, บันทึกภาษีหัก ณ ที่จ่ายที่ลูกค้าหัก + แนบ 50 ทวิ
                ▼
   ลูกหนี้คงค้าง / รายงานส่งนักบัญชี (Excel รายเดือน)
```
(หลังจด VAT เอกสารใบไหนเป็น "ใบกำกับภาษี" ขึ้นกับจุดความรับผิดทางภาษี — ดูคำถาม B1)

## หลักการที่บังคับในโค้ด
- **เงินเป็น DECIMAL(15,2)** คำนวณฝั่ง backend เท่านั้น (ไม่เชื่อยอดจากหน้าเว็บ) ด้วยจำนวนเต็มหน่วยย่อยของสกุลเงิน ปัดเศษครึ่งขึ้น — มีเทสต์อัตโนมัติ
- **ร่างแก้ได้ · ออกแล้วแก้ไม่ได้** — เปลี่ยนหลังออก = ยกเลิกพร้อมเหตุผลแล้วออกใหม่ / ใบเสนอราคาออก revision
- **เลขที่เอกสารออกตอนอนุมัติ/ออกเอกสารเท่านั้น** (ร่างไม่มีเลข) ออกใน transaction เดียวกับการบันทึก → ไม่ซ้ำ ไม่ข้าม
  เอกสารที่ยกเลิกยังคงเลขไว้ (ไม่นำเลขกลับมาใช้)
- **snapshot ณ วันที่อนุมัติ/ออก**: ข้อมูลลูกค้า, บริษัท/สาขา, อัตรา VAT, อัตราแลกเปลี่ยน, กติกาอนุมัติ, ลายเซ็น, รายการ —
  แก้ข้อมูลต้นทางทีหลัง เอกสารเก่าเหมือนเดิมทุกตัวอักษร
- **VAT ตามวันที่มีผล**: `cs_vat_registered_from` (ว่าง = ยังไม่จด) · เอกสารที่ "วันที่เอกสาร" ≥ วันนั้นจึงคิด VAT
- ทุกการกระทำเข้า audit log ที่มีอยู่แล้ว (เพิ่มแถวใน ENTITIES ให้อ่าน diff ง่าย)

## กติกาธุรกิจ (ยืนยันแล้ว 8 ต.ค. 2026)
1. **เลขที่เอกสาร** `QT-20261231-000001` — ประเภท 2 ตัว + ปี ค.ศ.เดือนวัน + เลขรัน 6 หลัก (18 ตัว) รีเซ็ตทุกวัน
   ประเภท: QT ใบเสนอราคา, IV ใบแจ้งหนี้, BN ใบวางบิล, RE ใบเสร็จ · **ลำดับเดียวร่วมกันทุกสาขา** (เลขไม่ซ้ำทั้งบริษัท) เอกสารเก็บสาขาไว้เอง
   ใบเสนอราคาได้เลขตอน **อนุมัติชั้นสุดท้าย** · revision ใช้เลขเดิม + Rev.1, Rev.2 · **วันที่เอกสาร = วันที่อนุมัติชั้นสุดท้าย (อัตโนมัติ ย้อนไม่ได้)** → เลขเรียงตามเวลาจริงเสมอ (ผู้ใช้เลือก 12 ต.ค. 2026, R10)
   ⚠ ก่อนจด VAT ให้นักบัญชียืนยันว่าเลขแบบนี้ใช้กับใบกำกับภาษีได้
2. **การเก็บเงิน** — เลือกต่อใบ: ครั้งเดียว หรือ แบ่งงวด (ระบุ % หรือจำนวนเงิน ผลรวมต้องเท่ายอดเอกสารพอดี งวดสุดท้ายรับเศษปัด)
3. **อนุมัติทุกใบ** — ผู้สร้างอนุมัติใบของตัวเองไม่ได้ ยกเว้นเปิดตั้งค่า "อนุญาตอนุมัติเอง" (บริษัทที่มีผู้อนุมัติคนเดียว)
4. **หัก ณ ที่จ่าย ปนกัน** — ลูกค้ามีค่าเริ่มต้นของตัวเอง แล้วระบุยอดจริงตอนรับเงิน (ช่วง 1C)

# ช่วง 1A — แบบละเอียด

## 1. ข้อมูล (ตาราง)
สร้างจริงแล้วใน `deploy_schema.sql` (13 ต.ค. 2026) — ฉบับอ่านอ้างอิง `database/query/create_sales.sql` (★ = ใหม่/เปลี่ยนจากร่าง)

**ปรับจากตารางด้านล่างตอนเขียนโค้ด (13 ต.ค. 2026)** — รายละเอียดคอลัมน์จริงดูที่ deploy_schema.sql
- **อัตรา VAT แยกเป็นตาราง `tb_vat_rates` (วันที่มีผล → อัตรา)** แทน `cs_vat_rate` คอลัมน์เดียว — ตามหลักการ ERP ข้อ 4 (อัตราภาษีต้องมีวันที่มีผล):
  ตั้งอัตราใหม่ล่วงหน้าได้ เอกสารใช้อัตรา ณ วันที่เอกสาร · seed 7.00% มีผลตั้งแต่ 2000-01-01 · `cs_vat_registered_from` ยังเป็นตัวบอกว่าจด VAT แล้วหรือยัง
- สาขา: ไม่มีคอลัมน์ "เป็นสำนักงานใหญ่" — ใช้รหัส `00000` บอกแทน (กันมีสำนักงานใหญ่ 2 แห่ง) · ที่อยู่สาขาว่าง = ใช้ที่อยู่บริษัท
- อัตราแลกเปลี่ยนเก็บ **DECIMAL(20,10)** (เดิม 15,6) — สกุลที่ ธปท. ประกาศต่อ 1000 หน่วย หารแล้วต้องการ 10 ตำแหน่ง ไม่งั้นยอดใหญ่คลาดได้หลักร้อยบาท · `convertToBaht` รับ 10 ตำแหน่ง
- `tb_exchange_rates` เก็บอัตราทุกชนิดที่ ธปท. ให้ (ซื้อตั๋วเงิน/ซื้อเงินโอน/ขาย/กลาง) เพราะชนิดที่ใช้ทางภาษีรอนักบัญชี (B6)
- ลูกค้า + `client_status` (active/inactive — แบบเดิมอ้าง "ลูกค้าต้อง active" แต่ตารางเดิมไม่มีคอลัมน์นี้) · เลขผู้เสียภาษียาวได้ 30 ตัว (ต่างประเทศ)
- บัญชีธนาคาร + `ba_swift_code` (รับโอนจากต่างประเทศ)
- แถวลูก (รายการ, งวด, ประวัติอนุมัติ, แถวในชุดสินค้า) ใช้ id แบบ BIGINT AUTO_INCREMENT — สร้างทีละหลายแถวใน transaction เดียว ไม่ล็อก tb_maxID ทีละแถว
- กติกาอนุมัติใช้คีย์ (ประเภทเอกสาร, ชั้น) ไม่มี id แยก · seed ผู้อนุมัติชั้น 1 = role ระบบ (เลือกจาก role_type ไม่ผูก id ตายตัว)
- FK ที่ตั้งใจให้ "ลบไม่ได้" (ตอบ 409 IN_USE): ลูกค้า/สาขา/สกุลเงิน/สินค้าที่อยู่ในเอกสาร, ผู้ใช้ที่สร้าง/อนุมัติ/ยกเลิกเอกสารหรือมีลายเซ็น, role ในกติกาอนุมัติ, โปรเจกต์ที่ผูกใบเสนอราคา
  · ลบหมวด → สินค้า/ชุดกลายเป็นไม่มีหมวด · ลบชุดรายการ → รายการในใบแค่ไม่รู้ว่ามาจากชุดไหน · ลบใบเสนอราคา (ร่าง) → รายการ/งวด/ประวัติตามไปด้วย

## 2. สถานะและการเปลี่ยนสถานะของใบเสนอราคา
```
           ┌──────────── ตีกลับ ชั้นใดก็ได้ (เหตุผล) → เริ่มชั้น 1 ใหม่ รอบถัดไป ───────────┐
           ▼                                                                         │
 [draft] ──ส่งขออนุมัติ──► [pending_approval ชั้น 1 → 2 → … → n] ──ชั้นสุดท้ายอนุมัติ──► [approved] ──ส่งลูกค้า──► [sent]
   │ ลบได้ (ถ้ายังไม่เคยมีเลข)         (snapshot แผนอนุมัติตอนส่ง)            (ออกเลข+snapshot)   │                    │
   │                                                                                  ├──ลูกค้าตอบรับ──► [accepted] ──► โปรเจกต์ + งาน
   │                                                                                  ├──ลูกค้าปฏิเสธ──► [declined]
   │                                                                                  ├──เลยวันยืนราคา──► [expired]
   │                                                                                  └──ยกเลิก────────► [cancelled]
   └── ออก revision จากใบที่อนุมัติแล้ว (ยังไม่ตอบรับ) → ร่างใหม่ (เลขเดิม Rev.N+1) · Rev ใหม่อนุมัติ → ฉบับเก่าเป็น [superseded]
```

| การกระทำ | จากสถานะ | สิทธิ์ | เงื่อนไข / ผลที่เกิด |
|---|---|---|---|
| สร้างร่าง | – | สร้าง/แก้ | ลูกค้าต้อง active · ค่าเริ่มต้นจากลูกค้า: สกุลเงิน, ภาษา, การคิด VAT · สาขา = สาขาผู้สร้าง · ร่าง **ยังไม่มีวันที่เอกสาร** เก็บแค่อายุยืนราคา (วัน, ค่าเริ่มต้นจากตั้งค่า) · เงื่อนไขตามภาษาเอกสาร · ดึงอัตราแลกเปลี่ยน (ถ้าไม่ใช่ THB) |
| คัดลอกเป็นใบใหม่ | ทุกสถานะ | สร้าง/แก้ | ร่างใหม่ (ไม่มีเลข, Rev.0) คัดลอกรายการ+งวด · ใช้กรณีงานเพิ่มหลังตอบรับ หรือเสนอลูกค้ารายอื่น · วันที่/อัตราแลกเปลี่ยนตั้งใหม่ |
| แก้ร่าง | draft | สร้าง/แก้ | แก้ได้ทุกช่อง · คำนวณยอดใหม่ฝั่ง backend ทุกครั้งที่บันทึก |
| ลบร่าง | draft | สร้าง/แก้ | ลบจริง · ร่าง revision ลบได้ (เลขยังอยู่กับฉบับก่อน) |
| ส่งขออนุมัติ | draft | สร้าง/แก้ | ต้องมีรายการราคา ≥ 1, ยอด > 0, งวดรวมเท่ายอด, อายุยืนราคา 1–365 วัน, สกุลต่างประเทศต้องมีอัตรา · **ล็อกอัตราแลกเปลี่ยน** · คำนวณ VAT ด้วยวันที่ส่ง · คำนวณแผนอนุมัติจากยอดก่อน VAT เป็นบาท แล้ว snapshot · รอบ +1 · บันทึกลายเซ็นผู้สร้าง (ฉบับปัจจุบัน) |
| อนุมัติ | pending_approval | อนุมัติใบเสนอราคา + role อยู่ในชั้นปัจจุบัน | ห้ามผู้สร้าง (ยกเว้นตั้งค่า) · ชั้นที่เปิด "ต้องเป็นคนละคน" ห้ามคนที่อนุมัติชั้นก่อนหน้าในรอบนี้ · บันทึกชั้นนี้ แล้ว **ผ่านชั้นถัดไปต่อเนื่องอัตโนมัติถ้าผู้กดมีสิทธิ์ชั้นนั้นด้วย** และชั้นนั้นไม่ได้บังคับคนละคน (บันทึกแยกทีละชั้น, ยืนยันก่อนกด — หัวข้อ 3) · ครบชั้นสุดท้าย → approved: **วันที่เอกสาร = วันนี้ (เวลาไทย)**, ยืนราคาถึง = วันที่ + อายุ, ออกเลข (Rev.0) / ใช้เลขเดิม (Rev ≥ 1), snapshot ลูกค้า/บริษัท/สาขา, ตรวจ VAT ซ้ำ (R19), บันทึกลายเซ็นผู้อนุมัติชั้นสุดท้าย, ฉบับก่อน → superseded |
| ตีกลับ | pending_approval | เหมือนอนุมัติ (ชั้นปัจจุบัน) | ต้องมีเหตุผล → draft · รอบหน้าเริ่มชั้น 1 ใหม่ |
| ส่งลูกค้า | approved | สร้าง/แก้ | บันทึกวันที่ส่ง |
| ลูกค้าตอบรับ | approved, sent | สร้าง/แก้ | เลือกโปรเจกต์: สร้างใหม่ (`insertProject`, ผู้กดเป็น PM) / ผูกโปรเจกต์เดิมของลูกค้ารายนี้ / ไม่ผูก · ช่องติ๊ก "สร้างงานจากรายการ" (ติ๊กไว้ก่อน ซ่อนเมื่อไม่ผูกโปรเจกต์) — ดูหัวข้อ 7 · **ล็อกถาวร** |
| ลูกค้าปฏิเสธ | approved, sent | สร้าง/แก้ | ต้องมีเหตุผล |
| หมดอายุ | approved, sent | ระบบ | เปลี่ยนอัตโนมัติเมื่อเลยวันยืนราคา (ตรวจตอนอ่านข้อมูล) |
| ออก revision | approved, sent, expired, declined | สร้าง/แก้ | ร่างใหม่ คัดลอกรายการ+งวด · มีร่างค้างได้ทีละ 1 ใบต่อสาย · ยืนราคาถึงตั้งใหม่ · อัตราแลกเปลี่ยนดึงใหม่ · **ใบที่ตอบรับแล้วออก revision ไม่ได้** (ใช้ "คัดลอกเป็นใบใหม่") |
| ยกเลิก | ทุกสถานะ ยกเว้น accepted, cancelled, superseded | ยกเลิกใบเสนอราคา | ต้องมีเหตุผล · เลขที่คงอยู่ · ร่างที่ยังไม่มีเลขใช้ "ลบ" แทน |

## 3. การอนุมัติหลายชั้น
**ตั้งค่า** (แท็บ "การอนุมัติ" ใน `/settings/company`):
```
ชั้น 1  ยอดตั้งแต่ 0 บาท          role: หัวหน้าฝ่ายขาย, กรรมการผู้จัดการ
ชั้น 2  ยอดตั้งแต่ 100,000 บาท     role: ผู้จัดการ, กรรมการผู้จัดการ
ชั้น 3  ยอดตั้งแต่ 1,000,000 บาท   role: กรรมการผู้จัดการ           ☑ ต้องเป็นคนละคนกับผู้อนุมัติชั้นก่อนหน้า
```
- **"ต้องเป็นคนละคนกับผู้อนุมัติชั้นก่อนหน้า"** (ตั้งต่อชั้น, เพิ่ม 12 ต.ค. 2026): คนที่อนุมัติชั้นใดก็ตามก่อนหน้าในรอบเดียวกันอนุมัติชั้นนี้ไม่ได้
  → การผ่านรวดเดียวหยุดที่ชั้นก่อนหน้านี้ ใบรอคนอื่นมาอนุมัติ · ใช้กับชั้นยอดสูงเพื่อบังคับให้มีผู้ตรวจอย่างน้อย 2 คน
  ระบบเตือนตอนบันทึกกติกาถ้าชั้นที่บังคับคนละคน มีผู้ใช้ที่มีสิทธิ์อนุมัติแค่คนเดียว (ใบจะค้าง)
- **ยืนยันก่อนกดอนุมัติ** (เพิ่ม 12 ต.ค. 2026): หน้าต่างยืนยันบอกเสมอว่ากดครั้งนี้ผ่านชั้นไหนบ้าง และหลังจากนี้เหลืออะไร เช่น
  "คุณกำลังอนุมัติ **ชั้น 1 และชั้น 2** · ชั้น 3 ต้องให้ผู้อนุมัติคนอื่น (กรรมการผู้จัดการ) อนุมัติต่อ เพราะชั้นนี้กำหนดให้เป็นคนละคน"
  หรือ "คุณกำลังอนุมัติ **ชั้น 1 (ชั้นสุดท้าย)** · ใบเสนอราคาจะได้เลขที่และแก้ไขไม่ได้อีก"
- ใบที่ยอดก่อน VAT (เป็นบาท) = 250,000 → ต้องผ่านชั้น 1 แล้วชั้น 2 · ยอด 50,000 → ชั้น 1 อย่างเดียว
- ยอดขั้นต่ำต้องเรียงจากน้อยไปมาก · ทุกชั้นต้องมี role ≥ 1 · ระบบเตือนถ้า role ในชั้นไหนไม่มีผู้ใช้ที่มีสิทธิ์ "อนุมัติใบเสนอราคา" (ใบจะค้าง)
- ผู้ใช้มีได้ role เดียว (`user_role_id`) — "คนเดียวอนุมัติหลายชั้น" ทำได้โดยใส่ role เดียวกันไว้หลายชั้น (เช่น กรรมการผู้จัดการ ข้างบน กดครั้งเดียวผ่านทุกชั้นที่เหลือ)
- **แผนอนุมัติ snapshot ตอนส่งขออนุมัติ** — แก้กติกาทีหลังไม่กระทบใบที่รออยู่ · ส่งใหม่หลังตีกลับ = คำนวณแผนใหม่ตามกติกาปัจจุบัน
- ผู้ใช้เห็นป้าย "รอคุณอนุมัติ" เฉพาะใบที่ชั้นปัจจุบันตรงกับ role ตัวเอง · หน้าเอกสารแสดง "รออนุมัติชั้น 2/3 (ผู้จัดการ, กรรมการผู้จัดการ)" + ประวัติทุกชั้นทุกรอบ

## 4. การคำนวณเงิน (เทสต์ใน `backend/test/money.test.js` — ต้องขยายรองรับข้อใหม่)
```
แถว heading / note      ไม่มียอด ไม่นับ
ส่วนลดบรรทัด           = บาท หรือ % ของ (จำนวน × ราคาต่อหน่วย)        (ปัดครึ่งขึ้นตามทศนิยมของสกุลเงิน, ห้ามเกินยอดก่อนลด)
ยอดบรรทัด             = จำนวน × ราคาต่อหน่วย − ส่วนลดบรรทัด
รวมเป็นเงิน            = Σ ยอดบรรทัด
ส่วนลดท้ายบิล          = บาท หรือ % ของรวมเป็นเงิน                      (ห้ามเกินรวมเป็นเงิน)
หลังหักส่วนลด          = รวมเป็นเงิน − ส่วนลดท้ายบิล
VAT                  = หลังหักส่วนลด × อัตรา
                       อัตรา = 0 ถ้าวันที่เอกสาร < วันจด VAT หรือ เลือก "0%" · ไม่งั้น = อัตราใน tb_vat_rates ณ วันที่เอกสาร
รวมทั้งสิ้น             = หลังหักส่วนลด + VAT
งวด %                = รวมทั้งสิ้น × % (ปัด) · งวดสุดท้าย = ยอดที่เหลือ (รับเศษ)
ยอดเป็นบาท (ภายใน)     = หลังหักส่วนลด × อัตราแลกเปลี่ยน, รวมทั้งสิ้น × อัตราแลกเปลี่ยน (ปัดเป็นสตางค์) — THB อัตรา = 1
```
- ทศนิยมตามสกุลเงิน (`cur_decimals` 0–2 เช่น JPY = 0) — ไม่รองรับสกุลที่มี 3 ทศนิยม (ตั้งค่าไม่ได้)
- ยอดรวมแสดง **จำนวนเงินตัวอักษร** ตามภาษาเอกสาร + ชื่อสกุลเงิน เช่น "หนึ่งหมื่นสองพันบาทห้าสิบสตางค์" / "หนึ่งพันห้าร้อยดอลลาร์สหรัฐถ้วน" / "One Thousand Five Hundred US Dollars Only" — ฟังก์ชันพร้อมเทสต์
- เลือกสินค้า (ราคาบาท) ใส่ใบสกุลต่างประเทศ → ราคา ÷ อัตรา ปัดตามทศนิยมสกุลนั้น แก้ต่อได้
- เปลี่ยนสกุลเงิน/อัตราในร่างที่มีรายการแล้ว → หน้าเว็บถามว่า "แปลงราคาที่มีอยู่ตามอัตราใหม่ไหม" (ไม่แปลงเงียบๆ)

## 4.1 เลือกรายการจากสินค้า/บริการที่บันทึกไว้ (ผู้ใช้เลือก 12 ต.ค. 2026)
**สองทาง ใช้ร่วมกัน:**
1. **แผงเลือกรายการ** — ปุ่ม "เพิ่มจากรายการ" เหนือตาราง เปิดแผงด้านขวา (มือถือ = เต็มจอเลื่อนจากล่าง)
   - ช่องค้นหา (ชื่อ / รหัส / รายละเอียด) · ชิปกรองหมวด · แท็บ **ใช้บ่อย** (ของผู้ใช้คนนี้ 90 วันล่าสุด) / **ทั้งหมด** / **ชุดรายการ**
   - แต่ละแถว: ชื่อ, รหัส, หน่วย, ราคาตั้งต้น (แปลงเป็นสกุลของใบ), ปุ่ม "+ เพิ่ม" · ป้าย "ในใบแล้ว ×2" ถ้าเคยเพิ่ม
   - **กดเพิ่มได้หลายรายการติดกัน แผงไม่ปิด** · แถวที่เพิ่มกระพริบในตารางให้เห็น (ไม่ใช้ toast)
   - ตัวเลือก "เพิ่มไปที่: ท้ายใบ / ใต้หัวข้อ …" (ค่าเริ่มต้น = หัวข้อสุดท้ายที่แก้)
   - คีย์บอร์ด: พิมพ์ค้นได้ทันทีที่เปิด, ↑↓ เลือก, Enter เพิ่ม, Esc ปิด
2. **พิมพ์ค้นในแถว** — พิมพ์ในช่องรายการ ขึ้นรายการที่ตรงให้เลือก (combobox) · เลือก = เติมชื่อ/หน่วย/ราคาลงแถวนั้น · ไม่เลือก = เป็นข้อความอิสระตามเดิม

**กติกา**
- **กดสินค้าเดิมซ้ำ = บรรทัดใหม่เสมอ** (บริการเดียวกันอยู่คนละหัวข้อได้)
- ค่าที่เติม: ชื่อ → รายละเอียด, หน่วย, ราคาตั้งต้น → ราคาต่อหน่วย และเก็บ `qti_list_price` · ทุกช่องแก้ต่อได้ — **ใบเก็บสำเนาของตัวเอง** แก้สินค้าทีหลังใบไม่เปลี่ยน
- **ชุดรายการ**: กดครั้งเดียวได้ทุกแถวของชุดตามลำดับ (หัวข้อ/รายการ/หมายเหตุ) · แถวที่อ้างสินค้าใช้ราคาปัจจุบันของสินค้า · สินค้าในชุดที่ถูกปิดใช้งาน = ข้าม และแจ้งในแผง "ข้าม 1 รายการที่ปิดใช้งาน: …"
- **ใช้บ่อย**: นับจากใบเสนอราคาที่ผู้ใช้คนนี้สร้าง 90 วันล่าสุด เรียงตามจำนวนครั้ง (ไม่มีตารางใหม่ — query จาก `tb_quotation_items`)
- **บันทึกเป็นสินค้าใหม่จากใบ** (เฉพาะคนที่มีสิทธิ์จัดการสินค้า): เมนูของแถวข้อความอิสระ → หน้าต่างกรอก ชื่อ/หมวด/หน่วย/ราคาบาท (เติมจากแถว, ใบสกุลต่างประเทศแปลงกลับเป็นบาทให้) → แถวนั้นผูกกับสินค้าใหม่
- **ราคาต่ำกว่าราคาตั้งต้น** (ผู้ใช้เลือก "แก้ได้ + แจ้งผู้อนุมัติ"):
  - บรรทัดที่ *ยอดบรรทัด < จำนวน × ราคาตั้งต้น* (คิดรวมส่วนลดบรรทัด) มีป้าย "ต่ำกว่าราคาตั้งต้น −5,000" ใต้แถว
  - ส่วนลดท้ายบิลแสดงแยกเป็นอีกบรรทัด
  - ตอนส่งขออนุมัติ backend **อัปเดต `qti_list_price` เป็นราคาปัจจุบันของสินค้า** แล้วคำนวณใหม่ — ผู้อนุมัติเทียบกับราคาล่าสุดเสมอ
  - แถบสถานะของผู้อนุมัติ + หน้าต่างยืนยันแสดง "3 รายการต่ำกว่าราคาตั้งต้น รวม −15,000 บาท · ส่วนลดท้ายบิล −10,000 บาท" กดดูรายบรรทัดได้
- **ราคาสินค้าเปลี่ยนระหว่างที่ร่างค้างอยู่**: แถวแสดง "ราคาตั้งต้นตอนนี้ 55,000 (ตอนเพิ่ม 50,000)" + ปุ่ม "ใช้ราคาใหม่" — ไม่เปลี่ยนให้เอง
- สินค้าที่ปิดใช้งาน: ไม่ขึ้นในแผง/การค้นหา · แถวที่เพิ่มไปแล้วในร่าง **ส่งขออนุมัติได้** (เป็นสำเนาแล้ว) แค่มีข้อความบอก — ต่างจากลูกค้า/สาขา/สกุลเงินที่ปิดแล้วซึ่งบล็อก (R9)
- ค้นหาฝั่ง backend (หน่วงพิมพ์ 250 ms, สูงสุด 50 แถวต่อครั้ง, index ชื่อ/รหัส) — รองรับสินค้าหลายพันรายการ

**หน้าจัดการ** (`/sales/products`, สิทธิ์ "จัดการสินค้า/บริการ"): แท็บ สินค้า/บริการ · หมวดหมู่ · ชุดรายการ (สร้างชุดด้วยตัวแก้ไขแบบเดียวกับตารางในใบเสนอราคา + แผงเลือกรายการเดียวกัน)

## 5. หลายสกุลเงิน + อัตราแลกเปลี่ยน ธปท.
- ดึงจาก **ธนาคารแห่งประเทศไทย API (อัตราแลกเปลี่ยนเฉลี่ยของธนาคารพาณิชย์)** ใช้ **อัตราซื้อถัวเฉลี่ย** · ต้องสมัคร API ที่ BOT API Portal
  แล้วใส่คีย์ใน `.env` ของ backend (ไม่เก็บในฐานข้อมูล) — **งานของผู้ใช้: สมัคร API key** · รายละเอียด endpoint/ฟิลด์ตรวจอีกครั้งตอนเขียนโค้ด
- ธปท. ประกาศอัตราของวันทำการหลังปิดตลาด → ใช้ **อัตราล่าสุดที่ประกาศ ณ หรือก่อนวันที่เอกสาร** (วันหยุด/วันนี้ที่ยังไม่ประกาศ = ใช้วันทำการก่อนหน้า) และแสดงวันที่ของอัตราให้เห็น
- แปลงหน่วยที่ ธปท. ประกาศ (เช่น ต่อ 100 เยน) เป็นบาทต่อ 1 หน่วยก่อนเก็บ
- ผลที่ดึงมาเก็บแคชใน `tb_exchange_rates` · ดึงไม่ได้ (API ล่ม/ไม่มีคีย์) → ผู้สร้างต้องกรอกเองพร้อมเหตุผล
- ร่าง: ใช้อัตราล่าสุด ณ วันที่ทำร่าง แก้ได้พร้อมเหตุผล (เช่น ตกลงอัตราคงที่กับลูกค้า) · **ล็อกตอนส่งขออนุมัติ** ไม่ดึงใหม่ตอนอนุมัติ —
  ผู้อนุมัติทุกชั้นเห็นตัวเลขเดียวกับที่จะลงเอกสาร (ทั้งอัตรา ธปท. และอัตราที่แก้) · วันที่ของอัตราอาจก่อนวันที่เอกสารไม่กี่วัน — แสดงชัดบนหน้าจอภายใน
- เอกสารที่ส่งลูกค้าแสดงเฉพาะสกุลเงินของเอกสาร (ไม่แสดงยอดบาท) · ยอดบาทใช้ภายใน: เกณฑ์อนุมัติ, รายงาน, แดชบอร์ด
- ⚠ ประเภทอัตราที่ใช้แปลงรายได้ทางภาษีต้องให้นักบัญชียืนยัน (คำถาม B6) — ใบเสนอราคาเองไม่ใช่เอกสารทางภาษี เปลี่ยนทีหลังได้ไม่กระทบ

## 6. ลายเซ็น
- หน้าโปรไฟล์ → "ลายเซ็นของฉัน": อัปโหลดรูป หรือเซ็นบนจอ (เมาส์/นิ้ว) → ระบบตัดขอบ, พื้นโปร่งใส, บีบอัดแบบไม่เสียรายละเอียด (lossless)
  ต้องใส่รหัสผ่านยืนยันก่อนบันทึก · ตั้งได้เฉพาะเจ้าตัว — แอดมิน **ยกเลิก** ลายเซ็นของคนอื่นได้ (เช่น พนักงานลาออก) แต่ตั้งแทนไม่ได้
- ไฟล์ลายเซ็น **ไม่อยู่ใน /uploads ที่เปิดสาธารณะ** — ส่งผ่าน endpoint ที่ต้อง login เท่านั้น · การตั้ง/ยกเลิกลายเซ็นเข้า audit log
- ใบเสนอราคาแสดงลายเซ็น: **ผู้เสนอราคา** (ฉบับที่ใช้ตอนส่งขออนุมัติ) + **ผู้อนุมัติชั้นสุดท้าย** (ฉบับตอนอนุมัติ) · ช่องลูกค้าเว้นว่างให้เซ็นกลับ
- ร่าง/รออนุมัติ: ไม่แสดงลายเซ็นเด็ดขาด · ใบที่ยกเลิก: แสดงตราประทับ "ยกเลิก" ทับ
- คนที่ยังไม่มีลายเซ็น → เว้นช่องว่างให้เซ็นมือ + พิมพ์ชื่อ (ไม่บล็อกการอนุมัติ)

## 7. ตอบรับ → โปรเจกต์ + สร้างงานจากรายการ
- สร้างโปรเจกต์ใหม่: ชื่อ = ชื่อเรื่องใบเสนอราคา, ลูกค้า = ลูกค้าในใบ, ผู้กดเป็นสมาชิกตำแหน่ง PM (ฟังก์ชันเดียวกับหน้าโปรเจกต์)
- ช่องติ๊ก "สร้างงานจากรายการ" (ติ๊กไว้ก่อน) ใช้ได้ทั้งโปรเจกต์ใหม่และโปรเจกต์เดิม (โปรเจกต์เดิม = เพิ่มต่อท้ายงานที่มี)
```
ใบเสนอราคา                         งานในโปรเจกต์
[หัวข้อ] ระบบหลังบ้าน          →   □ ระบบหลังบ้าน               (งานหลัก)
  ออกแบบฐานข้อมูล  20,000      →       □ ออกแบบฐานข้อมูล        (งานย่อย)
  ทำ API          50,000      →       □ ทำ API
[หัวข้อ] แอปมือถือ             →   □ แอปมือถือ
  หน้าจอหลัก       30,000      →       □ หน้าจอหลัก
[หมายเหตุ] ...                 →   (ไม่สร้างงาน)
รายการที่อยู่ก่อนหัวข้อแรก         →   งานหลักระดับบนสุด
```
- ชื่องาน = บรรทัดแรกของรายละเอียด (ตัดที่ 200 ตัว) · รายละเอียดงาน = ข้อความเต็ม + "จากใบเสนอราคา QT-xxxx Rev.N"
- งานยังไม่มีผู้รับผิดชอบ/วันที่ (PM มอบหมายต่อ — โปรเจกต์ agile สมาชิกกดรับเองได้ตามกติกาเดิม) · **ไม่คัดลอกราคาไปในงาน**
- ทุกงานเก็บ `task_quotation_item_id` ไว้อ้างกลับ · ทำใน transaction เดียวกับการตอบรับ (สร้างไม่ครบ = ไม่ตอบรับ)

## 8. หน้าจอ
เมนูใหม่ในแถบข้าง: กลุ่ม **"ขาย"** → ใบเสนอราคา, สินค้า/บริการ · ใน **ตั้งค่า** → ข้อมูลบริษัท

| หน้า | เนื้อหา |
|---|---|
| `/settings/company` | แท็บ: ข้อมูลบริษัท (ไทย/อังกฤษ) + โลโก้ · VAT · ค่าเริ่มต้นใบเสนอราคา (อายุ, เงื่อนไขไทย/อังกฤษ, อนุญาตอนุมัติเอง) · **การอนุมัติ** · **สกุลเงิน** (เปิด/ปิด, ทดสอบดึงอัตรา ธปท.) · สาขา · บัญชีธนาคาร |
| จัดการผู้ใช้ (หน้าเดิม) | + ช่อง "สาขา" |
| โปรไฟล์ (หน้าเดิม) | + "ลายเซ็นของฉัน" (อัปโหลด/เซ็นบนจอ, ยืนยันรหัสผ่าน) |
| ลูกค้า (หน้าเดิม) | + ประเภท, ประเทศ, เลขผู้เสียภาษี, สาขาลูกค้า, ที่อยู่ออกเอกสาร, ผู้ติดต่อ, เครดิตเทอม, อัตราหัก ณ ที่จ่าย, สกุลเงิน/ภาษา/การคิด VAT เริ่มต้น |
| `/sales/products` | ตาราง + ค้นหา + กรอง active · ฟอร์มใน dialog |
| `/sales/quotations` | แท็บตามสถานะ · ค้นหาเลข/ชื่อเรื่อง/ลูกค้า · กรองวันที่/สาขา/สกุลเงิน · ยอดแสดงตามสกุลเงิน + ยอดบาท · ป้าย "รอคุณอนุมัติ" |
| `/sales/quotations/new`, `/[id]/edit` | หัว: ลูกค้า, สาขา, ชื่อเรื่อง, วันที่, ยืนราคาถึง, โปรเจกต์, **สกุลเงิน + อัตรา (วันที่อัตรา, แก้ได้พร้อมเหตุผล)**, **ภาษาเอกสาร**, **การคิด VAT** · ตารางรายการ: เพิ่มแถว รายการ/หัวข้อ/หมายเหตุ, เลือกสินค้าหรือพิมพ์เอง, ส่วนลดบาท/%, ลากเรียงลำดับ · ส่วนลดท้ายบิล · สรุปยอดสด · งวดชำระ · เงื่อนไข · บันทึกภายใน · ป้ายบอกล่วงหน้าว่า "ยอดนี้ต้องอนุมัติ 2 ชั้น" |
| `/sales/quotations/[id]` | เอกสารแบบหน้าพิมพ์ + ปุ่มตามสถานะ/สิทธิ์ · ความคืบหน้าอนุมัติ · ไทม์ไลน์ทุกเหตุการณ์ · revision ทั้งสาย · ลิงก์โปรเจกต์ |
| `/sales/quotations/[id]/print` | A4 สำหรับพิมพ์/บันทึก PDF จากเบราว์เซอร์ |

**หน้าพิมพ์ A4** (ข้อความหัวเอกสารทั้งหมดตามภาษาเอกสาร):
- หัว: โลโก้ + ชื่อ/ที่อยู่/เลขผู้เสียภาษีบริษัท + สาขา (จาก snapshot, ภาษาตามเอกสาร) · "ใบเสนอราคา" / "QUOTATION" · เลขที่ (+ Rev.N), วันที่, ยืนราคาถึง
- วันที่: เอกสารไทยแสดง **พ.ศ.** (12 ตุลาคม 2569) · เอกสารอังกฤษแสดง ค.ศ. (12 October 2026)
- กล่องลูกค้า · ตารางรายการ (แถวหัวข้อตัวหนา + **ยอดรวมย่อยท้ายแต่ละหัวข้อ**, แถวหมายเหตุตัวเอียง) · สรุปยอด + จำนวนเงินตัวอักษร · สกุลเงินระบุชัด

- ร่าง: ลายน้ำ "ร่าง — ไม่ใช่เอกสารทางการ" · หลายหน้า: หัวตารางซ้ำทุกหน้า + เลขหน้า "หน้า 1/2"

# ช่วง 1B–1D — โครงร่าง (ทำแบบละเอียดก่อนเริ่มแต่ละช่วง)

**1B ใบแจ้งหนี้ / ใบวางบิล**
- ใบแจ้งหนี้ออกจากงวดของใบเสนอราคาที่ตอบรับแล้ว (หรือสร้างเองไม่อ้างใบเสนอราคา) · ครบกำหนด = วันที่ + เครดิตเทอมลูกค้า
- ร่าง → ออก (ได้เลข IV) → ยกเลิกพร้อมเหตุผล · ออกแล้วแก้ไม่ได้ · แสดงบัญชีธนาคารหลักของสกุลเงินนั้น
- สกุลเงิน/ภาษา/การคิด VAT ตามใบเสนอราคา · อัตราแลกเปลี่ยนของวันที่ใบแจ้งหนี้ (ไม่ใช่ของใบเสนอราคา)
- ใบวางบิลรวมหลายใบแจ้งหนี้ของลูกค้ารายเดียว (สกุลเงินเดียวกัน) + วันนัดรับเช็ค/โอน
- ตาราง: `tb_invoices`, `tb_invoice_items`, `tb_billing_notes`, `tb_billing_note_invoices`

**1C ใบเสร็จรับเงิน / หัก ณ ที่จ่าย**
- รับเงินตัดหลายใบแจ้งหนี้ได้ / รับบางส่วนได้ · วิธีรับ: โอน/เช็ค/เงินสด · บันทึกยอดหัก ณ ที่จ่ายจริง + แนบไฟล์ 50 ทวิ · ค่าธรรมเนียมโอน
- สกุลต่างประเทศ: บันทึกยอดบาทที่ได้รับจริง → ส่วนต่างอัตราแลกเปลี่ยนส่งให้นักบัญชี
- รายงานลูกหนี้คงค้างแยกอายุ 0–30 / 31–60 / 61–90 / >90 วัน
- ตาราง: `tb_receipts`, `tb_receipt_allocations`

**1D การเงินโปรเจกต์ / ส่งนักบัญชี**
- แท็บการเงินในโปรเจกต์: มูลค่าที่ตอบรับ, ออกบิลแล้ว, รับแล้ว, ค้างรับ, งวดถัดไป, ความคืบหน้างาน (จาก `task_quotation_item_id`)
- ส่งออก Excel รายเดือน (รูปแบบตามที่นักบัญชีต้องการ) · แดชบอร์ดยอดขาย (เป็นบาท)

**คำถามสำหรับช่วงหลัง (ยังไม่ต้องตอบตอนนี้ — ต้องถามนักบัญชี)**
| # | คำถาม |
|---|---|
| B1 | **จุดความรับผิดภาษีของงานบริการ**: ตามหลักทั่วไป ธุรกิจบริการต้องออกใบกำกับภาษีเมื่อ "ได้รับชำระเงิน" ไม่ใช่ตอนแจ้งหนี้ → หลังจด VAT ใบเสร็จอาจต้องเป็น "ใบเสร็จรับเงิน/ใบกำกับภาษี" ส่วนใบแจ้งหนี้เป็นแค่ใบแจ้งหนี้ — มีผลต่อแบบ 1B/1C ทั้งหมด |
