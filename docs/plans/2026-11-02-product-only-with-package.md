# สินค้าที่แสดงเมื่อเลือกบางชุดเท่านั้น · 2026-11-02

เจ้าของ: "บางสินค้าอาจแสดงเมื่อเลือกบางชุดรายการเท่านั้น"

ตัวอย่าง: "เพิ่มภาษาที่ 3" ขายได้เฉพาะคนที่เลือกแพ็กเว็บ 2 ภาษา · "เพิ่มห้องพัก" ขายเฉพาะแพ็กระบบจองโรงแรม

## ที่มีอยู่แล้ว

`tb_package_addon_rules` (2026-10-25) ตั้งที่ชุด มี 2 แบบ:

| กติกา | ผลเมื่อลูกค้าเลือกชุดนั้น |
| --- | --- |
| `included` มีในแพ็กแล้ว | การ์ดงานเพิ่มขึ้นว่ามีในแพ็กแล้ว กดซื้อไม่ได้ |
| `not_available` ใช้กับแพ็กนี้ไม่ได้ | ซ่อนงานเพิ่มนั้น |

ใช้ใน 3 ที่:
- หน้าร้านของลิงก์เลือกบริการ (`order-shop.tsx`)
- ตัวคิดราคา (`price-calculator/page.tsx`, `price-catalog.tsx`)
- backend ตอนส่งคำขอ (`order-public.service.js` ตรวจซ้ำ)

ที่ยังไม่มี: แบบกลับด้าน คือสินค้าที่ปกติไม่แสดง และแสดงเมื่อเลือกชุดที่กำหนดเท่านั้น

## ข้อเสนอ

- เก็บในตารางเดิม เพิ่มกติกาแบบที่ 3 `only_with` (ขายคู่กับชุดนี้)
  - สินค้าที่มีแถว `only_with` อย่างน้อย 1 ชุด = "สินค้าเฉพาะชุด"
  - แสดงเมื่อในตะกร้ามีชุดใดชุดหนึ่งในรายการนั้น
  - ไม่เพิ่มตารางใหม่ ไม่เก็บข้อมูลซ้ำ
- ตรวจที่เดียวกับกติกาเดิมทั้ง 3 ที่ (ใช้ฟังก์ชันกลางใน shared ทั้งหน้าเว็บและ backend ไม่เขียนกติกาซ้ำ)
- เมื่อเอาชุดออกจากตะกร้า สินค้าเฉพาะชุดที่ไม่มีชุดรองรับแล้วต้องจัดการ (ดูคำถาม)
- backend ตอนส่งคำขอ: มีสินค้าเฉพาะชุดแต่ไม่มีชุดที่รองรับ = ไม่รับ พร้อมบอกชื่อชุดที่ต้องเลือก
- รายการที่ทีมเลือกให้ในลิงก์ (ล็อก) ไม่ติดกติกานี้ เพราะทีมเลือกเอง · เตือนในแผ่นสร้างลิงก์ถ้าเลือกสินค้าเฉพาะชุดโดยไม่มีชุดคู่
- ใบเสนอราคาที่ทีมเขียนเองไม่บังคับ (ทีมใส่อะไรก็ได้) · ระบบเตือนเท่านั้น

## จุดที่ต้องระวัง

- ชุดที่ผูกไว้ถูกปิดใช้งานหรือลบ
  - ลบ: แถวหายเอง (FK cascade)
  - ปิดใช้งาน: สินค้าไม่มีชุดที่เปิดอยู่รองรับ = ไม่แสดงเลย → หน้าสินค้าต้องเตือน
- สินค้าเฉพาะชุดที่ไม่ได้เปิดหน้าร้าน: ยังไม่แสดงบนหน้าร้านเหมือนเดิม (กติกาหน้าร้านมาก่อน)
- ชุดที่ตั้ง `included` หรือ `not_available` กับสินค้าเดียวกันอยู่แล้ว: ตั้ง `only_with` คู่เดียวกันไม่ได้ (คู่ชุดกับสินค้ามีกติกาได้ 1 แบบ ตาม primary key เดิม)
- คำถามที่ผูกกับสินค้าเฉพาะชุด (ถามเมื่อเลือก) ทำงานเหมือนเดิม เพราะถามเมื่อสินค้าอยู่ในตะกร้า
- ชุดที่ใส่ในตะกร้าหลายชุด: แสดงเมื่อชุดใดชุดหนึ่งรองรับ
- schema: แก้ enum ของ `par_rule` → อัปเดต deploy_schema (ALTER แบบ idempotent) + manifest

## คำตอบเจ้าของ (2026-11-02)

| คำถาม | ตอบ |
| --- | --- |
| ตั้งที่ไหน | ในฟอร์มสินค้า |
| ก่อนเลือกชุด | ลูกค้าไม่เห็น · ทีมเห็นพร้อมเหตุผล |
| เอาชุดออกจากตะกร้า | เอาสินค้าเฉพาะชุดออกด้วย และบอกว่าเอาอะไรออกเพราะอะไร |

## ออกแบบละเอียด

### ข้อมูล

- `tb_package_addon_rules.par_rule` เพิ่มค่า `only_with`
  - deploy_schema: แก้ CREATE + ALTER MODIFY แบบตรวจก่อน (ทำซ้ำได้) · manifest
- คู่ชุดกับสินค้ามีกติกาได้ 1 แบบ (primary key เดิม)
- บันทึกกติกาสองที่ ต้องไม่ลบของกันและกัน:
  - บันทึกชุด (กติกางานเพิ่ม): แทนเฉพาะแถว `included` / `not_available` ของชุดนั้น ไม่แตะ `only_with`
  - บันทึกสินค้า: แทนเฉพาะแถว `only_with` ของสินค้านั้น
  - ชนกัน (ชุดนั้นตั้งกติกาแบบอื่นกับสินค้านี้อยู่แล้ว) = ตอบ 400 บอกชื่อชุดและกติกาเดิม

### ฟอร์มสินค้า (แท็บสินค้า/บริการ)

- ช่องใหม่ "แสดงเมื่อเลือกชุด" เลือกได้หลายชุด (ค้นหาชื่อชุด) · ว่าง = แสดงตามปกติ
- คำอธิบายใต้ช่อง: ลูกค้าเห็นสินค้านี้เมื่อเลือกชุดใดชุดหนึ่งในรายการแล้วเท่านั้น · ทีมเห็นในตัวคิดราคาพร้อมบอกว่าต้องเลือกชุดไหน
- ชุดที่เลือกไว้แต่ถูกปิดใช้งาน: ขึ้นเตือนว่า "ชุดนี้ปิดใช้งานอยู่" · ทุกชุดที่เลือกปิดหมด = เตือนว่าลูกค้าจะไม่เห็นสินค้านี้เลย
- รายการสินค้าในแท็บ: ป้าย "เฉพาะชุด" ที่สินค้านั้น

### ฟอร์มชุด (แท็บชุดรายการ)

- ใต้กติกางานเพิ่มเดิม แสดงอ่านอย่างเดียว: "สินค้าที่ขายคู่กับชุดนี้" (ชื่อสินค้าเป็นลิงก์ กดแล้วเปิดแผงแก้สินค้านั้น · ใช้ทางเดิมของแท็บคำถาม)
- ตัวเลือกกติกางานเพิ่มไม่ให้เลือกสินค้าที่ตั้ง "แสดงเมื่อเลือกชุด" กับชุดนี้อยู่แล้ว

### ฟังก์ชันกลาง (shared · ใช้ทั้งหน้าเว็บและ backend)

- `addonStateOf(productId, cartPackages, rules)`
  - คืน `{ state: "ok" | "included" | "not_available" | "needs_package", packageNames }`
  - ลำดับ: `not_available` ก่อน → `included` → `only_with` (ไม่มีชุดรองรับในตะกร้า = `needs_package` พร้อมชื่อชุดที่รองรับ)
- `dropUnsupported(cart, rules)` คืนตะกร้าที่เอาสินค้าเฉพาะชุดที่ไม่มีชุดรองรับออก + รายชื่อที่เอาออก

### หน้าร้านลิงก์เลือกบริการ (ลูกค้า)

- สินค้า `needs_package` ไม่แสดงในรายการ (ไม่ทำให้หน้าร้านรก)
- เลือกชุดที่รองรับแล้ว สินค้าปรากฏ
  - การ์ดมีข้อความเล็ก "ขายคู่กับ {ชื่อชุด}"
  - ขึ้นข้อความครั้งเดียวว่า "มีงานเพิ่มสำหรับ {ชื่อชุด} ให้เลือก"
- เอาชุดออก: เอาสินค้าที่ไม่มีชุดรองรับออกจากตะกร้า แล้วขึ้นข้อความว่า "เอา X ออกแล้ว เพราะขายคู่กับ {ชุด}" (ทางเดียวกับข้อความกติกาเดิม)
- ลิงก์ที่ทีมล็อกรายการไว้ให้: รายการที่ล็อกไม่ติดกติกานี้ (ทีมเลือกเอง)
  - แต่ถ้าล็อกชุดไว้ สินค้าเฉพาะชุดของชุดนั้นแสดงให้ลูกค้าเลือกเพิ่มได้ (เมื่อเปิดให้เลือกเพิ่ม)

### ตัวคิดราคา (ทีม · ทั้งลูกค้าตรงและ Fastwork)

- สินค้า `needs_package` แสดงสีเทา ปุ่มเพิ่มกดไม่ได้ พร้อมเหตุผล "เลือกชุด {ชื่อชุด} ก่อน"
- เอาชุดออก: เอาสินค้าออกและแจ้งแบบเดียวกับหน้าร้าน

### backend

- ส่งคำขอจากหน้าร้าน: สินค้าเฉพาะชุดที่ไม่มีชุดรองรับในคำขอ (นับรวมชุดที่ล็อกไว้) = 400 พร้อมบอกชื่อชุด · ใช้ฟังก์ชันกลาง
- ออกใบเสนอราคาจากตะกร้า (ตัวคิดราคา): ตรวจแบบเดียวกัน
- ใบเสนอราคาที่ทีมเขียนเอง และงวดที่เพิ่มในงาน Fastwork: ไม่บังคับ (ทีมตัดสินเอง)
- แค็ตตาล็อกที่ส่งให้หน้าร้าน/ตัวคิดราคา: แต่ละสินค้ามี `only_with_package_ids` (เฉพาะชุดที่เปิดอยู่)

### เทสต์

- บันทึกสินค้า only_with ไม่ลบกติกาของชุด และกลับกัน
- ชนกับกติกาเดิม = 400
- ส่งคำขอที่มีสินค้าเฉพาะชุดโดยไม่มีชุด = 400 · มีชุด = ผ่าน · ชุดที่ล็อกไว้นับ
- ออกใบจากตะกร้าตรวจเหมือนกัน
- ชุดปิดใช้งาน = สินค้าไม่อยู่ในแค็ตตาล็อกของลูกค้า
- ฟังก์ชันกลาง: ลำดับกติกา · หลายชุด · เอาชุดออกแล้วสินค้าหลุด

## ลำดับทำ

1. schema + ฟังก์ชันกลาง + เทสต์ของฟังก์ชัน
2. backend: บันทึกสินค้า/ชุด แยกแถว · แค็ตตาล็อก · ตรวจตอนส่งคำขอและออกใบจากตะกร้า · เทสต์ API
3. ฟอร์มสินค้า + ป้ายในรายการ + ส่วนอ่านอย่างเดียวในฟอร์มชุด
4. หน้าร้าน + ตัวคิดราคา (ใช้ฟังก์ชันกลาง)
5. mock data มีสินค้าเฉพาะชุดอย่างน้อย 1 ตัว · mock:verify · ถ่ายจอ 360px · เทสต์เต็มชุด
