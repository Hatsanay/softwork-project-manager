# แผน: onboarding ตอนเข้าระบบครั้งแรก (7 ต.ค. 2026)

สถานะ: **ทำเสร็จและทดสอบบนเครื่องแล้ว ยังไม่ได้ deploy**

## โจทย์ (จากผู้ใช้)
ผู้ใช้ที่แอดมินสร้างให้ เข้าระบบครั้งแรกต้อง:
1. ตั้งรหัสผ่านใหม่ (มีอยู่แล้ว)
2. ถ้าแอดมินไม่ได้ใส่อีเมลไว้ → กรอกอีเมล → ระบบส่ง OTP ไปยืนยัน (แบบระบบ fasttiw)
3. กด "ถัดไป" → อัปโหลดรูปโปรไฟล์

## การตัดสินใจ
- **อีเมลไม่บังคับตอนสร้างผู้ใช้** (เหมือน fasttiw ที่แอดมินสร้างลูกค้าได้โดยไม่ต้องกรอกข้อมูล) → ต้องมีอย่างอื่นไว้ login
  จึงเพิ่ม **ชื่อผู้ใช้ (`user_username`)** — แอดมินกำหนดเองได้ เว้นว่าง = ใช้รหัสผู้ใช้ (`user_id`) ไปก่อน แก้ทีหลังได้
- login ได้ทั้ง **อีเมลหรือชื่อผู้ใช้** (ชื่อผู้ใช้ห้ามมี `@` ทั้งสองแบบจึงไม่มีทางชนกัน)
- ผู้ใช้เดิมทุกคนได้ชื่อผู้ใช้ = `user_id` อัตโนมัติ (ยัง login ด้วยอีเมลได้เหมือนเดิม) และ admin ตั้งต้นได้ `admin`
- OTP: ยกกติกามาจาก fasttiw `emailOtp.js` — 6 หลัก, อายุ 10 นาที, กรอกผิดได้ 5 ครั้ง, ขอได้ 5 ครั้ง/ชม./อีเมล, ใช้ได้ครั้งเดียว, เก็บเป็นแฮช
  + จำกัดขอรหัส 10 ครั้ง/ชม./ผู้ใช้ (กันคนที่ login อยู่ใช้ระบบเราสแปมอีเมลคนอื่น)
- อีเมลที่มีผู้ใช้อื่นใช้อยู่แล้ว ขอรหัสไม่ได้ (409)
- ด่าน onboarding = `user_must_change_password` **หรือ** ยังไม่มีอีเมล → ออกกลางทางแล้วกลับมา ยังต้องทำขั้นที่ค้างให้ครบ
- รูปโปรไฟล์: ขั้นสุดท้าย **ข้ามได้** (ไม่บังคับ เหมือนหน้า /welcome ของ fasttiw)
- เครื่อง dev ที่ไม่ได้ตั้ง SMTP: ตั้ง `OTP_DEV_LOG=true` ใน `backend/.env` แล้วรหัสจะพิมพ์ใน log ของ backend แทน (production ไม่ตั้ง = ตอบ 503 บอกให้ตั้ง SMTP)

## งาน
- [x] DB: `tb_users.user_username` (NOT NULL UNIQUE), `user_email` เป็น NULL ได้, ตารางใหม่ `tb_email_otps` → `deploy_schema.sql` + `create_*.sql`
- [x] backend: login ด้วยอีเมล/ชื่อผู้ใช้, สร้าง/แก้ผู้ใช้ (อีเมลไม่บังคับ + ชื่อผู้ใช้), `POST /users/me/email/otp`, `POST /users/me/email/verify`, ข้ามการส่งอีเมลแจ้งเตือนถ้าไม่มีอีเมล
- [x] frontend: หน้า login, หน้า onboarding 3 ขั้น, หน้าสร้าง/แก้ไข/ดู/รายการผู้ใช้, หน้าโปรไฟล์
- [x] ทดสอบ: deploy_schema ใน DB ชั่วคราว, API flow ครบ (สร้าง → login → ตั้งรหัส → OTP → รูป), กรณีผิดพลาด

## ผลการทดสอบ (บนเครื่อง)
- deploy_schema.sql: 11/11 ใน DB ชั่วคราว รวมกรณี DB เก่าที่ไม่มี `user_username` และอีเมลยังเป็น NOT NULL (ผู้ใช้เดิมได้ชื่อผู้ใช้ = user_id) + รันบน DB เครื่อง dev แล้ว ผู้ใช้ 4 คนอยู่ครบ
- API 24/24: สร้างผู้ใช้ไม่มีอีเมล, ชื่อผู้ใช้ซ้ำ/ผิดรูปแบบ, login ด้วยชื่อผู้ใช้/อีเมล, OTP (อีเมลซ้ำ, รหัสผิดนับครั้งที่เหลือ, ใช้ซ้ำไม่ได้, คนอื่นเอารหัสเราไปใช้ไม่ได้, จำกัด 10 ครั้ง/ชม.), อัปโหลดรูป, แก้ไขโดยแอดมิน
- หน้าเว็บจริง: ขั้นตั้งรหัส → ออกแล้วกลับมาเจอขั้นอีเมลต่อ → ยืนยันแล้วเข้าระบบได้ปกติ
- **ยังไม่ได้คลิกทดสอบในเบราว์เซอร์** และยังไม่ได้ลองส่ง OTP ผ่าน SMTP จริง

## แก้ช่องโหว่ที่เจอระหว่างทำ
- `GET /users/me` เคยรับ `?user_id=` จาก query → ดูข้อมูลส่วนตัวของคนอื่นได้ ตอนนี้ใช้ user_id จาก token เท่านั้น
- `PUT /users/me` เคยเปลี่ยนอีเมลได้โดยไม่ยืนยัน → ตอนนี้เปลี่ยนอีเมลได้ทางเดียวคือ OTP (หน้าโปรไฟล์มีปุ่ม "เปลี่ยน/เพิ่ม")

## Deploy
- รัน `database/query/deploy_schema.sql` ก่อน restart backend (มีคอลัมน์/ตารางใหม่)
- production ต้องตั้ง SMTP ไว้ ไม่งั้นผู้ใช้ที่ไม่มีอีเมลจะติดที่ขั้นยืนยันอีเมล (ระบบตอบ 503 บอกให้ติดต่อผู้ดูแล) — **ห้ามตั้ง `OTP_DEV_LOG` บน production**
