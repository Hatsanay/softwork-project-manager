# แบบระบบ: รหัสแผนกผูกสาขา + รหัสพนักงานออกอัตโนมัติ + ย้ายแผนก/สาขา + บัตรพนักงาน — 18 ต.ค. 2026

สถานะ: **เขียนโค้ดเสร็จ (18 ต.ค. 2026)** · ผู้ใช้ตอบ C1-ก · C2-ก · C3-ก · T1-ก · T2-ก · T3-ก · T4-ก (CR80 ทีละใบ) · backend + deploy_schema + หน้าเว็บ (แผนก · ฟอร์ม/หน้าพนักงาน · ย้ายแผนก · บัตร · คิวบัตร · หน้าพิมพ์ CR80) · เพิ่มเติมตอนเขียน: อัปโหลดรูปแล้วบัตรที่ยังไม่พิมพ์เปลี่ยนรูปตาม · ไม่มีรูปใช้รูปโปรไฟล์บัญชีผู้ใช้ (snapshot ตอนออกบัตร) · คิวรอพิมพ์ไม่รวมคนพ้นสภาพ
ที่มา: ผู้ใช้สั่งให้รหัสแผนกบอกสาขาได้ และรหัสพนักงานบอก วันเริ่มงาน (yymmdd) สาขา แผนก เลขรัน · ระบบออกรหัสให้เอง · id ทุกตัว varchar(18)

ผู้ใช้ตอบแล้ว (18 ต.ค. 2026):
- ลำดับ: **สาขา แผนก วันที่ ลำดับ** · ไม่มีขีด · เลขรันเติมจนครบ 18 ตัว
- ~~ย้ายแผนก/สาขาแล้วรหัสคงเดิมตลอด~~ → **เปลี่ยนแล้ว: ย้ายแผนกหรือสาขา = ออกรหัสใหม่ + ออกบัตรใหม่** (ผู้ใช้สั่ง 18 ต.ค. 2026 — ข้อ 3.3)
- กรอกผิด: **ออกรหัสใหม่ได้จนกว่าพนักงานจะเข้ารอบเงินเดือนแรก** แล้วล็อก
- ข้อมูลเดิม: **ออกรหัสใหม่ให้ทั้งหมด**

## 1. หลักการ

| เรื่อง | ตัดสิน | เหตุผล |
|---|---|---|
| คีย์หลัก (`emp_id`, `dep_id`, `branch_id`) | **ไม่เปลี่ยน** — ยังเป็น `PREFIX + yyyymmdd + 7 หลัก` (18 ตัว) แบบทุกตาราง | ถูกอ้างจากเงินเดือน ลงเวลา การลา เอกสาร log ทั่วระบบ · คีย์ต้องไม่มีวันเปลี่ยน — ถ้าใส่สาขา/แผนกในคีย์ ย้ายแผนกแล้วคีย์ผิดความหมาย |
| "รหัส" ที่คนเห็น | `dep_code` (ใหม่) และ `emp_code` (เดิม แต่ระบบออกให้) | อ่านแล้วรู้สาขา/แผนก · ใช้ค้นหา เรียง พิมพ์บนเอกสาร |
| รหัสสาขา | ใช้ `branch_code` 5 หลักเดิม (เลขสาขาตามกรมสรรพากร 00000 = สำนักงานใหญ่) | เลขเดียวกับใบกำกับภาษี ไม่ต้องจำรหัสชุดที่สอง · แก้ไม่ได้หลังสร้างอยู่แล้ว (`branchUpdateSchema`) → รหัสแผนก/พนักงานที่ประกอบจากมันไม่มีวันผิด |
| แผนก | **ผูกกับสาขาเดียว** — IT สำนักงานใหญ่ กับ IT เชียงใหม่ = คนละแผนก | ตามที่สั่ง "รหัสแผนกให้รู้สาขาได้" |

## 2. รูปแบบรหัส

```
รหัสแผนก     00000ACC              8 ตัว  = รหัสสาขา 5 หลัก + ตัวย่อแผนก 3 ตัว
รหัสพนักงาน  00000ACC2610180001    18 ตัว = รหัสแผนก 8 + วันเริ่มงาน yymmdd 6 + ลำดับ 4
             └─สาขา┘└แผนก┘└วันที่┘└ลำดับ┘
```

- **ตัวย่อแผนก** ยาว 3 ตัวพอดี `A-Z` `0-9` (เช่น ACC, ITD, HRM, SAL) — ยาวคงที่ รหัสพนักงานจึงยาว 18 ตัวเสมอ อ่านแยกส่วนตามตำแหน่งได้ · ห้ามซ้ำในสาขาเดียวกัน (รหัสแผนกไม่ซ้ำทั้งบริษัท)
- **วันที่** = วันเริ่มงาน (`emp_hire_date`) ปี ค.ศ. 2 หลัก (ตรงกับเลขเอกสาร IV-20261018) — ระบบไม่ได้เก็บวันสมัคร
- **ลำดับ** 4 หลัก เริ่มใหม่ทุกวันเริ่มงาน **นับรวมทั้งบริษัท** (รับคนเข้าวันเดียวกันได้ 9,999 คน) → รหัสไม่ซ้ำแน่นอนแม้สาขา/แผนกเดียวกัน · ออกเลขด้วย `tb_document_sequences` (`ds_doc_type = 'EMP'`, `ds_date` = วันเริ่มงาน) มีล็อกกันเลขซ้ำแบบเลขเอกสาร
- ตรวจรูปแบบ: แผนก `^\d{5}[A-Z0-9]{3}$` · พนักงาน `^\d{5}[A-Z0-9]{3}\d{10}$`

## 3. กติกา

### 3.1 แผนก
- สร้าง: เลือกสาขา (บังคับ) + ชื่อ + ตัวย่อ 3 ตัว → `dep_code` = รหัสสาขา + ตัวย่อ (ระบบคิด เก็บไว้ค้นหา/เรียง)
- แก้ตัวย่อ/สาขาของแผนกได้ **เฉพาะเมื่อแผนกยังไม่มีพนักงาน** — มีพนักงานแล้วต้องสร้างแผนกใหม่แล้วย้ายพนักงาน (ข้อ 3.3) เพื่อให้รหัสเปลี่ยนพร้อมบัตรใหม่ตามขั้นตอน
- แผนกที่มีพนักงาน/role อ้างอยู่ลบไม่ได้ (ปิดใช้งานแทน — ของเดิม)

### 3.2 พนักงาน
- **แผนกบังคับเลือก** (ต้องมีเพื่อประกอบรหัส) · สาขาของพนักงาน = สาขาของแผนก (ช่องสาขาในฟอร์มเปลี่ยนเป็นแสดงอย่างเดียว)
- ช่อง "รหัสพนักงาน" เลิกให้กรอก — แสดง "ระบบออกให้เมื่อบันทึก" + ตัวอย่างส่วนหน้า `00000ACC261018····`
- รหัสออกตอนบันทึกครั้งแรก
- **ก่อนเข้ารอบเงินเดือนแรก** (ยังไม่มีในรอบเงินเดือนใดที่ไม่ยกเลิก): แก้วันเริ่มงานหรือแผนก → ออกรหัสใหม่ (เลขเดิมทิ้ง ไม่นำกลับมาใช้) · หน้าจอบอกล่วงหน้า "บันทึกแล้วรหัสจะเปลี่ยนจาก … เป็น …"
- **หลังเข้ารอบเงินเดือนแรก**: วันเริ่มงานแก้ไม่ได้ · ช่องแผนกในฟอร์มแก้ไม่ได้ — เปลี่ยนแผนก/สาขาต้องใช้ปุ่ม **"ย้ายแผนก / สาขา"** (ข้อ 3.3)
- สลิปที่ออกไปแล้วเก็บรหัสและชื่อแผนก ณ ตอนนั้นไว้ (`pri_emp_code`, `pri_department_name`) — ไม่เปลี่ยนตาม
- ทุกครั้งที่รหัสเปลี่ยน (แก้ข้อมูล / ย้าย) รหัสเดิมเข้าประวัติรหัส บัตรเดิมถูกยกเลิก และออกบัตรใหม่ (ข้อ 3.4)

### 3.3 ย้ายแผนก / สาขา (ผู้ใช้สั่ง 18 ต.ค. 2026: ต้องออกรหัสใหม่ ออกบัตรใหม่)
- ปุ่ม "ย้ายแผนก / สาขา" ในหน้าพนักงาน (สิทธิ์ `manageEmployees`) → เลือกแผนกใหม่ (แผนกไหนก็ได้ทุกสาขา — สาขาตามแผนก) · วันที่มีผล (ดู T2) · เหตุผล
- บันทึกใน transaction เดียว (ล็อกแถวพนักงาน):
  1. รหัสใหม่ = **รหัสแผนกใหม่ + วันที่ (ดู T1) + ลำดับถัดไปของวันนั้น**
  2. ปิดรหัสเดิมในประวัติ (ใช้ได้ถึงวันก่อนวันที่มีผล) และเปิดรหัสใหม่ · บันทึกเหตุผลและผู้ทำ
  3. แผนก/สาขาของพนักงานเปลี่ยน
  4. บัตรเดิมยกเลิก (เหตุผล "ย้ายแผนก/สาขา") · ออกบัตรใบใหม่สถานะ "รอพิมพ์"
- ย้ายไปแผนกเดิมไม่ได้ · พนักงานที่พ้นสภาพแล้วย้ายไม่ได้
- **ค้นหาด้วยรหัสเก่ายังเจอ** (ค้นจากประวัติรหัส) · หน้าพนักงานแสดงประวัติรหัสและแผนกทั้งหมด (รหัส แผนก สาขา ช่วงวันที่ เหตุผล)
- เงินเดือน: รอบที่คำนวณหลังย้ายใช้รหัส/แผนกใหม่ (สลิปเก็บ snapshot ตอนคำนวณ) · ลงเวลา/การลา/บัญชีผู้ใช้ ผูกกับ `emp_id` ไม่กระทบ
- ข้อความกำกับก่อนบันทึก: "ย้ายแล้ว รหัสจะเปลี่ยนจาก 00000ACC2610180001 เป็น 00001ITD2610180003 · บัตรใบเดิมใช้ไม่ได้ ต้องพิมพ์บัตรใหม่และเก็บบัตรเก่าคืน"

### 3.4 บัตรพนักงาน
- พนักงานมี **บัตรที่ใช้ได้ใบเดียว** ตลอดเวลา · ออกบัตรเมื่อ: สร้างพนักงาน (ใบที่ 1) · รหัสเปลี่ยน (แก้ข้อมูล/ย้าย) · บัตรหาย · ชำรุด · เปลี่ยนชื่อ/ตำแหน่ง/รูป (กดออกเอง)
- ออกบัตรใหม่ = ยกเลิกบัตรเดิมอัตโนมัติ (บันทึกเหตุผล) · ช่อง "เก็บบัตรเก่าคืนแล้ว" ติ๊กได้ภายหลัง (รายการ "บัตรที่ยังไม่ได้คืน" ให้ฝ่ายบุคคลตามเก็บ)
- พ้นสภาพพนักงาน = บัตรที่ใช้ได้ถูกยกเลิก + เข้ารายการต้องเก็บคืน
- ข้อมูลบนบัตรเก็บ snapshot ตอนออก (รหัส ชื่อ ตำแหน่ง แผนก สาขา รูป) — พิมพ์ซ้ำได้ตัวเดิมเสมอ · บัตรที่ยกเลิกพิมพ์ได้แต่มีตราประทับ "ยกเลิก"
- **หน้าพิมพ์บัตร** ขนาดบัตรมาตรฐาน CR80 (85.6 × 54 มม.) หน้า-หลัง พิมพ์ทีละใบ (T4-ก — ไม่ทำแบบหลายใบบน A4):
  - หน้า: โลโก้ + ชื่อบริษัท · รูป · ชื่อ-สกุล ไทย/อังกฤษ · ตำแหน่ง · แผนก · สาขา · **รหัสพนักงาน** ตัวใหญ่ + QR ของรหัส
  - หลัง: "หากพบบัตรนี้โปรดส่งคืน" + ที่อยู่/เบอร์บริษัท · บัตรใบที่ N · วันที่ออก
  - QR มีแค่รหัสพนักงาน (ไม่ใส่เลขบัตรประชาชน/ข้อมูลส่วนตัว)
- **วันหมดอายุบัตร** (ผู้ใช้เลือก 18 ต.ค. 2026: 3 ปี ตั้งค่าได้ · พิมพ์ด้านหน้าใต้รหัส):
  - `ec_expires_on` = วันออก (เวลาไทย) + `ps_card_valid_years` (ตั้งค่าบุคคล 1–10 ปี เริ่ม 3) ณ ตอนออก · เปลี่ยนตั้งค่าแล้วบัตรเดิมคงวันเดิม
  - หมดแล้วหรือเหลือไม่เกิน 30 วัน → แท็บ "บัตรใกล้หมดอายุ" (เฉพาะคนที่ยังทำงาน) · ปุ่ม "ต่ออายุบัตร" = ออกใบใหม่รหัสเดิม เหตุผล `expired` ใบเดิมยกเลิก ("บัตรหมดอายุ") ต้องเก็บคืน
  - บัตรที่ออกก่อนมีวันหมดอายุ: deploy เติม = วันออก + อายุตามตั้งค่า
  - ไม่ตัดวันหมดอายุตามวันพ้นสภาพ (ตั้งพ้นสภาพแล้วยกเลิกได้) · พ้นสภาพแล้วใช้ขั้นตอนเก็บบัตรคืนเดิม

### ย้ายข้อมูลเดิม (deploy_schema.sql — รันซ้ำได้)
1. เพิ่มคอลัมน์แบบให้ว่างได้ก่อน
2. แผนกที่ยังไม่มีสาขา → สำนักงานใหญ่ (`branch_code = '00000'`) · ตัวย่อยังว่าง → `D01`, `D02` … ตามลำดับวันที่สร้าง (ผู้ดูแลเปลี่ยนเป็นตัวย่อจริงได้ — ข้อ 3.1)
3. พนักงานที่ไม่มีแผนก → แผนก **"ทั่วไป" (GEN)** ที่สำนักงานใหญ่ (สร้างให้เฉพาะเมื่อมีพนักงานแบบนี้) — ดู C2
4. ออกรหัสพนักงานใหม่ทุกคนที่รหัสยังไม่ใช่รูปแบบใหม่ (ลำดับตามวันเริ่มงาน แล้วตามวันที่สร้าง) + ตั้ง `tb_document_sequences` ให้ต่อจากเลขที่ใช้ไป · รหัสเดิม (DEMO-001 ฯลฯ) เข้า `tb_employee_codes` (เหตุผล migration) ค้นด้วยรหัสเดิมยังเจอ
4.1 พนักงานที่ยังไม่พ้นสภาพ: สร้างบัตรใบที่ 1 สถานะ "รอพิมพ์"
5. ค่อยบังคับ NOT NULL / UNIQUE · ส่วนที่ 6 ตรวจโครงสร้าง

## 5. หน้าจอ
- **ตั้งค่า › จัดการแผนก**: คอลัมน์รหัส + สาขา · ฟอร์มมีเลือกสาขา + ตัวย่อ (ตัวพิมพ์ใหญ่อัตโนมัติ) + ตัวอย่างรหัสสด
- **บุคคล › พนักงาน**: รายการแสดงรหัสใหม่ เรียงตามรหัส = จัดกลุ่มตามสาขา/แผนกเอง · ฟอร์มตามข้อ 3.2 (+ อัปโหลดรูป) · แท็บ "บัตรรอพิมพ์" และ "บัตรที่ยังไม่ได้คืน"
- **หน้าพนักงาน**: ปุ่ม "ย้ายแผนก / สาขา" (แผ่นฟอร์ม + ตัวอย่างรหัสใหม่สด) · การ์ด "บัตรพนักงาน" (ใบที่ใช้อยู่ · พิมพ์ · ออกบัตรใหม่พร้อมเหตุผล · ติ๊กคืนบัตรเก่า) · การ์ด "ประวัติรหัสและแผนก"
- ข้อความกำกับทุกจุด (ไม่ใช้ tooltip) เช่น ใต้รหัสพนักงาน: "สาขา 00000 · แผนก ACC · เริ่มงาน 18 ต.ค. 2026 · คนที่ 1 ของวันนั้น · ย้ายแผนก/สาขาแล้วรหัสเปลี่ยนและต้องออกบัตรใหม่"

## 7. เทสต์
- `employee-codes.test.js`: รูปแบบ 18 ตัว · ลำดับเริ่มใหม่ต่อวัน · สร้างพร้อมกัน 5 คน ไม่ซ้ำ · แก้วันเริ่มงาน/แผนกก่อนรอบเงินเดือน = รหัสใหม่ · หลังเข้ารอบ แก้ในฟอร์มไม่ได้
- `employee-transfer.test.js`: ย้าย = รหัสใหม่ + ประวัติ + บัตรเดิมยกเลิก + บัตรใหม่รอพิมพ์ · กดย้ายซ้ำ = 409 · ค้นด้วยรหัสเก่าเจอ · รอบเงินเดือนหลังย้ายใช้รหัสใหม่ สลิปเก่ารหัสเดิม
- `employee-cards.test.js`: บัตรใช้ได้ใบเดียวเสมอ · ออกใหม่เพราะหาย = รหัสเดิม ใบที่ N+1 · พ้นสภาพ = บัตรยกเลิก + รอคืน
- `api-departments`: ต้องมีสาขา + ตัวย่อ · ตัวย่อซ้ำในสาขา = 409 · แก้ตัวย่อแล้วรหัสพนักงานที่ยังไม่ล็อกเปลี่ยนตาม
- deploy: ฐานเก่า (แผนกไม่มีสาขา, พนักงาน DEMO-001) → รันแล้วได้รหัสใหม่ครบ · รันซ้ำไม่เปลี่ยนอะไร
- รัน 2 เขตเวลา · ภาพหน้าจอ จอคอม + 360/400px
