# สร้างงาน/งานย่อยอัตโนมัติจากสินค้าที่เลือกตอนสร้างโปรเจกต์

สถานะ: **ทำเสร็จ 31 ต.ค. 2026** (ตอบ Q1 Q2 ข้อ ก) · บันทึกผลที่ข้อ 7

ที่มา: ผู้ใช้ "อยากให้สร้าง task และ subtask อัตโนมัติเมื่อสร้างโปรเจค หากได้เลือกรายการสินค้าหรือชุดรายการสินค้าไว้แล้ว" (31 ต.ค. 2026)

## 1. ตอนนี้

| ทางสร้างโปรเจกต์ | เลือกสินค้าได้ไหม | สร้างงานให้ไหม |
|---|---|---|
| ลูกค้าตอบรับใบเสนอราคา (ทีมกด / ลูกค้ากดในลิงก์) | ได้ (รายการในใบ) | ✓ (ติ๊กได้) |
| ยืนยันคำขอบริการจากลิงก์ | ได้ (ลูกค้าเลือก) | ✓ |
| รับงาน Fastwork จากคำขอ | ได้ | ✓ |
| เพิ่มเป็นงวดของงานเดิม (ตัวคิดราคา) | ได้ (ตะกร้า) | ✓ (สวิตช์) |
| **สร้างงาน Fastwork จากตะกร้าในตัวคิดราคา** | ได้ (ตะกร้า) | **✗ ส่งไปแค่ชื่อกับราคา ตะกร้าหาย** |
| **รับงาน Fastwork ใหม่ (พิมพ์เอง)** | ไม่มีช่องให้เลือก | ✗ |
| **สร้างโปรเจกต์ (`/projects/create`)** | ไม่มีช่องให้เลือก | ✗ |

## 2. ที่จะทำ

1. **ตัวเลือกสินค้า/ชุดรายการ** (component ใหม่ใช้ร่วม `components/catalog-task-picker.tsx`)
   - ค้นหาและเลือกได้ทั้งสินค้าและชุดรายการที่เปิดใช้งาน (โหลดจาก `/V1/products` + `/V1/product-packages` ที่มีอยู่) · ใส่จำนวนได้
   - ใต้ตัวเลือกแสดง **"งานที่จะสร้าง (N งาน)"** เป็นต้นไม้ให้เห็นก่อนกด: ชุดรายการ = งานหลัก · รายการในชุด = งานย่อย · สินค้าเดี่ยว = งานหลัก
   - ลบแต่ละตัวที่เลือกได้ · สวิตช์ "สร้างงานจากรายการที่เลือก" (เปิดเป็นค่าเริ่ม)
   - มือถือ: แถวเต็มความกว้าง ปุ่มลบ ≥ 44px · ต้นไม้ย่อหน้าแค่ระดับเดียว
2. **หน้าสร้างโปรเจกต์**: กล่องใหม่ "สร้างงานจากสินค้า (ไม่บังคับ)" + คำอธิบาย "เลือกแล้วระบบสร้างงานและงานย่อยให้ตอนบันทึก · แก้/ลบ/มอบหมายต่อได้ในหน้าโปรเจกต์"
3. **หน้ารับงาน Fastwork ใหม่**: กล่องเดียวกัน · ซ่อนเมื่อรับจากคำขอ (คำขอสร้างงานให้อยู่แล้ว กันงานซ้ำ)
4. **ตัวคิดราคา → สร้างงาน Fastwork จากตะกร้านี้**: ส่งตะกร้าไปทาง URL (`cart=p:ID.2,k:ID.1`) หน้ารับงานเลือกไว้ให้ครบ (ข้อ prefill)
5. **backend**: `POST /V1/projects` และ `POST /V1/fastwork/projects` รับ `tasks` (รูปแบบเดียวกับ "เพิ่มเป็นงวดของงานเดิม" `addedTaskSchema` ย้ายไปไว้ schema กลาง) → `insertTasksFromRows` ในธุรกรรมเดียวกับการสร้างโปรเจกต์ (สร้างงานไม่สำเร็จ = ไม่มีโปรเจกต์ค้างครึ่งทาง) · หมายเหตุในงาน "จากสินค้าที่เลือกตอนสร้างโปรเจกต์" · ผลคืน `task_count` → toast "สร้างโปรเจกต์แล้ว · เพิ่ม N งาน"
6. **ฟังก์ชันแปลงรายการเป็นงาน** ย้ายไปไว้ที่เดียว (`lib/catalog-tasks.ts`) ใช้ทั้งตัวเลือกใหม่ ตัวคิดราคา และเพิ่มเป็นงวดของงานเดิม

## 3. กติกาแปลงเป็นงาน

- ชุดรายการ → งานหลัก "ชื่อชุด" (จำนวน > 1 = "ชื่อชุด × 2" ไม่สร้างงานย่อยซ้ำ 2 ชุด) · รายการในชุด → งานย่อย "ชื่อ × จำนวน หน่วย" (จำนวน 1 = ชื่ออย่างเดียว)
- สินค้าเดี่ยว → งานหลัก (จำนวน > 1 = "ชื่อ × 3")
- **สินค้าแบบ % (เช่น งานด่วน +30%) ไม่สร้างงาน**: เป็นค่าบริการเพิ่ม ไม่ใช่ชิ้นงาน (แก้ในตัวคิดราคาเดิมด้วย ตอนนี้ยังสร้างเป็นงาน)
- ลำดับ: สินค้าเดี่ยวก่อน แล้วชุดรายการ (กติกาเดิมของ `insertTasksFromRows`: รายการที่ตามหลังหัวข้อเป็นงานย่อยของหัวข้อนั้น)
- เลือกชุดเดียวกันซ้ำ = รวมเป็นแถวเดียวเพิ่มจำนวน
- ชื่องานยาวเกิน 200 ตัว: ตัดตาม `taskTitleFrom` เดิม ข้อความเต็มอยู่ในรายละเอียดงาน

## 4. จุดที่ต้องระวัง

- **ไม่สร้างซ้ำ:** รับงานจากคำขอ = ไม่ส่ง tasks (backend ปฏิเสธถ้ามีทั้ง `service_request_id` และ `tasks` ไม่ว่าง · 400 พร้อมเหตุผล)
- **กดบันทึกสองครั้ง:** ปุ่มปิดระหว่างบันทึก (มีอยู่แล้ว) · ทั้งหมดอยู่ในธุรกรรมเดียว
- **สินค้า/ชุดถูกปิดใช้งานระหว่างเลือก:** ไม่กระทบ เพราะส่งเป็นข้อความงาน ไม่ผูกราคา
- **URL จากตัวคิดราคายาว:** ส่งแค่ id + จำนวน (ไม่ส่งชื่อ) · id ที่ไม่พบในแค็ตตาล็อกถูกข้ามพร้อมแจ้ง "บางรายการปิดใช้งานแล้ว"
- **สิทธิ์:** ใช้สิทธิ์สร้างโปรเจกต์/จัดการ Fastwork เดิม · การอ่านแค็ตตาล็อกใช้เส้นที่มีอยู่ (`requireAuth`) ไม่เห็นต้นทุน
- **ข้อความ:** ไม่มี em dash · ไม่มี tooltip
- **ไม่แก้ schema ฐานข้อมูล**

## 5. ลำดับงาน

1. ย้าย schema + ฟังก์ชันแปลง · backend 2 เส้นรับ `tasks` + เทสต์ (สร้างงาน/งานย่อยถูกลำดับ · ไม่ส่ง = ไม่มีงาน · คำขอ + tasks = 400 · ธุรกรรมย้อนเมื่อพลาด)
2. ตัวเลือกสินค้า + หน้าสร้างโปรเจกต์
3. หน้ารับงาน Fastwork + ส่งตะกร้าจากตัวคิดราคา
4. type check · lint · ภาพหน้าจอ 360/400px · อัปเดตไฟล์นี้

## 6. คำถาม (ตอบแล้ว 31 ต.ค. 2026: ข้อ ก ทั้งสองข้อ)

- **Q1 แก้งานก่อนสร้าง:** ก) ดูต้นไม้ได้อย่างเดียว ลบ/แก้ทีหลังในหน้าโปรเจกต์ (แนะนำ · หน้าสร้างไม่รก) · ข) ติ๊กออก/แก้ชื่องานย่อยทีละแถวได้ก่อนบันทึก
- **Q2 แม่แบบงานต่อสินค้า:** ก) ยังไม่ทำ ใช้ชื่อสินค้า/รายการในชุดเป็นงาน (แนะนำ) · ข) ให้แต่ละสินค้าตั้งงานย่อยแม่แบบได้ (เช่น "เว็บหน้าเดียว" → ออกแบบ · พัฒนา · ทดสอบ · ส่งมอบ) ต้องเพิ่มตาราง

## 7. ผลที่ทำ (31 ต.ค. 2026)

- schema กลาง `shared/schemas/project.mjs` (`catalogTasksField` · `projectCreateTasksSchema`) · Fastwork ใช้ตัวเดียวกัน (สร้างงาน + จ้างเพิ่ม) · `fastworkProjectSchema` ปฏิเสธ `service_request_id` + `tasks` พร้อมกัน (400 ที่ช่อง tasks)
- `POST /V1/projects` สร้างโปรเจกต์ + งานใน `withTransaction` เดียว (เดิมใช้ pool ตรง ไม่เป็นก้อนเดียว) · คืน `task_count`
- `POST /V1/fastwork/projects` รับ `tasks` · คืน `task_count`
- `GET /V1/projects/task-catalog` (createProject หรือ manageFastwork): สินค้าเปิดใช้งานแบบราคาตายตัว + ชุดรายการพร้อมแถวรายการ · ไม่มีราคา · รวมตัวที่ไม่แสดงหน้าร้าน
- **พบระหว่างทำ:** "เพิ่มเป็นงวดของงานเดิม" ไม่คิด % ความคืบหน้าใหม่หลังเพิ่มงาน → คิดหลัง commit แบบเดียวกับตอบรับใบเสนอราคา
- **พบระหว่างทำ:** ตัวคิดราคาเคยสร้างงานจากค่าบริการแบบ % → ข้ามแล้ว · ตะกร้ามีแต่ % = ซ่อนสวิตช์สร้างงาน
- หน้าเว็บ: `lib/catalog-tasks.ts` (แปลง/นับ/ส่งตะกร้าทาง URL) · `components/feature/catalog-task-picker.tsx` · หน้าสร้างโปรเจกต์ · หน้ารับงาน Fastwork (`?cart=` จากตัวคิดราคา · id ที่ปิดใช้งานแล้วข้ามพร้อมบอกจำนวน) · มือถือ: ชื่อบรรทัดบน ปุ่มจำนวนบรรทัดล่าง (360px ไม่บีบชื่อ)
- เทสต์: api-fastwork 2 ข้อใหม่ (ลำดับงานหลัก/ย่อย · คำขอ + งาน = 400 · งานผิด = ไม่มีโปรเจกต์ค้าง · รายการสินค้าตามสิทธิ์ ไม่มีราคา ไม่มี % ไม่มีตัวปิดใช้งาน · % ความคืบหน้าหลังจ้างเพิ่ม)
- ไม่แก้ schema ฐานข้อมูล
