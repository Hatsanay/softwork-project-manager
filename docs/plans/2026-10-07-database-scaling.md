# แผน: ปรับฐานข้อมูลให้รองรับข้อมูลจำนวนมาก (7 ต.ค. 2026)

## วิธีทำ (วัดผลจริง ไม่เดา)
1. สร้างฐานข้อมูลทดสอบชั่วคราว (`tmp_schema_perf`) จาก `deploy_schema.sql` แล้วใส่ข้อมูลจำลองระดับ "ใช้งานหลายปี"
   — ผู้ใช้ 200 คน, โปรเจกต์ 2,000, task+subtask ~200,000, ประวัติกิจกรรม ~600,000, แชท ~350,000, ปัญหา ~30,000
2. รัน backend จริงชี้ไปที่ฐานข้อมูลนั้น (พอร์ตแยก) แล้ววัดเวลาของทุก endpoint หลัก ทั้งมุมแอดมิน (เห็นทุกโปรเจกต์) และพนักงานทั่วไป
3. endpoint ที่ช้า → ดู EXPLAIN หา query ต้นเหตุ → เพิ่ม index / เขียน query ใหม่
4. วัดซ้ำ เทียบก่อน/หลัง และตรวจว่าผลลัพธ์ (ตัวเลขใน dashboard/KPI) ไม่เปลี่ยน
5. index ใหม่ทั้งหมดเข้า `deploy_schema.sql` + `create_*.sql` และทดสอบ deploy_schema ตามกติกาเดิม

### สิ่งที่แก้ (`backend/src/controllers/dashboard.controller.js`)
1. **เวลาเฉลี่ยทำงาน (cycle time)** — เดิม GROUP BY ประวัติกิจกรรมทั้งตารางทุกครั้ง → subquery ต่อ task ผ่าน index `idx_tal_status_start` ที่มีอยู่แล้ว
2. **ปัญหาที่เปิดอยู่ (3 query)** — เดิม full scan ทุกปัญหาในระบบ → สร้าง "ชุดปัญหาที่เป็นไปได้" ของผู้ใช้ก่อน (UNION: งานที่รับผิดชอบ / subtask ใต้งานที่รับผิดชอบ / ถูกแท็ก / สร้างเอง) แล้วกรองด้วยเงื่อนไขเดิม · ~280 → ~37 ms ต่อ query
3. **กิจกรรมล่าสุด** (คนที่เห็นเฉพาะโปรเจกต์ตัวเอง) — เดิมดึงประวัติทั้งหมดของทุกโปรเจกต์มาเรียง → อ่าน index เวลาย้อนจากล่าสุด 90 วัน หยุดเมื่อครบ 10 แถว ถ้าไม่ครบถอยไปใช้ query เดิม · ~235 → ~9 ms

### ยืนยันว่าผลไม่เปลี่ยน
- KPI: เทียบ hash ของ response ก่อน/หลัง ตรงกันทุก endpoint
- ปัญหา + กิจกรรมล่าสุด: รัน SQL เก่ากับใหม่คู่กัน 40 ผู้ใช้ × 4 query — ตรงกันทุกแถว (0 mismatch)
- เทสต์ API เดิม 19/19 และ onboarding 24/24 ผ่านบน DB เครื่อง dev

### ที่ตั้งใจไม่แก้
- **ภาพรวมทีม** (~0.9 วิ ที่ข้อมูลระดับนี้): นับงานทุกชิ้นของโปรเจกต์ที่ยัง active ตามนิยามอยู่แล้ว · จำลองว่าโปรเจกต์ปิดไป 90% (สภาพจริงเมื่อระบบใช้ไปหลายปี) เหลือ 147 ms — MySQL เลือก plan เองได้ดี
- **แชทที่ยังไม่อ่าน / แดชบอร์ดของคนที่รับผิดชอบงานจำนวนมหาศาล**: ช้าตามปริมาณงานของคนนั้นเอง (ไม่ใช่ทั้งบริษัท) — ถ้าวันหนึ่งมีคนแบบนั้นจริงค่อยพิจารณา cache สั้นๆ
- KPI รายคนที่เหลือ ~0.6 วิ: ช้าตามจำนวนงานในเดือนที่เลือก ไม่ใช่ตามประวัติทั้งหมด
