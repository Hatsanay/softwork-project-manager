สถานะ: **P-1 เสร็จ (24 ต.ค. 2026) · P-2 ค่าคอมมิชชั่นเสร็จ (25 ต.ค.) · P-3 เงินทุนเสร็จ (25 ต.ค.) · P-4 ข้อมูลจำลองเสร็จ (25 ต.ค.)** · ผู้ใช้ตอบครบ (Q1-ก Q2-ก Q3-ค Q4-ก Q5-ข Q6-ก + ตัวเลขชัด Q7 ค่าเริ่มต้น 17% แก้ได้) · สั่ง "เริ่มเขียนโค๊ด" 24 ต.ค.

## 1. สภาพตอนนี้ เทียบกับที่ระบบมี

| เรื่อง | สภาพจริงตอนนี้ | ระบบตอนนี้ |
|---|---|---|
| ตัวตน | บุคคลธรรมดา (คุณหัสนัย) ยังไม่จดบริษัท ไม่จด VAT | ตั้งชื่อ/เลขผู้เสียภาษีเป็นบุคคลได้อยู่แล้ว · เอกสารไม่คิด VAT ได้ |
| รายได้หลัก | งาน Fastwork: ลูกค้าจ่ายเข้าแพลตฟอร์ม → Fastwork หักค่าธรรมเนียม → โอนให้เมื่อปิดงาน/งวด | รายได้นับจากใบแจ้งหนี้/ใบเสร็จเท่านั้น · ไม่มีที่บันทึกเงินที่แพลตฟอร์มโอนมา และค่าธรรมเนียม |
| รายได้รอง | ลูกค้าตรง (บางงาน) | ใบเสนอราคา → ใบแจ้งหนี้ → ใบเสร็จ ใช้ได้ครบ |

| ต้นทุนโปรเจกต์ | ค่าใช้จ่ายที่จ่ายจริง + ค่าธรรมเนียมแพลตฟอร์ม | ค่าใช้จ่าย + "ค่าแรงประมาณการ" จากเงินเดือน (ไม่ตรง เพราะทีมไม่ได้รับเงินเดือน) |
| เป้าหมาย | เก็บกำไรสะสมเป็นทุนจดบริษัท | ไม่มี |

หลักของแบบนี้: **รองรับสภาพตอนนี้ก่อน โดยไม่ทำลายส่วนที่เตรียมไว้สำหรับบริษัทที่จดแล้ว** · วันที่จดบริษัทจริง เปิดสวิตช์กลับ ใช้ระบบเต็มได้ทันที ข้อมูลช่วงก่อนจดยังอยู่ครบ

## 2. สวิตช์ "ช่วงก่อนจดบริษัท"

- ตั้งค่าบริษัท: **รูปแบบกิจการ** = บุคคลธรรมดา (ยังไม่จดบริษัท) / นิติบุคคล + วันที่จดบริษัท
- บุคคลธรรมดา:
  - เมนูเงินเดือน/ประกันสังคม/ภ.ง.ด.1 **คงไว้** (Q5-ข: เผื่อบางคนได้เงินเดือนประจำจริง)
  - ต้นทุนโปรเจกต์: ค่าแรงประมาณการนับเฉพาะคนที่มีเงินเดือนในระบบ (เหมือนเดิม) + ค่าคอมมิชชั่นที่ปิดยอดแล้ว · คนที่ได้แต่ส่วนแบ่ง ไม่มีเงินเดือน = ไม่มีค่าแรงประมาณการ ไม่นับซ้ำ
  - หัวเอกสาร (ใบเสนอราคา/ใบแจ้งหนี้/ใบเสร็จ งานลูกค้าตรง) ใช้ชื่อและเลขประจำตัวผู้เสียภาษีของบุคคล ไม่มีคำว่า "บริษัท"
- เตือนเพดาน VAT: บุคคลธรรมดารายได้เกิน 1.8 ล้านบาท/ปี ต้องจด VAT · แสดงรายได้สะสมปีนี้เทียบเพดานในหน้าเงินทุน (คำถามนักบัญชี Z4)

## 3. งาน Fastwork

### 3.1 โปรเจกต์รู้ว่ามาจากไหน
- ช่องทางงาน: **Fastwork** / ลูกค้าตรง (ค่าเริ่มต้นตามที่เลือกล่าสุด) · เลขคำสั่งซื้อ Fastwork · ลิงก์หน้างาน
- ลูกค้า Fastwork: ชื่อที่แสดงบน Fastwork ก็พอ ไม่ต้องมีเลขผู้เสียภาษี/ที่อยู่ (ลูกค้าเดิมเลือกซ้ำได้ เติมให้อัตโนมัติ)
- สร้างโปรเจกต์จากงาน Fastwork ได้โดยไม่ต้องมีใบเสนอราคา: ราคางาน · งวดงาน (Fastwork แบ่งงวดได้) · กำหนดส่ง

### 3.2 เงินที่ Fastwork โอนมา (ตารางใหม่ ไม่ใช้ใบแจ้งหนี้)
หนึ่งแถวต่อการโอนหนึ่งครั้ง:

| ช่อง | ความหมาย |
|---|---|
| โปรเจกต์ · งวด | ผูกงวดงาน (ถ้ามี) |
| ราคางวดตามที่ลูกค้าจ่าย | ยอดเต็มที่ลูกค้าจ่ายเข้า Fastwork |
| ค่าธรรมเนียมแพลตฟอร์ม | คิดให้จากอัตราที่ตั้งไว้ (แก้ได้) · เป็นต้นทุนของโปรเจกต์ |
| หัก ณ ที่จ่าย | ถ้า Fastwork หัก (รอนักบัญชียืนยัน Z2) · เก็บเลข 50 ทวิ ที่ได้รับ |
| ยอดที่เข้าบัญชีจริง | ราคา − ค่าธรรมเนียม − หัก ณ ที่จ่าย (คิดให้ ตรวจกับยอดในสมุดบัญชี) |
| วันที่เงินเข้า · บัญชีที่รับ · เลขอ้างอิง | |
| สถานะ | รอโอน (ลูกค้ายืนยันงานแล้ว) / เข้าแล้ว / ยกเลิก (คืนเงินลูกค้า/ข้อพิพาท) |

- ไม่ใช้ใบแจ้งหนี้/ใบเสร็จ เพราะ Fastwork ออกเอกสารให้ลูกค้าเอง · ใบแจ้งหนี้ของเรามีเลขเอกสาร อนุมัติ และหน้าพิมพ์ที่ไม่ได้ใช้กับงานนี้
- การเงินโปรเจกต์/รายงานขาย/ไฟล์นักบัญชี: รายได้ = งานลูกค้าตรง (ใบแจ้งหนี้) + งาน Fastwork (ราคาเต็ม) · ค่าธรรมเนียมแสดงเป็นต้นทุนบรรทัดแยก · ยอดเดียวต่อความหมาย ไม่ซ้ำ (กติกาเงิน)
- ยกเลิกหลังเงินเข้า (คืนเงินลูกค้า) = บันทึกรายการคืน ไม่ลบของเดิม (เอกสารเงินห้ามแก้ย้อนหลัง)

## 4. ค่าคอมมิชชั่นรายโปรเจกต์

### 4.1 ตั้งการแบ่งต่อโปรเจกต์
- รายชื่อผู้ได้ส่วนแบ่ง: สมาชิกในระบบ (บัญชีผู้ใช้) หรือคนนอก (ผู้ขาย/ฟรีแลนซ์ที่มีในระบบ)
- แต่ละคนเลือกได้ (Q3-ค): **จำนวนเงินตายตัว** หรือ **% ของกำไร** · ส่วนที่ไม่ได้แบ่ง = **เก็บเข้าเงินทุน**
- ลำดับคิด (อ่านจากบนลงล่างในหน้าปิดยอด):
  ```
  กำไรที่แบ่งได้
  − ส่วนแบ่งแบบจำนวนเงินตายตัว (ตามที่ตกลง จ่ายก่อน)
  = กำไรหลังหักส่วนแบ่งตายตัว
  × % ของแต่ละคน (คิดจากยอดนี้)
  ส่วนที่เหลือ = เข้าเงินทุน
  ```
- กำไรไม่พอจ่ายส่วนแบ่งตายตัว: ยังจ่ายตามที่ตกลง ส่วน % ได้ 0 และเงินทุนติดลบ (แสดงเตือนสีแดงก่อนปิดยอด "โปรเจกต์นี้ขาดทุน")
- รวม % ทุกคนเกิน 100% บันทึกไม่ได้
- ค่าเริ่มต้นจากตั้งค่า เช่น เก็บเข้าทุน 30% · ตั้งตอนเปิดโปรเจกต์ แก้ได้จนกว่าจะปิดยอด
- เติมรายชื่อจากสมาชิกโปรเจกต์ให้อัตโนมัติ (ตามกติกาเติมให้ก่อน พิมพ์น้อย)

### 4.2 กำไรที่ใช้แบ่ง (ฐานเงินสด ตามคำตอบ Q2)
```
เงินที่ได้รับจริง (ใบเสร็จงานลูกค้าตรง + เงิน Fastwork ราคาเต็ม)
− ค่าธรรมเนียมแพลตฟอร์ม
− ค่าใช้จ่ายที่ผูกโปรเจกต์ (อนุมัติแล้ว)
= กำไรที่แบ่งได้
```
- ไม่รวม "ค่าแรงประมาณการ" (ทีมได้ส่วนแบ่งแทนเงินเดือน)
- อ่านจากบนลงล่างได้ในหน้าปิดยอด ตัวเลขเดียวต่อความหมาย

### 4.3 ปิดยอดและจ่าย (ตามคำตอบ Q4)
- **ปิดยอด** = คำนวณกำไร × % ของแต่ละคน ณ วันนั้น แล้วล็อก (แก้ไม่ได้ ถ้าผิดทำรายการปรับใหม่)
- เบิกล่วงหน้าได้ระหว่างโปรเจกต์ · ตอนปิดยอดหักที่เบิกไปแล้วให้เอง · ติดลบ = ต้องคืน (แสดงชัด)
- บันทึกจ่ายรายคน: วันที่ · บัญชีที่โอนออก · เลขอ้างอิง · หัก ณ ที่จ่าย (ถ้าต้องหัก ตาม Z1)
- เศษสตางค์จากการแบ่ง → เข้าเงินทุน (ผลรวมทุกคน + ทุน = กำไรพอดีทุกสตางค์ คิดด้วย BigInt)
- ต้นทุนที่มาทีหลังปิดยอด → เตือนในหน้าโปรเจกต์ "มีค่าใช้จ่ายหลังปิดยอด" ให้ทำรายการปรับ

### 4.4 ใครเห็นอะไร
- ผู้มีสิทธิ์จัดการส่วนแบ่ง (สิทธิ์ใหม่): ตั้ง ปิดยอด บันทึกจ่าย เห็นทุกคน
- ผู้ได้ส่วนแบ่ง: หน้า **"ส่วนแบ่งของฉัน"** เห็นเฉพาะของตัวเองทุกโปรเจกต์ แต่ **ที่มาของตัวเลขต้องครบและชัด** (Q6):
  - เงินที่ได้รับจริงของโปรเจกต์ (แยกงวด: วันที่ ราคางาน ค่าธรรมเนียม ยอดเข้า) → ค่าธรรมเนียม → ค่าใช้จ่ายโปรเจกต์ (แยกรายการ: วันที่ ชื่อ ยอด) → กำไรที่แบ่งได้
  - → รวมส่วนแบ่งตายตัวทั้งหมด (ยอดรวม ไม่บอกว่าใครได้เท่าไร) → กำไรหลังหักส่วนตายตัว → × % ของฉัน = ยอดของฉัน
  - → หักที่เบิกล่วงหน้า (วันที่ ยอด) → ยอดที่จะได้/ได้แล้ว (วันที่โอน เลขอ้างอิง) · ปิดยอดแล้วแสดงตัวเลข ณ วันปิดยอด (ไม่เปลี่ยนตามต้นทุนที่มาทีหลัง)
  - ยังไม่ปิดยอด: แสดงเป็น "ประมาณการ ณ วันนี้" พร้อมเหตุผลว่าตัวเลขยังเปลี่ยนได้
- สมาชิกคนอื่นไม่เห็นยอดของกัน (ตามคำตอบ Q6)

## 5. เงินทุนสะสม (เป้าเปิดบริษัท)

- ตั้งเป้า: จำนวนเงินทุนที่อยากมีก่อนจดบริษัท + วันที่ตั้งใจจด (ไม่บังคับ)
- สมุดเงินทุน: เข้าจากส่วนที่เก็บเข้าทุนของแต่ละโปรเจกต์ (อัตโนมัติตอนปิดยอด) · ฝากเพิ่มเอง · ถอนออก (ต้องใส่เหตุผล)
- หน้าเดียวเห็น: ยอดสะสม / เป้า (แถบความคืบหน้า) · เข้ามาจากโปรเจกต์ไหน · รายได้สะสมปีนี้เทียบเพดาน VAT 1.8 ล้าน · ค่าเฉลี่ยต่อเดือน → คาดว่าถึงเป้าเดือนไหน
- เงินทุนเป็นตัวเลขติดตาม ไม่ได้แยกบัญชีธนาคารให้เอง (แนะนำแยกบัญชีจริงด้วย ใส่ไว้ในคำอธิบาย)

## 5.1 เมนู "Fastwork" (หน้าศูนย์รวมขั้นตอน · ผู้ใช้สั่ง 24 ต.ค. 2026)

ผู้ใช้: "สร้างเมนูเพิ่มว่า fastwork ในหน้านั้นจะมีการ์ดที่ลิงก์ไปยังหน้าต่างๆ ที่จำเป็น ที่ต้องทำ เรียงตาม flow ตั้งแต่เริ่มจนถึงจบ"

- เมนูหลักใหม่ **Fastwork** (ไอคอนกระเป๋างาน) · หน้า `/fastwork` · ขึ้นสำหรับผู้มีสิทธิ์อย่างน้อยหนึ่งขั้นในหน้านี้
- การ์ดเรียงตามลำดับงานจริง มีเลขขั้น (เลขมีความหมาย = ลำดับที่ต้องทำ) · แต่ละการ์ด: ชื่อขั้น · บอกสั้นๆ ว่าทำอะไร · **ตัวเลขงานที่ค้างในขั้นนี้** (เช่น "รอบันทึกเงินเข้า 2 งวด") · ปุ่มไปหน้านั้นโดยเลือกตัวกรองให้แล้ว
- การ์ดที่มีงานค้างเด่นขึ้น (ขอบสีน้ำเงิน + ตัวเลข) · ไม่มีงานค้าง = สีปกติ บอก "ไม่มีค้าง"

| ขั้น | การ์ด | ไปหน้า | ตัวเลขค้าง |
|---|---|---|---|
| 1 | รับงานจาก Fastwork → สร้างโปรเจกต์ | ฟอร์มสร้างโปรเจกต์ช่องทาง Fastwork (ราคางาน งวด เลขคำสั่งซื้อ ลูกค้า) | - |
| 2 | ตั้งทีมและส่วนแบ่ง | หน้าโปรเจกต์ แท็บสมาชิก/ส่วนแบ่ง | โปรเจกต์ Fastwork ที่ยังไม่ได้ตั้งส่วนแบ่ง |
| 3 | ทำงานและส่งงานตามงวด | บอร์ดงานของโปรเจกต์ | โปรเจกต์ที่กำลังทำ · งวดใกล้ครบกำหนด (7 วัน) |
| 4 | ลูกค้ายืนยันงวด → บันทึก "รอโอน" | รายการเงิน Fastwork (เลือกงวด เติมราคางาน/ค่าธรรมเนียมให้) | งวดที่ส่งงานแล้วแต่ยังไม่บันทึก |
| 5 | เงินเข้าบัญชี → ยืนยันเงินเข้า | รายการเงิน Fastwork ตัวกรอง "รอโอน" | รายการรอโอน |
| 6 | ค่าใช้จ่ายของโปรเจกต์ | บันทึกค่าใช้จ่าย (เลือกโปรเจกต์ให้แล้ว) | - |
| 7 | เบิกส่วนแบ่งล่วงหน้า (ถ้าจำเป็น) | หน้าส่วนแบ่งของโปรเจกต์ | คำขอเบิกที่รอบันทึกจ่าย |
| 8 | ปิดโปรเจกต์ → ปิดยอดส่วนแบ่ง | หน้าปิดยอด | โปรเจกต์ที่เงินเข้าครบแต่ยังไม่ปิดยอด |

## 7. จุดที่ต้องระวัง

- **ห้ามนับรายได้ซ้ำ:** งานเดียวมีทั้งใบแจ้งหนี้และเงิน Fastwork ไม่ได้ (เลือกช่องทางที่โปรเจกต์ · ระบบกันผูกผิด)
- **ปิดยอดพร้อมกันสองคน:** ล็อกด้วยเวอร์ชัน (แบบเดียวกับรอบเงินเดือน)
- **ค่าธรรมเนียม Fastwork เปลี่ยนได้:** เก็บอัตรา ณ วันที่บันทึกในแต่ละรายการ ไม่อ่านจากตั้งค่าย้อนหลัง
- **ผู้ได้ส่วนแบ่งลาออก/บัญชีถูกปิด:** ยอดที่ค้างจ่ายยังแสดงและจ่ายได้ · ชื่อคัดลอกไว้เฉพาะในรายการเบิกและบรรทัดปิดยอด (หลักฐานการจ่าย) · ส่วนแบ่งที่ยังแก้ได้ไม่เก็บชื่อซ้ำ ดึงจากผู้ใช้/ผู้ขาย (ผู้ใช้สั่ง 25 ต.ค. 2026: ลดความซ้ำซ้อนของข้อมูล)
- **คนนอก (ฟรีแลนซ์):** ถ้าเป็นผู้ขายที่ต้องหัก ณ ที่จ่าย ใช้ประเภทเงินได้ของผู้ขายเดิม
- **เปลี่ยนเป็นนิติบุคคล:** ช่วงก่อนจดกับหลังจดแยกด้วยวันที่จดบริษัท · รายงานแยกสองช่วง (ภาษีคนละแบบ) · เงินทุนสะสมยกไปเป็นทุนจดทะเบียนได้ (บันทึกถอนออก "นำไปจดบริษัท")
- **มือถือ:** หน้าส่วนแบ่งของฉันและบันทึกเงิน Fastwork ต้องใช้บนมือถือได้ (ส่วนใหญ่ดูจากมือถือ)

## 8. คำถาม

- **Q1 บันทึกเงินจาก Fastwork:** ก) รายการรับเงินจากแพลตฟอร์มแยก (แนะนำ · ข้อ 3.2) · ข) ใช้ใบแจ้งหนี้/ใบเสร็จเดิม โดยตั้ง Fastwork เป็นลูกค้า → **ผู้ใช้เลือก ก**
- **Q2 กำไรที่แบ่ง:** ก) จากเงินที่ได้รับจริง (แนะนำ · แบ่งเงินที่มีอยู่จริงเท่านั้น) · ข) จากยอดตามสัญญา → **ผู้ใช้เลือก ก**
- **Q3 วิธีแบ่ง:** ก) % ของกำไรต่อคน ส่วนที่เหลือเข้าทุน (แนะนำ) · ข) จำนวนเงินตายตัวต่อคน · ค) ได้ทั้งสองแบบ → **ผู้ใช้เลือก ค**
- **Q4 จังหวะจ่าย:** ก) ปิดยอดตอนจบโปรเจกต์ + เบิกล่วงหน้าได้ (แนะนำ · ตัวเลขนิ่ง ไม่ต้องตามคืน) · ข) แบ่งทุกครั้งที่เงินเข้า → **ผู้ใช้เลือก ก**
- **Q5 เมนูบริษัท (เงินเดือน ประกันสังคม ภ.ง.ด.1):** ก) ซ่อนไว้จนจดบริษัท (แนะนำ) · ข) คงไว้ → **ผู้ใช้เลือก ข**
- **Q6 ความโปร่งใส:** ก) แต่ละคนเห็นเฉพาะส่วนแบ่งของตัวเอง (แนะนำ) · ข) สมาชิกโปรเจกต์เห็นของทุกคน → **ผู้ใช้เลือก ก "แต่ต้องบอกตัวเลขและที่มาที่ไปให้ชัดเจน"** (ข้อ 4.4)
- **Q7 ค่าธรรมเนียม Fastwork:** ผู้ใช้: ใช้เป็นค่าเริ่มต้น แก้ได้ทุกรายการ → ค่าเริ่มต้น **17%** (อัตราปกติที่มีข่าวปี 2025 · เคยลดเหลือ 10% ช่วงโปรโมชัน ก.พ.-เม.ย. 2025 · ยังไม่ยืนยันปี 2026 — ตรวจหน้าค่าธรรมเนียมใน Fastwork ของตัวเองแล้วแก้ในตั้งค่า) · ช่อง VAT ของค่าธรรมเนียมแยกไว้ ค่าเริ่มต้น 0 · ทุกรายการเก็บอัตรา ณ วันที่บันทึก

## 11. P-2 ค่าคอมมิชชั่น (24-25 ต.ค. 2026)

**ฐานข้อมูล** (deploy_schema + reset · 106 ตาราง)
- `tb_project_shares` (shr_): ผู้รับ = ผู้ใช้ หรือผู้ขาย · แบบ % หรือจำนวนเงินตายตัว · หน้าที่ในงาน · ลำดับ
- `tb_share_advances` (sha_): เบิกล่วงหน้า = จ่ายแล้วทันที (วันที่ บัญชี เลขอ้างอิง) · ยกเลิกพร้อมเหตุผล ไม่ลบ
- `tb_share_settlements` (sst_): ปิดยอด = ล็อกรายได้/ค่าธรรมเนียม/ค่าใช้จ่าย/กำไร/ส่วนตายตัว/ฐาน %/เงินทุน ณ วันนั้น · ยกเลิกได้ (เวอร์ชันกันแก้ทับ)
- `tb_share_settlement_lines` (ssl_): ส่วนแบ่ง − เบิกแล้ว = ต้องจ่าย (ติดลบ = ต้องคืน) · จ่าย: หัก ณ ที่จ่าย ยอดโอน วันที่ บัญชี
- สิทธิ์ใหม่ `manageProfitShares` (บิตท้ายสุด) · role เดิมต้องติ๊กเอง

**สูตร** (`shared/profit-share-math.mjs` ใช้ทั้ง backend และหน้าเว็บ)
- กำไรที่แบ่งได้ = (ใบเสร็จก่อน VAT − คืนเงินตามใบลดหนี้ + ราคางวด Fastwork ที่เงินเข้า) − (ค่าธรรมเนียม + VAT) − ค่าใช้จ่ายที่อนุมัติแล้วของโปรเจกต์
- ส่วนตายตัวได้ก่อน → ที่เหลือ × % ของแต่ละคน (ปัดสตางค์ลง · ฐาน ≤ 0 = % ได้ 0) → เงินทุน = ที่เหลือทั้งหมด (รับเศษสตางค์ · ติดลบได้เมื่อขาดทุน)
- ผลรวมทุกคน + เงินทุน = กำไรที่แบ่งได้ พอดีทุกสตางค์

**กติกา**
- ปิดยอดไม่ได้เมื่อ: ยังไม่ตั้งส่วนแบ่ง · มีเงิน Fastwork รอโอน · ตัวเลขเปลี่ยนระหว่างที่ดูอยู่ (`expected_distributable` ไม่ตรง → `PROFIT_CHANGED`)
- ปิดยอดแล้ว: แก้ส่วนแบ่ง/เบิก/บันทึกหรือยืนยันเงิน Fastwork ของงานนั้นไม่ได้ (`SHARES_SETTLED`) · ยกเลิกการปิดยอดได้เมื่อยังไม่ได้จ่าย/รับคืนจากใคร

## 12. P-3 เงินทุนสะสม + สวิตช์รูปแบบกิจการ + เพดาน VAT (ทำแล้ว 25 ต.ค. 2026)

หลัก: **ไม่เก็บตัวเลขซ้ำ** (ผู้ใช้สั่ง 25 ต.ค.) · ยอดเข้าทุนจากโปรเจกต์อ่านจากการปิดยอดส่วนแบ่งโดยตรง ไม่คัดลอกลงสมุดเงินทุน · ยกเลิกการปิดยอด = ยอดหายจากเงินทุนเองอัตโนมัติ

**ฐานข้อมูล**

- ตารางใหม่ `tb_capital_entries` (cpe_): เฉพาะรายการที่บันทึกเอง · ฝากเพิ่ม / ถอนออก · จำนวนเงิน · วันที่ · หมายเหตุ (ถอนต้องใส่เหตุผล) · ยกเลิกพร้อมเหตุผล ไม่ลบ

**ยอดเงินทุน (บนลงล่าง)**
- เข้าจากโปรเจกต์ = รวม "เข้าเงินทุน" ของการปิดยอดที่ยังไม่ยกเลิก (ติดลบได้ถ้าโปรเจกต์ขาดทุน)
- \+ ฝากเพิ่มเอง − ถอนออก = **ยอดเงินทุนสะสม**
- ถอนเกินยอดคงเหลือไม่ได้ · ถอน/ฝาก วันที่ไม่เกินวันนี้

**เทียบเป้า**: ยอดสะสม / เป้า (แถบความคืบหน้า) · ขาดอีก · เฉลี่ยต่อเดือน = เงินเข้าสุทธิ 6 เดือนล่าสุด (รวมเดือนนี้) ÷ 6 · คาดว่าถึงเป้า = เดือนที่ได้จาก ขาดอีก ÷ เฉลี่ย (ปัดขึ้น) · เฉลี่ย ≤ 0 = "ยังคาดไม่ได้"

**เลื่อนไปทำทีหลัง (บอกผู้ใช้)**: นับค่าคอมมิชชั่นเป็นต้นทุนในการ์ดการเงินโปรเจกต์ (ข้อ 2) · รายงานแยกช่วงก่อน/หลังจดบริษัท · ชีตเงินทุนในไฟล์นักบัญชี
