## 1. ขอบเขต

**ทำใน 1B**
- ใบแจ้งหนี้ (IV): ออกจากงวดของใบเสนอราคาที่ลูกค้าตอบรับแล้ว (เลือกได้หลายงวดของใบเดียวกันรวมเป็นใบเดียว) หรือสร้างเองไม่อ้างใบเสนอราคา
- ร่าง → (อนุมัติ ตาม I1) → ออก (ได้เลข) → บันทึกว่าส่งลูกค้าแล้ว → ยกเลิกพร้อมเหตุผล
- ใบวางบิล (BN) ตาม I3: รวมใบแจ้งหนี้ที่ออกแล้วของลูกค้ารายเดียว สกุลเงินเดียว + วันนัดชำระ
- หน้าพิมพ์ A4 ไทย/อังกฤษ (โครงเดียวกับใบเสนอราคา) + บัญชีธนาคาร + QR พร้อมเพย์ (I5)
- หน้าใบเสนอราคา: ตารางงวดบอกสถานะการออกบิลของแต่ละงวด + ปุ่ม "ออกใบแจ้งหนี้งวดนี้"
- สถานะ "เกินกำหนด" คำนวณตอนอ่าน (ไม่เก็บ)

**ไม่ทำใน 1B** (อยู่ช่วงอื่น)
- รับเงิน / ใบเสร็จ / หัก ณ ที่จ่ายจริง / ยอดค้างชำระรายใบ → **1C** (1B เตรียมคอลัมน์ยอดรับแล้วไว้ แต่ยังเป็น 0 เสมอ)
- ใบกำกับภาษี / ใบลดหนี้ / ใบเพิ่มหนี้ → ก่อนจด VAT (รอ B1, B3)
- แท็บการเงินในโปรเจกต์ / Excel ส่งนักบัญชี → **1D**
- ส่งอีเมลจากระบบ → ภายหลัง (ตอนนี้พิมพ์/PDF แล้วส่งเองเหมือนใบเสนอราคา)

## 2. ภาพรวม flow

```
ใบเสนอราคา (ตอบรับแล้ว) ── งวด 1 มัดจำ 30% ──► [ออกใบแจ้งหนี้] ─► IV ร่าง ─► ออก IV-20261020-000001 ─► ส่งลูกค้า
                         ├─ งวด 2 ส่งมอบ 40% ──► (ยังไม่ออก)
                         └─ งวด 3 ปิดงาน 30% ──► (ยังไม่ออก)

สร้างเอง (ไม่มีใบเสนอราคา) ─► IV ร่าง ─► ส่งขออนุมัติ (I1-ค) ─► อนุมัติครบ = ออกอัตโนมัติ

IV ที่ออกแล้วของลูกค้ารายเดียว สกุลเดียว ──► ใบวางบิล BN (นัดชำระวันที่ …) ─► พิมพ์ให้ลูกค้าเซ็นรับ
```

## 4. กติกาธุรกิจ

### 4.1 ออกจากงวดใบเสนอราคา
- ใบเสนอราคาต้องสถานะ **ลูกค้าตอบรับ** เท่านั้น
- เลือกงวดที่ยังไม่ถูกออกบิล (ไม่นับใบแจ้งหนี้ที่ยกเลิก) ได้ 1 งวดขึ้นไป → ได้ร่าง 1 ใบ แถวละงวด (I2-ก)
- ใบเสนอราคา "เก็บครั้งเดียว" = มีงวดเดียวเต็มยอด → คัดลอกรายการเต็มมาแทนบรรทัดงวด
- **ยอดต่องวดล็อกตามใบเสนอราคา** แก้ไม่ได้ (อยากเปลี่ยนยอด = ออกใบเสนอราคาใหม่) · แก้ได้: หมายเหตุ, เครดิต, บัญชีรับเงิน, อัตราหัก ณ ที่จ่ายที่แสดง
- ยอดก่อน VAT ของงวด = แยกจากยอดงวด (ซึ่งรวม VAT ของใบเสนอราคา) ตามสัดส่วนของใบเสนอราคา · **งวดสุดท้ายที่ออกรับเศษ** ให้ผลรวมทุกใบ = ยอดใบเสนอราคาพอดี (R-B2)
- ไม่ต้องอนุมัติ (I1-ค) → กด "ออกใบแจ้งหนี้" จากร่างได้เลย

### 4.2 ใบสร้างเอง
- แก้รายการได้ทุกช่องตอนร่าง (ใช้ตัวแก้รายการเดียวกับใบเสนอราคา) · ลูกค้าต้องเปิดใช้งาน
- ต้องอนุมัติตามกติกา `IV` (I1-ค) — ชั้นตามยอดก่อน VAT เป็นบาท · ผู้สร้างอนุมัติเองไม่ได้ (ยกเว้นตั้งค่า "อนุญาตอนุมัติเอง") · ครบชั้นสุดท้าย = **ออกอัตโนมัติ** (ได้เลข/วันที่)

### 4.3 หลังออก
- แก้ไม่ได้ทุกช่อง · บันทึก "ส่งลูกค้าแล้ว" ได้
- **ยกเลิก**: ต้องมีเหตุผล · เลขยังอยู่ · งวดกลับเป็น "ยังไม่ออกบิล" ออกใหม่ได้ · ถ้าอยู่ในใบวางบิลที่ยังไม่ยกเลิก → ยกเลิกไม่ได้ (ข้อความบอกให้ยกเลิกใบวางบิลก่อน) · 1C: มีการรับเงินแล้วยกเลิกไม่ได้
- **ออกใหม่แทน** = ยกเลิก + สร้างร่างใหม่คัดลอกข้อมูล (ปุ่มเดียว ทำใน transaction เดียว)

### 4.4 ใบวางบิล
- เลือกใบแจ้งหนี้ที่ออกแล้ว ยังไม่ยกเลิก ยังไม่อยู่ในใบวางบิลอื่น ของลูกค้า/สกุลเดียวกัน
- ร่าง → ออก (ได้เลข BN) → ยกเลิกพร้อมเหตุผล (ใบแจ้งหนี้กลับมาเลือกใหม่ได้) · ไม่ต้องอนุมัติ
- หน้าพิมพ์: ตารางใบแจ้งหนี้ (เลขที่ วันที่ ครบกำหนด ยอด) + วันนัดชำระ + ช่องลูกค้าเซ็นรับวางบิล

## 8. จุดเล็กที่อาจเป็นบั๊ก (ตรวจตอนออกแบบ)
| # | ความเสี่ยง | ป้องกัน |
|---|---|---|
| R-B1 | **ออกงวดเดียวซ้ำ** — สองคนกดพร้อมกัน / เปิดสองแท็บ | ล็อกแถวใบเสนอราคา (`FOR UPDATE`) ตอนสร้างร่างและตอนออก · ตรวจงวดซ้ำทั้งตอนสร้างร่างและตอนออก (ร่างสองใบเลือกงวดเดียวกันได้ แต่ออกได้ใบเดียว) |
| R-B2 | **เศษสตางค์สะสม** — แยกยอดก่อน VAT ทีละงวดแล้วผลรวมไม่เท่ายอดใบเสนอราคา | (ปรับตอนเขียนโค้ด) แยกทีเดียวจาก **ทุกงวด** ด้วยวิธี "เศษเหลือมากสุดได้ก่อน" (`shared/invoice-totals.mjs`) → ผลของแต่ละงวดคงที่ ไม่ขึ้นกับลำดับการออกบิล · ผลรวมตรงพอดี · ทุกงวด 0 ≤ ยอดก่อน VAT ≤ ยอดงวด (วิธี "งวดสุดท้ายรับเศษ" พังเมื่องวดสุดท้ายเล็กมาก) |
| R-B3 | **ยอดเกินใบเสนอราคา** — ยกเลิกแล้วออกใหม่ / ร่างซ้อน | ตอนออกตรวจ ผลรวมใบที่ไม่ยกเลิก ≤ ยอดใบเสนอราคา ทุกครั้ง |
| R-B4 | **VAT เปลี่ยนระหว่างใบเสนอราคากับใบแจ้งหนี้** — ใบเสนอราคาก่อนจด VAT (ไม่มี VAT) แต่ออกใบแจ้งหนี้หลังจด | คิด VAT ตามวันที่ออกใบแจ้งหนี้ · ถ้าต่างจากใบเสนอราคา **หยุดก่อนออก** พร้อมข้อความ "ใบเสนอราคาคิด VAT x% แต่วันนี้ต้องคิด y% — ยอดจะเปลี่ยนจากที่ลูกค้าตกลง ตรวจกับลูกค้า/นักบัญชีก่อน" แล้วให้กดยืนยันอีกชั้น · ต้องถามนักบัญชีก่อนวันจด (เพิ่มในคำถาม B1) |
| R-B5 | ร่างค้างข้ามวัน — วันที่/ครบกำหนด/อัตราแลกเปลี่ยนเก่า | ร่างไม่มีวันที่ · คำนวณวันที่ ครบกำหนด อัตรา ตอนกดออกเท่านั้น (เวลาไทย `todayBangkok()`) |
| R-B6 | ลูกค้า/สาขา/บัญชีธนาคาร/สกุลถูกปิดระหว่างร่าง | ออกไม่ได้ + บอกว่าอะไรถูกปิด (แบบ R9) · บัญชีที่ปิดแล้วเลือกใหม่ได้ |
| R-B7 | ใบเสนอราคาถูกแทนที่/ยกเลิกหลังออกบิล | ใบที่ตอบรับแล้ว revision/ยกเลิกไม่ได้อยู่แล้ว (1A) — ใบแจ้งหนี้อ้างได้ถาวร |
| R-B8 | โปรเจกต์ถูกยกเลิก/ลบ | โปรเจกต์ที่มีใบแจ้งหนี้ลบไม่ได้ (แบบ `PROJECT_HAS_QUOTATIONS`) · ยกเลิกโปรเจกต์ได้ ใบแจ้งหนี้ไม่เปลี่ยน |
| R-B9 | เครดิต 0 / ติดลบ / มากเกิน | 0–365 วัน · 0 = ครบกำหนดวันที่ออก |
| R-B10 | เกินกำหนดตามเวลาเครื่อง UTC (R2) | เทียบ `todayBangkok()` · เทสต์รันซ้ำด้วย `TZ=UTC` |
| R-B11 | QR พร้อมเพย์ยอดผิด/เลขผิด | สร้าง payload ตามมาตรฐาน EMVCo + CRC16 มีเทสต์กับตัวอย่างที่รู้ผล · เงินบาทเท่านั้น · ยอดหลังหัก ณ ที่จ่าย (ถ้าแสดง) ไม่ใส่ใน QR — QR ใส่ **ยอดหลังหัก ณ ที่จ่าย** (ผู้ใช้เลือก I5) · ไม่แสดงหัก ณ ที่จ่าย = ใส่ยอดเต็ม · ข้อความใต้ QR บอกยอดที่ฝังไว้ชัดเจน |
| R-B12 | หน้าพิมพ์ยาวหลายหน้า / ลายน้ำ | ใช้โครงเดียวกับใบเสนอราคา (หัวตารางซ้ำ เลขหน้า ลายน้ำร่าง ตรายกเลิก) |
| R-B13 | เลขที่ IV/BN ชนกับ QT | ตัวนับแยกตามประเภทใน `tb_document_sequences` อยู่แล้ว · เทสต์ออกพร้อมกัน 25 คำขอ |

## 9. เทสต์ที่ต้องผ่าน
- หน่วย: แยกยอดก่อน VAT/VAT ต่องวด + งวดสุดท้ายรับเศษ (THB, USD, สกุล 0 ทศนิยม, ส่วนลดท้ายบิล) · ครบกำหนด/เกินกำหนดข้ามเขตเวลา · payload พร้อมเพย์ + CRC
- API: ออกจากงวด 1 งวด/หลายงวด · งวดซ้ำถูกปฏิเสธ (รวมกดพร้อมกัน) · ผลรวมไม่เกินใบเสนอราคา · ยกเลิกแล้วออกใหม่ได้ · ใบสร้างเองอนุมัติหลายชั้นแล้วออกอัตโนมัติ · ยกเลิกใบที่อยู่ในใบวางบิลไม่ได้ · ใบวางบิลรวมได้เฉพาะลูกค้า/สกุลเดียว · VAT เปลี่ยน (R-B4) ต้องยืนยัน · snapshot ไม่เปลี่ยนเมื่อแก้ลูกค้า/บริษัท/บัญชี · สิทธิ์ทุกปุ่ม
- ภาพหน้าจอ: จอคอม + มือถือ 360/400px ทุกหน้า + หน้าพิมพ์ไทย/อังกฤษ/USD/ร่าง/ยกเลิก
