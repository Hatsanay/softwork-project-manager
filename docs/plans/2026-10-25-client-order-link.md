# ลิงก์เลือกบริการ + คำถามความต้องการ → ใบเสนอราคา → โปรเจกต์อัตโนมัติ

สถานะ: **S-1 ถึง S-5 เขียนเสร็จ (25 ต.ค. 2026)** · ดูข้อ 14-18

ผู้ใช้สั่ง 25 ต.ค. 2026: "เราจะมีลิงก์ส่งให้ลูกค้าเป็นการช็อปปิ้งว่าลูกค้าต้องการอะไรบ้าง โดยแสดงจากสินค้าที่มีอยู่แล้ว และมีระบบคำถาม requirement ต่างๆ ที่ควรถาม
เพื่อเป็นข้อมูลใช้ในการออกแบบและพัฒนา แสดงราคาชัดเจน เหมือนเลือกซื้อสินค้า คำนวณราคาทั้งหมด หลังจากลูกค้ากดส่ง ให้คนที่ได้รับมอบหมายยืนยันและสร้างโปรเจกต์ให้อัตโนมัติ"

คำตอบ (25 ต.ค.): **Q1-ค** ลิงก์ทั้งแบบเฉพาะลูกค้าและแบบสาธารณะ · **Q2-ก** ยืนยัน → ใบเสนอราคา (เติมจากตะกร้า) → ลูกค้าตอบรับ → โปรเจกต์ ·
**Q3-ข** ราคาประมาณการ ผู้รับผิดชอบปรับได้ก่อนยืนยัน · **Q4-ก** คำตอบไม่มีผลกับราคา (ลูกค้าปรับจำนวนในตะกร้าเอง) ·
**Q5-ข** ตั้งคนรับเริ่มต้นในตั้งค่า · **Q6** ร่างชุดคำถามต่อหมวด (เว็บไซต์ แอปมือถือ ออกแบบ UX/UI ระบบงาน) แก้เพิ่มได้ในตั้งค่า ·
**Q7-ก** ลูกค้ากดยอมรับใบเสนอราคาเองในลิงก์ได้ · **Q8-ก** ลิงก์สาธารณะแสดงราคา · **Q9-ก** แนบไฟล์ได้ (รูป/PDF 10 MB · 5 ไฟล์ต่อคำถาม) ·
ผู้ใช้เพิ่ม: "ใช้ระบบนี้กับ fastwork ได้ด้วย" → ข้อ 13

## 1. ภาพรวมขั้นตอน

```
พนักงานสร้างลิงก์ (หรือใช้ลิงก์สาธารณะ)
  → ลูกค้า: 1 เลือกบริการ → 2 ตอบคำถาม → 3 ข้อมูลติดต่อ → 4 ตรวจและส่ง
  → คำขอบริการ "รอตรวจ" (แจ้งผู้รับผิดชอบทางอีเมล + ตัวเลขค้างในเมนู)
  → ผู้รับผิดชอบ: ผูก/สร้างลูกค้า · ปรับรายการ/ราคา · กด "สร้างใบเสนอราคา"
  → ใบเสนอราคา: อนุมัติ → ส่ง (ขั้นตอนเดิมทั้งหมด)
  → ลูกค้าตอบรับ (กดในลิงก์เดิม Q7 · หรือพนักงานบันทึกแบบเดิม)
  → เปิดโปรเจกต์ + สร้างงานจากรายการ (ของเดิม) · ความต้องการแนบในหน้าโปรเจกต์
```

## 2. ลิงก์ (2 แบบ ตาราง เดียวกัน)

| | ลิงก์เฉพาะลูกค้า | ลิงก์สาธารณะ |
|---|---|---|
| ใช้กับ | ลูกค้าที่คุยอยู่ (มีในระบบแล้ว หรือยังไม่มี) | ติดหน้าเว็บ/เพจ/โปรไฟล์ LINE |
| ข้อมูลติดต่อ | เติมจากลูกค้าที่ผูกไว้ แก้ได้ | ลูกค้ากรอกเอง |
| อายุ | 30 วัน (แก้ได้ · ต่ออายุได้) | ไม่หมดอายุ ปิด/เปิดได้ |
| ส่งได้ | 1 คำขอ (ส่งแล้ว = หน้าสถานะ) | หลายคำขอ (คนละคน) |
| ขอบเขตสินค้า | เลือกหมวดได้ (ว่าง = ทุกหมวดที่เปิดหน้าร้าน) | เลือกหมวดได้ |
| ผู้รับผิดชอบ | ค่าเริ่มต้นจากตั้งค่า แก้ต่อลิงก์ได้ | ค่าเริ่มต้นจากตั้งค่า แก้ต่อลิงก์ได้ |

- ที่อยู่: `/order/<token>` (token สุ่ม 32 ตัว · หน้าเว็บสาธารณะ ไม่ต้อง login)
- สร้างลิงก์เฉพาะลูกค้าจาก: หน้าลูกค้า (เลือกลูกค้าให้แล้ว) · หน้ารายการลิงก์ · ส่งทางอีเมลได้ (ใช้ตัวส่งอีเมลเดิม) หรือคัดลอกไป LINE
- **ลูกค้าที่มาจาก Fastwork**: ลิงก์เลือกบริการ (มีราคา/ตะกร้า/ใบเสนอราคา) สร้างให้ไม่ได้ เพราะราคาและการจ่ายต้องอยู่บน Fastwork · ใช้ **ลิงก์ความต้องการ** ของโหมด Fastwork แทน (ข้อ 13) · ตรวจจากลูกค้าที่มีโปรเจกต์ช่องทาง Fastwork แล้วบอกเหตุผลในหน้า

## 3. หน้าร้าน (มือถือก่อน)

- สินค้าที่ขึ้นหน้าร้าน = สินค้า/ชุดสินค้าที่เปิด "แสดงบนหน้าร้าน" และยังใช้งาน · เรียงตามหมวด
- การ์ดสินค้า: รูป (ถ้ามี) · ชื่อ · คำอธิบาย (ใช้ `product_description` เดิม ไม่เก็บซ้ำ) · ราคา/หน่วย · ปุ่ม + / − จำนวน
- ชุดสินค้า: แสดงรายการข้างในและราคารวมของชุด · ใส่ตะกร้าทั้งชุด (ในคำขอเก็บเป็นหัวข้อ + รายการ เหมือนตอนดึงชุดเข้าใบเสนอราคา)
- **แถบล่างจอติดตลอด**: จำนวนรายการ · ยอดประมาณการ · ปุ่มขั้นถัดไป
- ตะกร้า/สรุป (บนลงล่าง ตัวเลขเดียวต่อความหมาย):
  ```
  รายการ × จำนวน = ราคา        (ทุกแถว)
  รวม
  + VAT 7%                       (เฉพาะเมื่อบริษัทจด VAT แล้ว ณ วันนี้)
  = ยอดประมาณการ
  ```
  ข้อความใต้ยอด: "ราคาประมาณการ ทีมงานจะยืนยันราคาสุดท้ายในใบเสนอราคา" (Q3-ข)
- ตะกร้าเก็บในเครื่องลูกค้า (เปิดลิงก์ใหม่ยังอยู่) · ราคาอ่านจากระบบทุกครั้งที่เปิด · สินค้าถูกปิดระหว่างเลือก → แจ้งและเอาออกให้ก่อนส่ง

## 4. คำถามความต้องการ

**โครงสร้าง**: กลุ่มคำถาม → คำถาม · กลุ่มผูกกับหมวดสินค้า (หลายหมวดได้) · กลุ่ม "ทั่วไป" ถามทุกคำขอ
→ ลูกค้าเลือกสินค้าหมวดไหน ขึ้นกลุ่มคำถามของหมวดนั้น (กลุ่มเดียวกันขึ้นครั้งเดียว)

**ชนิดคำตอบ**: ข้อความสั้น · ข้อความยาว · เลือกหนึ่ง · เลือกหลายข้อ · ใช่/ไม่ใช่ · ตัวเลข · วันที่ · ลิงก์ · แนบไฟล์ (รูป/PDF ไม่เกิน 10 MB ไม่เกิน 5 ไฟล์ต่อคำถาม)
แต่ละคำถาม: บังคับตอบไหม · ข้อความช่วยใต้คำถาม (ตัวอย่างคำตอบ) · ตัวเลือก (ชนิดเลือก) · ลำดับ · เปิด/ปิด

**ชุดตั้งต้น** (deploy ใส่ให้ครั้งแรก · แก้/ลบ/เพิ่มได้ · ผูกกลุ่มกับหมวดในหน้าตั้งค่า เพราะชื่อหมวดของแต่ละที่ต่างกัน)

- **ทั่วไป** (ถามทุกคำขอ)
  1. ธุรกิจ/องค์กรของคุณทำอะไร ลูกค้าหลักคือใคร (ข้อความยาว · บังคับ)
  2. เป้าหมายของงานนี้ (เลือกหลายข้อ: เพิ่มยอดขาย · ลดงานเอกสาร · ภาพลักษณ์ · ให้ลูกค้าจองเอง · อื่นๆ)
  3. อยากให้เสร็จภายใน (วันที่)
  4. งบประมาณที่ตั้งไว้ (เลือกหนึ่ง: ต่ำกว่า 20,000 · 20,000-50,000 · 50,000-100,000 · มากกว่า 100,000 · ยังไม่แน่ใจ)
  5. ใครเป็นคนตัดสินใจ/ตรวจรับงาน (ข้อความสั้น)
  6. ช่องทางที่สะดวกให้ติดต่อ (เลือกหนึ่ง: โทร · LINE · อีเมล)
- **เว็บไซต์**
  1. มีเว็บไซต์เดิมไหม (ใช่/ไม่ใช่) · ถ้ามี ลิงก์ (ลิงก์)
  2. ประมาณกี่หน้า และมีหน้าอะไรบ้าง (ข้อความยาว · ช่วย: หน้าแรก เกี่ยวกับเรา บริการ ติดต่อ)
  3. มีโดเมนแล้วไหม (เลือกหนึ่ง: มีแล้ว · ยังไม่มี ให้จดให้ · ไม่แน่ใจ)
  4. ต้องการระบบอะไรเพิ่ม (เลือกหลายข้อ: ฟอร์มติดต่อ · จอง/นัดหมาย · ร้านค้าออนไลน์ · ชำระเงิน · ระบบสมาชิก · หลายภาษา · บทความ/ข่าว)
  5. ใครจะแก้เนื้อหาหลังส่งมอบ (เลือกหนึ่ง: แก้เอง ต้องมีหลังบ้าน · ให้ทีมงานแก้)
  6. เว็บตัวอย่างที่ชอบ และชอบตรงไหน (ข้อความยาว)
  7. มีเนื้อหา/รูปพร้อมแล้วไหม (เลือกหนึ่ง: พร้อม · บางส่วน · ยังไม่มี)
- **แอปมือถือ**
  1. ต้องการลงระบบไหน (เลือกหลายข้อ: iOS · Android)
  2. ผู้ใช้แอปคือใคร ใช้ทำอะไรเป็นหลัก (ข้อความยาว · บังคับ)
  3. ฟีเจอร์ที่ต้องมีในเวอร์ชันแรก (ข้อความยาว · ช่วย: เรียงจากสำคัญที่สุด)
  4. ต้องใช้งานตอนไม่มีอินเทอร์เน็ตไหม (ใช่/ไม่ใช่)
  5. ต้องเชื่อมกับระบบอื่นไหม เช่น LINE ระบบชำระเงิน ระบบเดิม (ข้อความยาว)
  6. มีบัญชีนักพัฒนา App Store / Google Play แล้วไหม (เลือกหนึ่ง: มีแล้ว · ยังไม่มี · ไม่แน่ใจ)
- **ออกแบบ UX/UI**
  1. ออกแบบให้อะไร (เลือกหนึ่ง: เว็บไซต์ · แอปมือถือ · ระบบงาน · อื่นๆ)
  2. ประมาณกี่หน้าจอ (ตัวเลข)
  3. มีโลโก้/สีประจำแบรนด์แล้วไหม (เลือกหนึ่ง: มีครบ · มีโลโก้อย่างเดียว · ยังไม่มี) · แนบไฟล์โลโก้/คู่มือแบรนด์ (แนบไฟล์)
  4. โทนที่ต้องการ (เลือกหลายข้อ: เรียบหรู · สดใส · เป็นทางการ · เป็นกันเอง · มินิมอล)
  5. ตัวอย่างงานที่ชอบ (ลิงก์/แนบไฟล์)
- **ระบบงาน** (ระบบภายในองค์กร)
  1. ตอนนี้ทำงานนี้อย่างไร (กระดาษ · Excel · โปรแกรมเดิม) และติดปัญหาอะไร (ข้อความยาว · บังคับ)
  2. ผู้ใช้กี่คน แบ่งกี่บทบาท (ข้อความยาว · ช่วย: เช่น แอดมิน 2 พนักงาน 15)
  3. ต้องย้ายข้อมูลเดิมเข้าระบบใหม่ไหม (ใช่/ไม่ใช่) · แนบตัวอย่างไฟล์/เอกสารที่ใช้อยู่ (แนบไฟล์)
  4. รายงานที่ต้องดู (ข้อความยาว)
  5. ใช้บนอุปกรณ์อะไร (เลือกหลายข้อ: คอมพิวเตอร์ · มือถือ · แท็บเล็ต)
  6. ต้องการติดตั้งที่ไหน (เลือกหนึ่ง: คลาวด์ · เซิร์ฟเวอร์ของบริษัท · ไม่แน่ใจ)

## 5. ข้อมูลติดต่อ + ส่ง

- ช่อง: ชื่อผู้ติดต่อ (บังคับ) · เบอร์โทร (บังคับ) · อีเมล · LINE ID · ชื่อบริษัท/ร้าน · ต้องการใบกำกับในนามบริษัทไหม (ใช่ → เลขผู้เสียภาษี ที่อยู่)
- ยินยอมข้อมูลส่วนบุคคล (บังคับติ๊ก · ข้อความบอกว่าเก็บอะไร ใช้ทำอะไร เก็บนานเท่าไร) · เก็บวันเวลาที่ยินยอม
- หน้า "ตรวจและส่ง": รายการ + ยอดประมาณการ + คำตอบทั้งหมด แก้ย้อนกลับได้ทุกขั้น
- ส่งแล้ว → หน้าสถานะในลิงก์เดิม: เลขคำขอ · สิ่งที่ส่ง · สถานะปัจจุบัน (รอทีมงานตรวจ → ใบเสนอราคาพร้อมแล้ว → ตอบรับแล้ว เริ่มงาน)

## 6. ฝั่งพนักงาน: คำขอบริการ

เมนู **ขาย > คำขอบริการ** (ตัวเลขรอตรวจ) · การ์ดในแดชบอร์ด "คำขอบริการรอตรวจ" · อีเมลแจ้งผู้รับผิดชอบเมื่อมีคำขอใหม่

หน้ารายละเอียดคำขอ (บนลงล่าง):
1. **ลูกค้า**: ระบบหาลูกค้าเดิมที่ตรงกัน (เบอร์ · อีเมล · เลขผู้เสียภาษี · ชื่อ) แล้วเสนอให้ผูก · ไม่ตรง = สร้างใหม่จากข้อมูลที่ลูกค้ากรอก (เติมให้ แก้ได้)
2. **รายการและราคา**: ตารางจากตะกร้า (ราคา ณ วันที่ลูกค้าส่ง) · แก้จำนวน/ราคา เพิ่ม/ลบ รายการได้ (Q3-ข) · ยอดบนลงล่างเหมือนหน้าลูกค้า · แถวที่แก้มีป้าย "ปรับจากที่ลูกค้าเลือก"
3. **ความต้องการ**: คำตอบทุกข้อเรียงตามกลุ่ม · ไฟล์แนบเปิด/ดาวน์โหลดได้ · ทำเครื่องหมาย "ต้องถามเพิ่ม" พร้อมโน้ตภายในได้
4. ปุ่ม: **สร้างใบเสนอราคา** (เปิดหน้าใบเสนอราคาที่เติมแล้ว เป็นร่าง ปรับงวด/เงื่อนไขต่อได้ แล้วส่งอนุมัติตามเดิม) · **ปฏิเสธ** (ใส่เหตุผล · ลูกค้าเห็นแค่ "ทีมงานจะติดต่อกลับ")

ใบเสนอราคาที่สร้าง: ชื่อเรื่องจากบริการที่เลือก · ชุดสินค้า = หัวข้อ + รายการ · บันทึกภายในอ้างเลขคำขอ · ผูกกลับที่คำขอ (คำขอหนึ่งมีใบเสนอราคาที่ยังไม่ยกเลิกได้ใบเดียว)
สถานะคำขอหลังสร้างใบเสนอราคา **อ่านจากใบเสนอราคา** (รออนุมัติ · ส่งแล้ว · ตอบรับ · ปฏิเสธ · หมดอายุ) ไม่เก็บซ้ำในคำขอ

## 6.1 ติ๊กได้ว่าจะออกใบเสนอราคาไหม (ผู้ใช้สั่ง 25 ต.ค. 2026)

หน้ายืนยันคำขอมีช่องติ๊ก **"ออกใบเสนอราคา"** (ทั้งลูกค้าตรงและ Fastwork · ติ๊กไว้เป็นค่าเริ่มต้น) · ข้อความช่วยใต้ช่องบอกผลของแต่ละแบบ

| | ติ๊ก (ค่าเริ่มต้น) | ไม่ติ๊ก |
|---|---|---|
| ลูกค้าตรง | สร้างใบเสนอราคาจากตะกร้า → อนุมัติ → ส่ง → ลูกค้ากดยอมรับ → เปิดโปรเจกต์ (ข้อ 6-7) | กด "ยืนยันและเปิดโปรเจกต์" → สร้างลูกค้า (ถ้าไม่มี) + โปรเจกต์ + งานจากรายการทันที · ลิงก์ของลูกค้าขึ้น "ทีมงานยืนยันแล้ว เริ่มงาน" · เก็บเงินด้วยใบแจ้งหนี้ที่สร้างเอง (ไม่มีงวดจากใบเสนอราคา) |
| Fastwork | ใบเสนอราคาภายใน (ข้อ 13) → "ลูกค้ายืนยันบน Fastwork แล้ว" → งาน + งวด Fastwork จากใบ | กด "ลูกค้ายืนยันบน Fastwork แล้ว" จากคำขอเลย → งานจากรายการเข้าโปรเจกต์เดิม + เพิ่มงวด Fastwork (เติมให้ 1 งวด = ยอดส่วนที่เกินงานเดิม แบ่งเพิ่มได้) |

- ไม่ออกใบเสนอราคา: รายการและราคาในคำขอ (ที่ผู้รับผิดชอบปรับแล้ว) คือหลักฐานขอบเขตงาน · การ์ดความต้องการในโปรเจกต์แสดงรายการนี้ด้วย
- สร้างงานจากรายการ: แยกตัวสร้างงานของขั้นตอนตอบรับใบเสนอราคาออกมาเป็นฟังก์ชันกลาง ใช้ได้ทั้งจากใบเสนอราคาและจากคำขอ (ไม่เขียนซ้ำ)
- เปลี่ยนใจภายหลัง: คำขอที่ยืนยันแบบไม่ออกใบเสนอราคาแล้ว ออกใบเสนอราคาเพิ่มจากหน้าโปรเจกต์ได้ตามปกติ (ไม่ผูกกลับคำขอ)

## 7. ตอบรับ → โปรเจกต์

- ใบเสนอราคาส่งแล้ว → หน้าสถานะในลิงก์ขึ้นสรุปใบเสนอราคา + เปิด PDF + ปุ่ม **"ยอมรับใบเสนอราคา"** (Q7)
- ลูกค้ากด → ใช้ขั้นตอนตอบรับเดิม (`project_mode: new`, `create_tasks: true`) → เปิดโปรเจกต์ + งานจากรายการ · บันทึกว่าลูกค้าตอบรับเองทางลิงก์ (ชื่อที่พิมพ์ยืนยัน + เวลา)
- พนักงานบันทึกตอบรับแบบเดิมได้เหมือนเดิม (ลูกค้าตอบทาง LINE/โทร)
- หน้าโปรเจกต์: การ์ด **"ความต้องการจากลูกค้า"** อ่านจากคำขอที่ผูกกับใบเสนอราคาของโปรเจกต์ (ไม่คัดลอก) · สมาชิกโปรเจกต์เห็น (ข้อมูลออกแบบ/พัฒนา) · ยอดเงินเห็นตามสิทธิ์เดิม

## 8. ฐานข้อมูล (prefix ไม่ชนตารางอื่น · ตรวจแล้ว)

- `tb_products` + `product_is_public` (แสดงบนหน้าร้าน) · `product_image_url` · `tb_product_packages` + `pkg_is_public` · `pkg_image_url`
- `tb_company_settings` + `cs_service_request_assignee_id` (ผู้รับคำขอเริ่มต้น)
- `tb_order_links` (ol_): token · ชนิด personal/public · ลูกค้าที่ผูก · ผู้รับผิดชอบ · หมวดที่เปิด (ตารางลูก `tb_order_link_categories`) · หมดอายุ · สถานะ active/disabled · สร้างโดย
- `tb_requirement_groups` (rqg_) · `tb_requirement_group_categories` · `tb_requirement_questions` (rqq_: ชนิด บังคับ ข้อความช่วย ตัวเลือก (JSON) ลำดับ สถานะ)
- `tb_service_requests` (svr_): เลขคำขอ · ลิงก์ · ข้อมูลติดต่อที่ลูกค้ากรอก · ยินยอม PDPA · ผู้รับผิดชอบ · ลูกค้าที่ผูก · ใบเสนอราคาที่สร้าง · สถานะ submitted/quoted/rejected · เหตุผลปฏิเสธ · เวอร์ชัน
- `tb_service_request_items` (svi_): สินค้า/ชุด · ชื่อ หน่วย ราคา จำนวน ณ วันส่ง (คัดลอกเพราะเป็นราคาที่ลูกค้าเห็นตอนส่ง) · ค่าที่ผู้รับผิดชอบปรับ
- `tb_service_request_answers` (sva_): คำถาม · ข้อความคำถาม ณ วันส่ง (คัดลอก: คำถามแก้ทีหลังได้ คำตอบต้องอ่านคู่กับคำถามเดิม) · คำตอบ · ไฟล์ (ตารางลูก `tb_service_request_files`)
- ทุกตารางใหม่: TRUNCATE ใน reset · deploy_schema แบบรันซ้ำได้ · ชุดคำถามตั้งต้นใส่เฉพาะตอนตารางยังว่าง

- ตั้งค่าหน้าร้าน (เปิดสินค้าบนหน้าร้าน รูป) และชุดคำถาม: `productManagement` เดิม
- ผู้รับคำขอเริ่มต้น: `companySettings` เดิม

## 10. จุดที่ต้องระวัง

- **สแปมลิงก์สาธารณะ**: ช่องดักบอท (honeypot) · จำกัดคำขอต่อลิงก์ (เช่น 20 ต่อชั่วโมง) · request มาผ่านเซิร์ฟเวอร์ frontend IP จึงอาจไม่ใช่ของลูกค้า (บทเรียนจาก rateLimit เดิม) → นับต่อลิงก์ + ต่อเบอร์โทรด้วย
- **กดส่งซ้ำ**: หน้าเว็บส่งรหัสครั้งเดียวต่อการส่ง ซ้ำ = ตอบคำขอเดิม · ลิงก์เฉพาะลูกค้าส่งได้ครั้งเดียว
- **ราคาเปลี่ยนระหว่างเลือก**: ตอนกดส่งตรวจราคาล่าสุดอีกครั้ง ต่างจากที่เห็น → แจ้งให้ดูยอดใหม่ก่อนส่ง (ไม่เปลี่ยนเงียบๆ)
- **ไฟล์แนบ**: เก็บแบบส่วนตัว (ไม่ใช่ uploads สาธารณะ) · จำกัดชนิด/ขนาด · ลูกค้าเห็นได้เฉพาะในลิงก์ของตัวเอง
- **ลิงก์รั่ว**: token สุ่มยาว · ลิงก์เฉพาะลูกค้าหมดอายุ · ปิดลิงก์ได้ทันที · หน้าสถานะไม่แสดงข้อมูลภายใน (เหตุผลปฏิเสธ โน้ต)
- **ยืนยันพร้อมกันสองคน / สร้างใบเสนอราคาซ้ำ**: ล็อกด้วยเวอร์ชัน · คำขอหนึ่งมีใบเสนอราคาที่ยังไม่ยกเลิกได้ใบเดียว
- **ลูกค้าตอบรับใบเสนอราคาที่หมดอายุ/ถูกยกเลิก**: ปุ่มหายและบอกเหตุผล
- **VAT**: ยังไม่จด = ไม่แสดงบรรทัด VAT · จดแล้ว = ใช้อัตรา ณ วันที่เปิดหน้า (ระบบอัตราตามวันที่เดิม)
- **สินค้าราคา 0 / ไม่มีหน่วย**: แสดง "สอบถามราคา" และไม่นับในยอด
- **ช่วงก่อนจดบริษัท**: ชื่อบนหน้าร้าน/ใบเสนอราคาใช้ชื่อในตั้งค่าบริษัท (บุคคลธรรมดาได้)
- **ข้อมูลไม่ซ้ำ**: คำอธิบายสินค้าใช้ของเดิม · สถานะหลังออกใบเสนอราคาอ่านจากใบเสนอราคา · ความต้องการในโปรเจกต์อ่านจากคำขอ · คัดลอกเฉพาะราคา/ข้อความคำถาม ณ วันส่ง (มีเหตุผลข้างบน)
- **มือถือ**: ปุ่ม + / − อย่างน้อย 44px · แถบล่างไม่บังช่องกรอก · ช่องกรอกตัวอักษร 16px (กัน iOS ซูม) · ทดสอบ 360/400px

## 11. ลำดับงาน

1. **S-1 หน้าร้าน**: ฟิลด์แสดงบนหน้าร้าน/รูป · ลิงก์ 2 แบบ · หน้าเลือกบริการ + ตะกร้า + ข้อมูลติดต่อ + ส่ง (ยังไม่มีคำถาม) · หน้าสถานะ
2. **S-2 คำถาม**: ตาราง + ชุดตั้งต้น + หน้าตั้งค่า (ผูกหมวด) · ขั้นตอบคำถามในหน้าร้าน + แนบไฟล์
3. **S-3 คำขอบริการ**: เมนู + แจ้งเตือน · ผูก/สร้างลูกค้า · ปรับรายการ · สร้างใบเสนอราคา · ปฏิเสธ
4. **S-4 ตอบรับออนไลน์ + การ์ดความต้องการในโปรเจกต์**
5. **S-5 โหมด Fastwork** (ข้อ 13): ตัวคิดราคาภายใน + คัดลอกคำถามเป็นข้อความ · ลิงก์ความต้องการของงาน Fastwork
6. ทุกช่วง: เทสต์ + deploy_schema + reset + ภาพหน้าจอมือถือ · ข้อมูลจำลองเพิ่มทั้งสองชุดตอนจบ (ชุดช่วงก่อนจดมีลิงก์ความต้องการของงาน Fastwork)

## 13. โหมด Fastwork (ผู้ใช้สั่ง 25 ต.ค. 2026: "ใช้ระบบนี้กับ fastwork ได้ด้วย")

**กติกา Fastwork ประเทศไทย** (ตรวจ 25 ต.ค. 2026 · [Exchange of non-system contact channels](https://fastwork4276.zendesk.com/hc/en-th/articles/12126542576655-Exchange-of-non-system-contact-channels) อัปเดต 10 ก.พ. 2026)
- ช่องทางหลักต้องเป็นแชต/โทรในระบบ Fastwork
- แชร์ช่องทางนอกระบบได้เมื่อ: ออร์เดอร์สถานะ "กำลังดำเนินการ" แล้ว + ทั้งสองฝ่ายยินยอม + ใช้เพื่องานเท่านั้น
- การจ่ายเงินต้องผ่าน Fastwork เสมอ · ผิดกติกา = ระงับบัญชีหรือยกเลิกงานได้

**จึงแบ่งเป็น 2 ช่วง**

| ช่วง | ใช้อะไร | ลูกค้าเห็นอะไร |
|---|---|---|
| ก่อนจ้าง (คุยในแชต Fastwork) | **ตัวคิดราคาภายใน**: พนักงานเลือกสินค้าลงตะกร้าในระบบเรา (หน้าเดียวกับหน้าร้าน แต่ใช้ภายใน) ได้ยอดรวม + แบ่งงวด → ใช้กรอกใบเสนอราคาบน Fastwork · **คัดลอกคำถาม** ของหมวดที่เลือกเป็นข้อความ ไปถามในแชต Fastwork | ไม่มีลิงก์ภายนอก · ราคาและคำถามอยู่ในแชต Fastwork |
| หลังจ้าง (ออร์เดอร์ "กำลังดำเนินการ") | **ลิงก์ Fastwork** ผูกกับโปรเจกต์: **เลือกสินค้าลงตะกร้า + ราคา + คำถาม + แนบไฟล์** เหมือนลิงก์ลูกค้าตรง (ผู้ใช้สั่ง 25 ต.ค.) · ไม่มีใบเสนอราคา ไม่มีปุ่มยอมรับ ไม่มีการจ่ายเงิน | เลือกสิ่งที่ต้องการ เห็นยอดประมาณการ ตอบคำถาม แนบไฟล์ · ส่วนที่เกินงานเดิม ทีมส่งใบเสนอราคาเพิ่ม/งวดเพิ่มบน Fastwork ให้จ่ายผ่าน Fastwork |

**เปลี่ยนล่าสุด 25 ต.ค. 2026 (ผู้ใช้: "fastwork แก้ไม่ต้องสนใจสถานะการดำเนินการ ผมอยากให้ลูกค้ากำหนดขอบเขตผ่านลิงก์ที่ผมให้เลย") · ข้อนี้แทนเงื่อนไข "หลังจ้างเท่านั้น" ทั้งหมดด้านล่าง**
- **ไม่ได้พาลูกค้าออกนอก Fastwork** (ผู้ใช้ 25 ต.ค. 2026: "ผมไม่ได้พาไปช่องทางนอก สุดท้ายแล้วผมก็ให้ชำระเงินผ่าน fastwork"): ลิงก์เป็นแบบฟอร์มเลือกขอบเขตงาน · การคุย ใบเสนอราคาที่ตกลง และการจ่ายเงิน อยู่บน Fastwork ทั้งหมด
- ไม่มีช่องติ๊กยืนยันสถานะ · ส่งลิงก์ได้ตั้งแต่ยังคุยในแชตก่อนจ้าง
- ในลิงก์ไม่มีช่องทางจ่ายเงิน ไม่มีเบอร์/อีเมล/LINE ของเรา ไม่ถามข้อมูลติดต่อของลูกค้า · ข้อความ "ราคาและการชำระเงินทำผ่าน Fastwork"
- เรื่องใช้งานจริง: แชต Fastwork อาจซ่อน/บล็อกลิงก์ภายนอก (ยังไม่ได้ทดสอบ · ถ้าซ่อน ให้ลูกค้าคัดลอกที่อยู่ไปเปิดเอง)
- **QR code + รหัสสั้น** (ผู้ใช้ 25 ต.ค. 2026: "มีปุ่มสร้าง qr code ลิงก์ จะแก้ปัญหา fastwork ซ่อนลิงก์ได้ไหม"): ทุกลิงก์ (ทั้ง 3 แบบ) มีปุ่ม "QR code" → รูป PNG พร้อมชื่อร้าน + ข้อความ "สแกนเพื่อเลือกบริการ" บันทึกรูปหรือคัดลอกรูปไปส่งในแชตได้ · วาดในเครื่องด้วยไลบรารี qrcode ที่ใช้กับ QR พร้อมเพย์อยู่แล้ว (ไม่ส่งข้อมูลออกบริการภายนอก)
  - ช่วยได้เมื่อแชตกรองเฉพาะข้อความลิงก์ · ไม่ช่วยถ้าแชตไม่รับรูป หรือ Fastwork ตรวจรูปด้วย (ยังไม่ได้ทดสอบทั้งสองแบบ)
  - ลูกค้าเปิดแชตบนมือถือเครื่องเดียวกัน สแกนจากจอตัวเองไม่ได้ → ต้องกดค้างที่รูปให้มือถืออ่าน QR (iPhone/Android รุ่นใหม่ทำได้) หรือบันทึกรูปแล้วสแกนจากคลังภาพ · ใต้รูปมีที่อยู่แบบสั้น (`/o/<รหัส 8 ตัว>`) ให้พิมพ์เองได้เป็นทางสำรอง
  - รหัสสั้นเป็นอีกชื่อของ token เดิมในตาราง `tb_order_links` (คอลัมน์ `ol_short_code` ไม่ซ้ำ) · เดาได้ยากพอสำหรับลิงก์ที่มีอายุ + จำกัดการเปิดผิดต่อ IP
- **ลิงก์ Fastwork 2 แบบ**:
  - **ก่อนจ้าง** (ใหม่): สร้างจากหน้า Fastwork > "ลิงก์ให้ผู้ซื้อ" · ใส่ชื่อผู้ซื้อที่แสดงบน Fastwork · ยังไม่ผูกลูกค้า/โปรเจกต์
  - **งานเดิม** (ขอบเขตเพิ่ม): สร้างจากการ์ดงาน Fastwork ในหน้าโปรเจกต์ · ผูกโปรเจกต์ (ตามแบบเดิมด้านล่าง ไม่มีติ๊กยืนยัน)
- **ขั้นตอนก่อนจ้าง**:
  1. พนักงานสร้างลิงก์ + คัดลอกข้อความสำเร็จรูปไปวางในแชต Fastwork
  2. ลูกค้าเลือกสินค้า (เห็นราคา) → ตอบคำถาม + ไฟล์ → ตรวจและส่ง (ไม่มีขั้นข้อมูลติดต่อ)
  3. ระบบสร้างคำขอชนิด Fastwork (ยังไม่มีโปรเจกต์) → แจ้งผู้รับผิดชอบ
  4. พนักงานตรวจ/ปรับ → ติ๊กออกใบเสนอราคาภายในได้ (ระบบสร้างลูกค้าบุคคลจากชื่อผู้ซื้อ หรือผูกลูกค้าเดิม เพราะใบเสนอราคาต้องมีลูกค้า)
  5. พนักงานส่งใบเสนอราคาบน Fastwork ด้วยตัวเลขจากใบภายใน/คำขอ
  6. ลูกค้าจ่ายบน Fastwork
  7. พนักงานกด **"รับงานจากคำขอนี้"** → หน้ารับงานใหม่ (ของเดิม) เติมให้: ชื่องาน ลูกค้า งวด (จากงวดของใบเสนอราคา หรือ 1 งวด = ยอดรวม) แก้ได้ → บันทึก = โปรเจกต์ Fastwork + งานจากรายการ + คำขอผูกโปรเจกต์ (การ์ดความต้องการ) + ใบเสนอราคาภายใน (ถ้ามี) ผูกโปรเจกต์เป็น "ตอบรับ"
  8. ต่อด้วยขั้นตอน Fastwork เดิม (ส่งงาน → เงินเข้า → ส่วนแบ่ง)
- ลูกค้าไม่จ้าง: พนักงานกด "ปิดคำขอ (ไม่ได้งาน)" พร้อมเหตุผล · ใช้ดูอัตราได้งานจากลิงก์ภายหลังได้

**รายละเอียดเดิม (ลิงก์งานเดิม/ขอบเขตเพิ่ม)** · เปลี่ยน 25 ต.ค. 2026 (ผู้ใช้: "ในลิงก์มีให้เลือกสินค้าเลยเหมือนที่คุยไว้ เพราะผมอยากทำมาก มันง่าย")**
- ลิงก์ Fastwork มีหน้าร้าน + ตะกร้า + ยอดประมาณการ เหมือนลิงก์ลูกค้าตรง แล้วต่อด้วยคำถาม/แนบไฟล์
- สิ่งที่ยังตัดออกเพื่อให้อยู่ในกติกา: ใบเสนอราคา ปุ่มยอมรับ ช่องทางจ่ายเงิน และข้อมูลติดต่อของเรา · ข้อความในหน้าบอกชัดว่า "ราคาและการชำระเงินทำผ่าน Fastwork"
- ส่งแล้ว: รายการที่เลือก + คำตอบ เข้าการ์ดความต้องการของโปรเจกต์ · ระบบเทียบกับงวดที่ตกลงไว้ → ส่วนที่เกิน = **ยอดที่ต้องเสนอเพิ่มบน Fastwork** (พนักงานส่งใบเสนอราคา/งวดเพิ่มบน Fastwork แล้วบันทึกงวดเพิ่มในระบบ)
- (เงื่อนไข "ส่งได้หลังออร์เดอร์กำลังดำเนินการ" และ "เปิดออร์เดอร์เล็กก่อน" ยกเลิกแล้ว ดูข้อ "เปลี่ยนล่าสุด" ด้านบน)

**ใบเสนอราคาของงาน Fastwork = เอกสารภายใน (ผู้ใช้สั่ง 25 ต.ค. 2026: "fastwork ใบเสนอราคาของเรา เราเก็บไว้ที่เรา ไม่ส่งให้ลูกค้า")**
- คำขอจากลิงก์ Fastwork → ผู้รับผิดชอบตรวจ/ปรับ → **สร้างใบเสนอราคาภายใน** (ผูกโปรเจกต์ Fastwork เดิม) · อนุมัติภายในตามกติกาเดิม
- ใบเสนอราคาช่องทาง Fastwork: **ส่งลูกค้าไม่ได้** (ไม่มีปุ่มส่ง/อีเมล/ลิงก์ยอมรับ · PDF พิมพ์ได้มีหัว "เอกสารภายใน") · ใช้เป็นตัวเลขอ้างอิงตอนกรอกใบเสนอราคาบน Fastwork
- ลูกค้าจ่ายบน Fastwork แล้ว → พนักงานกด **"ลูกค้ายืนยันบน Fastwork แล้ว"** = ตอบรับเข้าโปรเจกต์เดิม (project_mode existing · สร้างงานจากรายการ) + **เพิ่มงวดงาน Fastwork จากงวดของใบเสนอราคา** (ชื่อ/ยอด เติมให้ แก้ได้ก่อนบันทึก)
- ใบเสนอราคาช่องทาง Fastwork **ออกใบแจ้งหนี้/ใบเสร็จไม่ได้** (รายได้มาจากเงินที่ Fastwork โอน · กันนับรายได้ซ้ำ ซึ่งเป็นข้อจำกัดที่บันทึกไว้ใน P-1)
- ข้อมูลไม่ซ้ำ: ช่องทางของใบเสนอราคาอ่านจากโปรเจกต์ที่ผูก (project_channel) ไม่เพิ่มคอลัมน์ · งวด Fastwork ที่สร้างจากใบเสนอราคาเป็นข้อตกลงจริงที่อาจต่างจากใบภายใน จึงเก็บแยก (คัดลอกตอนสร้างครั้งเดียว)

**ลิงก์ความต้องการ (หลังจ้าง) · รายละเอียดเดิม (ส่วนคำถาม/ไฟล์/ล็อก ยังใช้ · ส่วน "ไม่มีราคา" ถูกแทนด้วยข้อบนนี้)**
- สร้างจากการ์ด "งาน Fastwork" ในหน้าโปรเจกต์ · เลือกกลุ่มคำถาม (เติมจากหมวดของสินค้าในตัวคิดราคาถ้าใช้ไว้ · ไม่ใช้ = เลือกเอง)
- ต้องติ๊กยืนยันก่อนสร้าง: "ออร์เดอร์บน Fastwork ขึ้นสถานะกำลังดำเนินการแล้ว และผู้ซื้อตกลงให้ส่งลิงก์ในแชต" (ระบบตรวจสถานะบน Fastwork เองไม่ได้ · เก็บชื่อคนติ๊กและเวลา)
- ข้อความแนะนำสำหรับวางในแชต Fastwork (คัดลอกได้) บอกว่าลิงก์ใช้เก็บรายละเอียดงานเท่านั้น การจ่ายเงินและการคุยหลักยังอยู่บน Fastwork
- ไม่ถามเบอร์/อีเมล (ไม่จำเป็นต่องาน · ติดต่อผ่านแชต Fastwork) · ไม่ต้องยินยอม PDPA เรื่องข้อมูลติดต่อ แต่ยังบอกว่าเก็บคำตอบ/ไฟล์ไว้ใช้ทำงานนี้
- ส่งแล้ว: คำตอบแนบเข้าการ์ด "ความต้องการจากลูกค้า" ของโปรเจกต์ทันที (ไม่ผ่านคำขอบริการ ไม่สร้างใบเสนอราคา เพราะงานและราคามีอยู่แล้ว) · แจ้งผู้รับผิดชอบและสมาชิกโปรเจกต์
- ลูกค้าตอบเพิ่ม/แก้ได้จนทีมกด "ล็อกความต้องการ" (เริ่มออกแบบแล้ว) · แก้หลังล็อก = คุยผ่านแชต Fastwork
- ลิงก์หมดอายุ 30 วัน · ปิดเองเมื่อโปรเจกต์ปิด

**ตัวคิดราคาภายใน (ก่อนจ้าง)**

**หน้าสร้าง/แก้ลิงก์**
- ส่วนใหม่ "รายการที่ทีมงานเลือกให้" (ไม่บังคับ): ค้นสินค้าหรือชุดบริการ + จำนวน · เลือกได้หลายรายการ · เลือกของที่ไม่ได้เปิดหน้าร้านก็ได้ (ทีมเลือกเอง) แต่ต้องยังใช้งานอยู่
- "หมวดที่ให้ลูกค้าเลือกเพิ่ม": แบบเดิม + ตัวเลือกใหม่ "ไม่ให้เลือกเพิ่ม" (ลิงก์ที่มีแต่รายการล็อก ลูกค้าแค่ตอบคำถามแล้วส่ง)
- ข้อความช่วย: รายการล็อก ลูกค้าเอาออกหรือแก้จำนวนไม่ได้ · ราคาตามราคาปัจจุบันของสินค้า/ชุด

**หน้าร้าน (ลูกค้า)**
- บนสุด: การ์ด "ทีมงานเลือกให้แล้ว" แสดงรายการล็อก (ไอคอนกุญแจ ไม่มีปุ่มจำนวน)
- ล่างลงมา: "เลือกเพิ่มได้ถ้าต้องการ" = สินค้าในหมวดที่เปิด · แพ็กที่ล็อกไว้ไม่แสดงซ้ำในรายการให้เลือก
- ตะกร้า: รายการล็อกอยู่บนสุด มีกุญแจ ลบ/แก้ไม่ได้ · ปุ่มถัดไปกดได้ทันทีแม้ลูกค้าไม่เลือกเพิ่ม
- คำถามความต้องการคิดจากหมวดของรายการล็อกด้วย

**Backend**
- ตารางใหม่ `tb_order_link_items` (oli_id, oli_link_id, oli_product_id, oli_package_id, oli_quantity, oli_order) · มี product หรือ package อย่างใดอย่างหนึ่ง
- ส่งคำขอ: ระบบใส่รายการล็อกให้เอง (ไม่เชื่อค่าจากเบราว์เซอร์) · ลูกค้าส่งรายการเดียวกับที่ล็อกมาซ้ำ = ไม่นับซ้ำ · ยอดที่ลูกค้าเห็นต้องรวมรายการล็อก
- `tb_service_request_items.svi_is_preset` เก็บว่าแถวไหนทีมเลือกให้ (สำเนาตอนส่ง เพราะรายการล็อกของลิงก์แก้ได้ภายหลัง) → หน้าคำขอของทีมแสดง "ทีมงานเลือกให้"
- ตรวจตอนเปิดลิงก์: รายการล็อกถูกปิดใช้งาน / ชุดมีสินค้าที่ถูกปิด → ลิงก์ขึ้น "ลิงก์นี้ใช้ไม่ได้ชั่วคราว ติดต่อทีมงาน" (ไม่ให้ส่งคำขอที่ขาดรายการ) · หน้ารายการลิงก์ของทีมเตือนด้วย

**จุดที่ต้องระวัง**
- ตะกร้าที่จำไว้ในเครื่องลูกค้าเก็บเฉพาะของที่ลูกค้าเลือก รายการล็อกมาจากลิงก์ทุกครั้ง (ทีมแก้รายการล็อกแล้วลูกค้ารีเฟรช = เห็นของใหม่)
- ลิงก์เฉพาะลูกค้าส่งได้ครั้งเดียวเหมือนเดิม · ลิงก์สาธารณะ/Fastwork ที่มีรายการล็อก ทุกคำขอได้รายการล็อกชุดเดียวกัน
- รวมกับข้อ 19 (เลือกแพ็กได้ทีละแพ็ก): ลิงก์ที่ล็อกแพ็กไว้แล้ว ลูกค้าเลือกแพ็กอื่นเพิ่มไม่ได้

**ผู้ใช้ตอบ (25 ต.ค. 2026)**: รายการที่ทีมเลือกให้ = **ล็อก** (ลูกค้าเอาออก/แก้จำนวนไม่ได้) · ราคา = **ราคาปกติของสินค้า/ชุด** (ส่วนลดทำในใบเสนอราคาหรือบน Fastwork) → ไม่มีช่องราคาเฉพาะลิงก์

## 21. ข้อ 19 + 20 ที่ทำแล้ว (25 ต.ค. 2026)

**ฐานข้อมูล** (119 ตาราง): `tb_product_categories.pc_is_single_choice` · `tb_products.product_price_mode` ('fixed'/'percent') + `product_percent` · `tb_order_links.ol_allow_more` · `tb_service_request_items.svi_is_preset` + `svi_percent` · ตารางใหม่ `tb_order_link_items` (oli_) `tb_package_addon_rules` (par_) `tb_requirement_group_packages` (rgp_)

**กติกา (backend ตรวจตอนส่งเสมอ ไม่เชื่อหน้าเว็บ)**

- แถว % = % × ผลรวมแถวราคาตายตัว (ไม่ซ้อน %) ปัดครึ่งขึ้นต่อแถว · VAT หลังรวม · จำนวน 1 · ไม่เก็บยอดซ้ำ (svi_unit_price ว่าง) คิดใหม่ทุกครั้งจากแถวหลังปรับ · ใบเสนอราคาได้ยอดที่คิดแล้ว (ใบล็อกเอง) · สินค้าแบบ % อยู่ในชุดไม่ได้
- กลุ่มคำถามผูกชุดได้ (นอกจากหมวด) · applicableGroups(groups, categoryIds, packageIds)

**หน้าเว็บ**: หน้าร้าน (การ์ด "ทีมงานเลือกให้แล้ว" กุญแจ · ใส่แพ็กใหม่ = เปลี่ยนแทน · งานเพิ่ม "มีในแพ็กแล้ว" / ซ่อน · งานด่วน กดเลือก/เอาออก แสดงยอดตอนนี้) · ตะกร้า (แถวล็อก/แถว %) · หน้าลิงก์ (เลือกรายการให้ลูกค้า + สวิตช์ให้เลือกเพิ่ม) · หน้าสินค้า (หมวดเลือกได้อย่างเดียว · ราคาแบบ % · กติกางานเพิ่มในชุด · คำถามผูกชุด) · หน้าคำขอ (ป้ายทีมงานเลือกให้ · แถว % แก้ราคา/จำนวนไม่ได้) · ตัวคิดราคา Fastwork คิด % ด้วย

## 23. ปรับหน้าตัวคิดราคา Fastwork (30 ต.ค. 2026 · ผู้ใช้: "แก้ UX/UI หน้านี้ให้สวยและใช้งานง่าย")

ไฟล์: `fastwork/price/page.tsx` (ข้อมูล + กติกาตะกร้า) · `_components/price-catalog.tsx` · `price-summary.tsx` · `price-texts.ts`

- ฝั่งเลือก: ค้นหา (ชื่อ + รายละเอียด) · ชิปหมวด · แพ็กเป็นการ์ดวางเทียบกัน เรียงตามราคา ราคาตัวใหญ่ รายการในแพ็ก 4 ข้อแรก + "ดูอีก N รายการ" · งานเพิ่มแยกตามหมวด
- กติกาเดียวกับหน้าร้าน: หมวดเลือกได้อย่างเดียว = เปลี่ยนแทน · แพ็กใหม่เอางานเพิ่มที่มีในแพ็กแล้ว/ใช้ไม่ได้ออก (แจ้งด้วย toast) · งานเพิ่มที่มีในแพ็ก = "มีใน {แพ็ก} แล้ว" กดไม่ได้ · ใช้กับแพ็กไม่ได้ = ซ่อน + บอกจำนวน · งานเพิ่มแบบ % ได้ครั้งเดียว
- ข้อความ "เลือกได้ 1 แพ็ก" ขึ้นเฉพาะเมื่อทุกแพ็กอยู่หมวดเลือกได้อย่างเดียวหมวดเดียวกัน
- แผงสรุป (ติดจอบนจอใหญ่): ว่าง = 4 ขั้นตอนใช้งาน · มีของ = รายการ (ปุ่ม x เอาออก) · ราคาเสนอ → หักค่าธรรมเนียม → เงินเข้าจริง · ล้างทั้งหมด
- ปุ่มใหม่ "คัดลอกขอบเขตงาน": รายการ + รายการในแพ็ก + ราคารวม สำหรับวางในข้อเสนอ ไม่มีค่าธรรมเนียม/เงินเข้าจริง (ข้อมูลภายใน)
- มือถือ: แถบล่างบอกจำนวนรายการ ราคาเสนอ เงินเข้าจริง + ปุ่ม "ดูสรุป" · ซ่อนเองเมื่อเลื่อนถึงแผงสรุป
