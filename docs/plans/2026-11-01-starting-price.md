# สินค้า "ราคาเริ่มต้น": ทีมกรอกราคาจริงก่อนสร้างใบเสนอราคา

สถานะ: **เขียนโค๊ดแล้ว 1 พ.ย. 2026 (ยังไม่ commit)** · ตอบครบ Q1 ก · Q2 ข · Q3 ก · ลดราคาไม่ต้องให้ลูกค้ายืนยัน · ผลอยู่ข้อ 7

ที่มา: ผู้ใช้ "บางสินค้าราคาไม่ได้ fix เช่นการจดโดเมน ราคาแล้วแต่ชื่อ" · "ตอนสร้างใบเสนอราคาอัตโนมัติจะต้องเอาราคาไปแสดง ดังนั้นหากลูกค้าเลือกรายการที่มีคำว่าเริ่มต้น ก่อนสร้างใบเสนอราคาให้ถามทีมงานก่อนเพื่อกรอกราคา" (1 พ.ย. 2026)

## 1. ตอนนี้

- สินค้ามีราคา 2 แบบ: ราคาตายตัว · % ของยอดรายการอื่น
- ลูกค้าเลือกในลิงก์ → คำขอบริการ → ทีมกด "ยืนยันคำขอ" (ติ๊กออกใบเสนอราคา) → ระบบสร้างใบจากราคาในคำขอ
- หน้าคำขอแก้ราคา/จำนวนแต่ละรายการได้อยู่แล้ว (`svi_adjusted_unit_price`) แต่ไม่มีอะไรบอกว่ารายการไหนต้องแก้ → ใบออกด้วย 650 ทั้งที่ชื่อนั้นอาจแพงกว่า

## 2. ที่จะทำ

### 2.1 ตั้งที่สินค้า

- วิธีคิดราคาแบบที่ 3 **"ราคาเริ่มต้น"** (`product_price_mode = 'from'`): ราคา = ราคาต่ำสุด · ช่อง **"ราคาขึ้นกับอะไร"** (บังคับ · เช่น "นามสกุลและชื่อโดเมน") แสดงให้ลูกค้าเห็น
- ใช้ได้ทุกที่ที่ราคาตายตัวใช้ได้ (ใส่ในชุดรายการได้ · เป็นบริการรายรอบได้)

### 2.2 ลูกค้า (หน้าร้าน · หน้าสถานะคำขอ)

- การ์ดสินค้า: **"เริ่มต้น 650 บาท"** + "ราคาขึ้นกับนามสกุลและชื่อโดเมน"
- ยอดรวม: **"ยอดเบื้องต้น"** + "มีรายการราคาเริ่มต้น ทีมยืนยันราคาจริงในใบเสนอราคา" (ไม่เรียกว่ายอดสุทธิ)
- คำถามความต้องการที่ผูกกับสินค้านี้ (เช่น "ชื่อโดเมนที่ท่านอยากจด") ถามตามปกติ · ทีมใช้คำตอบตั้งราคา

### 2.3 ทีม (หน้าคำขอบริการ) · หัวใจของเรื่องนี้

- คำขอจำรายการราคาเริ่มต้นไว้ตอนลูกค้าส่ง (`svi_needs_price` · จำ ณ ตอนส่ง สินค้าเปลี่ยนแบบทีหลังไม่กระทบคำขอเดิม)
- รายการนั้นมีป้าย **"รอกรอกราคา"** + เหตุผล + คำตอบที่เกี่ยวข้องอยู่ใกล้ๆ · ช่องราคาเติมราคาเริ่มต้นไว้ให้
- **ถามทีมก่อนสร้างใบ (ไม่มีปุ่มยืนยันทีละบรรทัด · Q2 ข):** กดยืนยันคำขอ/ออกใบภายใน/รับงาน/เพิ่มงวด แล้วมีรายการราคาเริ่มต้นที่ยังไม่ผ่านการตรวจ → หน้าต่างถาม **"ตรวจราคาก่อนสร้างใบ"** แสดงรายการนั้นพร้อมช่องราคา (เติมราคาเริ่มต้น) + เหตุผล + คำตอบที่เกี่ยวข้อง · แก้ราคาหรือกดต่อเลย = ราคานั้นยืนยันแล้ว (`svi_price_confirmed_at/by`) ไม่ต้องกดยืนยันแยก
- แก้ราคาในตารางรายการของคำขอก่อนหน้านั้น = ยืนยันแล้วเช่นกัน (หน้าต่างไม่ถามบรรทัดนั้นอีก)
- **ทุกทางที่ราคาออกไปถึงลูกค้า/ผู้ซื้อ ต้องผ่านหน้าต่างถามนี้ก่อน** · backend รับ `confirmed_prices` มาพร้อมคำสั่ง และตรวจว่าทุกรายการราคาเริ่มต้นยืนยันแล้ว (ขาด = 409 `PRICE_NOT_CONFIRMED`) · ใช้กติกาเดียวกันทุกชนิดลิงก์ (ผู้ใช้ยืนยัน 1 พ.ย. 2026: "ของ fastwork แบบลิงก์และแบบอื่นๆ ก็ใช้แนวทางนี้เหมือนกัน")

| ช่องทาง | ทางที่ต้องกรอกราคาก่อน |
|---|---|
| ลิงก์เฉพาะลูกค้า / ลิงก์สาธารณะ (ลูกค้าตรง) | ยืนยันคำขอ (ออกใบเสนอราคา หรือเปิดโปรเจกต์ตรง) |
| ลิงก์ Fastwork ก่อนจ้าง | ยืนยันคำขอ + ออกใบเสนอราคาภายใน (ใช้ส่งราคาบน Fastwork) · รับงานจากคำขอ |
| ลิงก์ Fastwork ของงานเดิม (จ้างเพิ่ม) | "ลูกค้ายืนยันบน Fastwork แล้ว" (`fastwork-accept` → งวดเพิ่ม) |
| ลิงก์ที่ทีมเลือกรายการให้ (ทุกชนิด) | เหมือนชนิดลิงก์นั้น (Q3) |
- รายการคำขอ + แดชบอร์ด "คำขอใหม่รอตรวจ" แสดงป้าย "รอกรอกราคา N" ให้รู้ว่าค้างที่ทีม

### 2.4 ตัวคิดราคา Fastwork · ใบเสนอราคา · ต่ออายุ

- ตัวคิดราคา (Fastwork แบบไม่ผ่านลิงก์): บรรทัดราคาเริ่มต้นมีช่องกรอกราคา (เติมราคาเริ่มต้น) · กดคัดลอกขอบเขตงาน/สร้างงานจากตะกร้า/เพิ่มเป็นงวดของงานเดิม แล้วมีบรรทัดที่ยังไม่ได้แตะราคา = หน้าต่างตรวจราคาแบบเดียวกัน (กดต่อได้เลย · Q2 ข) · ยอดเสนอใช้ราคาที่กรอก
- หน้าสถานะคำขอของลูกค้า/ผู้ซื้อ: ก่อนยืนยันแสดง "ยอดเบื้องต้น" · ยืนยันแล้วแสดงราคาที่ทีมยืนยัน + "ทีมยืนยันราคาแล้ว"
- ใบเสนอราคาที่ทีมสร้างเอง: เลือกสินค้าราคาเริ่มต้นแล้ว บรรทัดขึ้นข้อความใต้ช่องราคา "ราคาเริ่มต้น · ตรวจราคาจริงก่อนส่ง" (เตือน ไม่บังคับ เพราะทีมพิมพ์ราคาเองอยู่แล้ว)
- ต่ออายุ: ราคาต่อรอบมาจากราคาจริงในใบ (ทำอยู่แล้ว) · กล่องตั้งต่ออายุตอนรับงาน Fastwork เพิ่มช่องแก้ราคา

### 2.5 ทีมเลือกสินค้าให้ลูกค้าได้อิสระ (ผู้ใช้สั่ง 1 พ.ย. 2026)

ตอนนี้ไม่เท่ากัน: ลิงก์ที่ทีมเลือกรายการให้ = ทุกสินค้า/ชุดที่เปิดใช้งาน แต่ใส่ราคาไม่ได้ · แก้รายการในคำขอ = เพิ่มได้แค่สินค้าเดี่ยว (ชุดไม่ได้) · ตัวคิดราคา = เฉพาะที่เปิดหน้าร้าน + ติดกติกาของลูกค้า (หมวดเลือกได้อย่างเดียว · งานเพิ่มที่มีในแพ็กแล้ว) · ใบเสนอราคา = อิสระอยู่แล้ว

- **เลือกอะไรก็ได้ที่เปิดใช้งาน** ทุกที่ที่ทีมเลือกให้: สินค้า + ชุดรายการ · ไม่จำกัดเฉพาะที่เปิดหน้าร้าน · กติกาหน้าร้านเป็นแค่คำเตือน ไม่บังคับ (เช่น "แพ็กนี้มีงานนี้อยู่แล้ว")
  - แก้รายการในคำขอ: เพิ่มชุดรายการได้ (หัวข้อ + รายการในชุด)
  - ตัวคิดราคา: สวิตช์ "แสดงสินค้าที่ไม่อยู่บนหน้าร้าน" · กติกาหน้าร้านเตือนแทนการเอาออกเอง
- **ทีมเลือกสินค้าราคาเริ่มต้นเอง = ทีมใส่ราคาจริงตรงนั้น** และถือว่ายืนยันแล้ว (คนเลือกคือทีม):
  - ลิงก์ที่ทีมเลือกรายการให้: **ไม่ใส่ราคาในลิงก์** (Q3 ข้อ ก) · ลูกค้าเห็น "เริ่มต้น" · ทีมยืนยันราคาในคำขอเหมือนลิงก์ปกติ
  - แถวที่ทีมเพิ่มในคำขอ: ยืนยันในตัว
  - ตัวคิดราคา: กรอกราคาตอนเลือก

### 2.6 ลูกค้าเห็นราคาที่ปรับเมื่อไร (ผู้ใช้ถาม 1 พ.ย. 2026)

- **ระหว่างรอทีม:** หน้าสถานะคำขอบอก "ทีมกำลังตรวจราคา จดโดเมน ตามชื่อที่คุณแจ้ง"
- **กล่อง "ราคาที่ปรับจากที่คุณเลือก"** (เฉพาะบรรทัดที่ราคาต่างจากที่ลูกค้าเห็นตอนเลือก): "จดโดเมน (shopabc.co.th): ราคาเริ่มต้น 650 บาท → ราคาจริง 1,200 บาท · ราคาขึ้นกับนามสกุลและชื่อโดเมน"
  - ลูกค้าตรง: อยู่เหนือปุ่มยอมรับในใบเสนอราคาบนหน้าสถานะ
  - ผู้ซื้อ Fastwork: หน้าสถานะแสดง "ราคาที่ทีมยืนยัน" + กล่องเดียวกัน · ข้อความขอบเขตงานที่ทีมคัดลอกไปวางบน Fastwork มีบรรทัดอธิบายการปรับราคาด้วย
- ยังไม่ส่งอีเมลแจ้งเองตอนราคาเปลี่ยน (ลูกค้าเห็นเมื่อเปิดลิงก์ หรือเมื่อทีมส่งใบ/ข้อเสนอ)

### 2.7 ลูกค้ายืนยันราคาใหม่ (ผู้ใช้สั่ง 1 พ.ย. 2026: "ต้องให้ลูกค้ายืนยันอีกครั้งหรือไม่ และติ๊กไม่ต้องให้ลูกค้ายืนยันก็ได้")

| กรณี | ลูกค้ายืนยันอย่างไร |
|---|---|
| ลูกค้าตรง ออกใบเสนอราคา | กดยอมรับใบ = ยืนยันราคาใหม่ในตัว (กล่องข้อ 2.6 อยู่เหนือปุ่ม) |
| ลูกค้าตรง เปิดงานเลย (ไม่ออกใบ) | ช่องติ๊ก **"ให้ลูกค้ายืนยันราคาใหม่ก่อนเริ่มงาน"** ในหน้ายืนยันคำขอ |
| ผู้ซื้อ Fastwork | จ่ายบน Fastwork = ยืนยัน · ในระบบแสดงอย่างเดียว |

- ช่องติ๊กขึ้นเฉพาะเมื่อมีบรรทัดที่ **ราคาสูงขึ้น** จากที่ลูกค้าเห็น (ลดราคา = ไม่ต้องยืนยัน · ผู้ใช้เลือกข้อ ก) · ติ๊กไว้ให้เป็นค่าเริ่ม
- **ติ๊ก:** คำขอเป็น "รอลูกค้ายืนยันราคา" · หน้าสถานะมีปุ่ม **"ยืนยันราคานี้"** (ระบบเปิดงานให้เลย แบบเดียวกับลูกค้ายอมรับใบ) และ **"ไม่ตกลง (ให้ทีมติดต่อกลับ)"** (กลับมาที่ทีม + ป้าย "ลูกค้าไม่ตกลงราคา" + เหตุผลที่ลูกค้าพิมพ์ได้) · ระหว่างรอ ทีมแก้ราคาใหม่ได้ (ลูกค้าต้องยืนยันใหม่)
- **ไม่ติ๊ก:** ต้องเลือก/พิมพ์เหตุผล เช่น "ลูกค้าตกลงทางโทรศัพท์/แชตแล้ว" · บันทึกในคำขอ + audit
- ไม่มีบรรทัดที่ราคาสูงขึ้น = ทำงานแบบเดิม ไม่มีช่องติ๊ก

## 3. ฐานข้อมูล

- `tb_products.product_price_mode` enum เพิ่ม `'from'` · `product_price_note` varchar(150) NULL ("ราคาขึ้นกับอะไร")
- `tb_service_request_items`: `svi_needs_price` tinyint · `svi_price_confirmed_at` datetime NULL · `svi_price_confirmed_by` varchar(18) NULL FK users
- `tb_service_requests`: สถานะใหม่ `awaiting_customer` (รอลูกค้ายืนยันราคา) · `svr_price_response` enum('accepted','declined') NULL + `svr_price_response_at` + `svr_price_response_note` (ลูกค้าพิมพ์) · `svr_price_skip_reason` varchar(300) NULL (ทีมไม่ให้ลูกค้ายืนยัน)
- deploy_schema.sql (ALTER enum แบบ idempotent + คอลัมน์ + FK + manifest) · reset ไม่ต้องแก้ (ไม่มีตารางใหม่)

## 4. จุดที่ต้องระวัง

- **ราคา 0 / ลดราคา:** ราคาจริงต่ำกว่าราคาเริ่มต้นได้ (เช่น โปรโมชัน) แต่ขึ้นข้อความ "ต่ำกว่าราคาเริ่มต้น" ให้เห็น (ใช้กติกาขายต่ำกว่าราคาเดิมของใบเสนอราคา)
- **แก้คำขอหลังยืนยันราคา:** ลูกค้าแก้จำนวน/ทีมแก้ราคาอีก = ยังถือว่ายืนยันแล้ว (คนแก้คือทีม) · ลูกค้าส่งคำขอใหม่ = ต้องยืนยันใหม่
- **ลิงก์ที่ทีมเลือกรายการให้ (ล็อก):** ตอนนี้ลิงก์เก็บแค่สินค้า + จำนวน (`tb_order_link_items` ไม่มีราคา) → รายการราคาเริ่มต้นในลิงก์แบบนี้ต้องยืนยันในคำขอเหมือนกัน (Q3)
- **สินค้าแบบ % คิดจากยอด:** ใช้ราคาจริงหลังยืนยัน (ยอดเบื้องต้นก่อนหน้านั้น)
- **ข้อความ:** ไม่มี em dash · ยอดที่ลูกค้าเห็นกำกับว่า "เบื้องต้น" ทุกที่ (finance clarity)
- **ข้อมูลจำลอง:** ตั้ง "จดโดเมน" เป็นราคาเริ่มต้นทั้ง 2 ชุด + คำขอรอกรอกราคา 1 รายการ

## 5. ลำดับงาน

SP-1 ฐานข้อมูล + ตั้งที่สินค้า · SP-2 หน้าร้าน/หน้าสถานะ "เริ่มต้น" + "ยอดเบื้องต้น" · SP-3 หน้าคำขอ: รอกรอกราคา/ยืนยัน + ห้ามออกใบก่อนยืนยัน + ป้ายในรายการ/แดชบอร์ด · SP-3b ลูกค้าเห็น/ยืนยันราคาใหม่ (ข้อ 2.6 2.7) · SP-4 ทีมเลือกอิสระ (คำขอเพิ่มชุดได้ · ตัวคิดราคาเห็นทุกสินค้า กติกาเป็นคำเตือน) · SP-5 ตัวคิดราคา + ใบเสนอราคา + กล่องต่ออายุ + ข้อมูลจำลอง + เทสต์

## 6. คำถาม (ตอบ "ตามที่แนะนำ" ได้)

- **Q1 ลูกค้าเห็นอะไร:** ✅ ผู้ใช้เลือก ก (ยอดเบื้องต้น) · ก) "เริ่มต้น 650 บาท" + ยอดเบื้องต้น (แนะนำ · ลูกค้ารู้งบคร่าวๆ) · ข) "ประเมินราคาให้" ไม่แสดงราคา ไม่นับในยอด
- **Q2 ราคาเท่าราคาเริ่มต้นพอดี:** ✅ ผู้ใช้เลือก "ไม่ต้อง" (ข) · ยังถามทีมก่อนสร้างใบด้วยหน้าต่างตรวจราคา กดต่อได้เลยไม่ต้องยืนยันทีละบรรทัด · ก) ทีมต้องกด "ราคานี้ถูกแล้ว" ทุกครั้ง (แนะนำ · กันลืมตรวจ) · ข) ไม่แก้ราคา = ถือว่าใช้ราคาเริ่มต้น
- **Q3 ลิงก์ที่ทีมเลือกรายการให้:** ✅ ผู้ใช้เลือก **ก** (1 พ.ย. 2026) · ยืนยันราคาในคำขอเหมือนลิงก์ปกติ · ไม่เพิ่มช่องราคาในหน้าสร้างลิงก์

## 7. ผลการทำ (1 พ.ย. 2026)

- **SP-1:** `product_price_mode` เพิ่ม `from` · `product_price_note` (บังคับเมื่อเป็นราคาเริ่มต้น · แบบอื่นไม่เก็บ) · แผงสินค้ามีการ์ดวิธีคิดราคาแบบที่ 3 + ช่อง "ราคาขึ้นกับอะไร" · ใส่ในชุดได้ · เป็นบริการรายรอบได้ · รายการงานจากสินค้า/ตั้งต่ออายุนับเป็นราคาตายตัว
- **SP-2:** หน้าร้าน "เริ่มต้น 650.00 บาท / ปี" + "ราคาขึ้นกับ..." · ชุดที่มีแถวราคาเริ่มต้น = "เริ่มต้น" + บอกแถวในชุด · ยอดในตะกร้า "ยอดเบื้องต้น" (มีรายการราคาเริ่มต้น) · คำขอจำ `svi_needs_price` ตอนส่ง (รวมแถวในชุด)
- **SP-3:** หน้าคำขอ: ป้าย "รอกรอกราคา" + เหตุผล · ยอด "ยอดเบื้องต้น" · หน้าต่าง **"ตรวจราคาก่อนสร้างใบ"** (ราคาเติมไว้ · คำตอบของคำถามที่สินค้านั้นเลือกอยู่ข้างช่อง · ต่ำ/สูงกว่าราคาเริ่มต้นบอกใต้ช่อง) ก่อน ยืนยันคำขอ · ออกใบภายใน · รับงาน · ลูกค้ายืนยันบน Fastwork แล้ว
  - **ต่างจากแบบข้อ 2.3:** ยืนยันราคาเป็นคำสั่งแยก `PUT /V1/service-requests/:id/prices` (ก่อนคำสั่งหลัก) แทนการส่ง `confirmed_prices` มาพร้อมคำสั่ง · เหตุผล: หน้ารับงาน/งวดเพิ่มเติมยอดงวดจากราคาในคำขอ ต้องยืนยันราคาก่อนเปิดฟอร์มยอดจึงถูกตั้งแต่แรก · ความปลอดภัยเท่าเดิม: ยืนยันคำขอ/รับงาน/งวดเพิ่ม ตรวจซ้ำ ขาด = 409 `PRICE_NOT_CONFIRMED`
  - แก้ราคาในปรับรายการ = ยืนยันแล้ว (บันทึกคนยืนยัน/เวลา) · ทีมเพิ่มสินค้าราคาเริ่มต้นเอง = ยืนยันในตัว · รายการคำขอมีป้าย "รอกรอกราคา N" · แดชบอร์ด "คำขอใหม่รอตรวจ" บอก "รอกรอกราคา N คำขอ" + ช่อง "รอลูกค้ายืนยันราคาใหม่"
- **SP-3b:** เปิดงานตรง + มีแถวที่ราคาสูงขึ้น = ช่องติ๊ก "ให้ลูกค้ายืนยันราคาใหม่ก่อนเริ่มงาน" (ค่าเริ่มต้น) · ไม่ติ๊กต้องมีเหตุผล · คำขอเป็น `awaiting_customer` · หน้าสถานะลูกค้า: ขั้น "ทีมงานปรับราคาบางรายการ" + กล่อง "ราคาที่ปรับจากที่คุณเลือก" + ยอดรวมที่ทีมยืนยัน + ปุ่ม "ยืนยันราคานี้" (เปิดโปรเจกต์ · ผู้รับคำขอเป็นคนสร้าง) / "ไม่ตกลง" (ข้อความถึงทีม · กลับมารอตรวจพร้อมป้าย) · ทีมแก้ราคาระหว่างรอ = กลับมารอตรวจ ลูกค้าต้องยืนยันใหม่ · ใบเสนอราคา: กล่องเทียบราคาในใบกับที่ลูกค้าเห็น อยู่เหนือปุ่มยอมรับ · Fastwork: "ราคาที่ทีมงานยืนยัน"
- **SP-4:** ตัวคิดราคาเห็นทุกสินค้า/ชุดที่เปิดใช้งาน (สวิตช์ "แสดงรายการที่ไม่อยู่บนหน้าร้าน") · กติกาหน้าร้านเป็นคำเตือน ไม่เอาออกเอง · ปรับรายการในคำขอเพิ่ม **ชุดรายการ** ได้ (หัวข้อ + รายการในชุด · ลบหัวข้อ = ลบทั้งชุด)
- **SP-5:** ตัวคิดราคามีกล่อง "ราคาเริ่มต้น" (ราคาจริงต่อสินค้า ใช้กับแถวในชุดด้วย) · คัดลอกขอบเขตงาน/สร้างงาน/เพิ่มงวด ก่อนแก้ราคา = ถาม "ใช้ราคานี้ต่อ" · ขอบเขตงานที่คัดลอกมีบรรทัด "ราคาที่ขึ้นกับรายละเอียดของคุณ" · ใบเสนอราคาที่ทีมสร้างเอง: แถวสินค้าราคาเริ่มต้นเตือน "ตรวจราคาจริงก่อนส่ง" · กล่องตั้งต่ออายุตอนรับงาน Fastwork แก้ราคาต่อรอบได้
- **ข้อมูลจำลอง:** ชุดบริษัท "จดโดเมนรายปี" ราคาเริ่มต้น (คำขอร้านเบเกอรี่ 21 ต.ค. รอกรอกราคา) · ชุดก่อนจด เพิ่ม "จดโดเมน" ราคาเริ่มต้น (คำขอ kbi_bakery รอกรอกราคา) · สคริปต์ยืนยันราคาก่อนยืนยันคำขอทุกครั้ง
