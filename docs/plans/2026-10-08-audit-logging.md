# แผน: เก็บ log การใช้งานอย่างละเอียดเพื่อตรวจสอบย้อนหลัง (8 ต.ค. 2026)

สถานะ: **ทำเสร็จและทดสอบบนเครื่องแล้ว ยังไม่ได้ deploy**

## อ้างอิงมาตรฐาน
- OWASP Logging Cheat Sheet — บันทึก "ใคร ทำอะไร กับข้อมูลไหน เมื่อไหร่ จากที่ไหน ผลเป็นอย่างไร", ไม่เก็บความลับ, log ต้องแก้/ลบไม่ได้
- ISO/IEC 27001:2022 Annex A 8.15 (Logging) — เก็บเหตุการณ์ด้านความปลอดภัย, ป้องกัน log ถูกแก้ไข, กำหนดระยะเก็บ
- PDPA — บันทึกการเข้าถึงข้อมูลส่วนบุคคล
- แนวทางจากระบบ fasttiw (tiwwai) ที่ใช้งานจริง: audit middleware ตัวเดียวครอบทุก endpoint + error log แบบจัดกลุ่ม + หน้าอ่านอย่างเดียว

## สิ่งที่บันทึก
| หมวด | เหตุการณ์ |
|---|---|
| เปลี่ยนข้อมูล | ทุกคำขอ POST/PUT/DELETE — พร้อม **ค่าก่อน/หลังรายฟิลด์** (diff) ของแถวที่ถูกแก้ |
| ความปลอดภัย | ทุกคำขอที่ถูกปฏิเสธ (401/403/429) ทุก method, ตั้ง/เปลี่ยนรหัสผ่าน, รีเซ็ตรหัส, ขอ/ยืนยัน OTP, เปลี่ยนสิทธิ์ (แจกแจงบิตที่เพิ่ม/ลด) |
| อ่านข้อมูลสำคัญ | ดูรายชื่อ/ข้อมูลผู้ใช้งาน, เปิดหน้า log, ลูกค้าเปิดลิงก์ share |
| ข้อผิดพลาด | error 5xx ทุกครั้ง (stack, path, ผู้ใช้) จัดกลุ่มด้วย fingerprint + นับจำนวนครั้ง |
| เข้าสู่ระบบ | tb_login_logs เดิม (login / logout / login_failed) |

ทุกแถวมี: request id (ตรงกับ header `X-Request-Id`), ผู้ใช้ (+ snapshot ชื่อ/ชื่อผู้ใช้/role ณ ตอนนั้น), method, path, ชนิดข้อมูล + id, โปรเจกต์ที่เกี่ยวข้อง, ผลลัพธ์ (HTTP status), ข้อความ error, IP, user-agent, เวลาที่ใช้ (ms), เวลา (มิลลิวินาที)

## หลักการ
- **ไม่เก็บความลับ**: รหัสผ่าน, token, OTP, cookie, รหัสผ่านชั่วคราว ถูกแทนด้วย `[ปิดบัง]` ทั้งใน payload และใน diff · share token เก็บแค่ 4 ตัวแรก
- **แก้/ลบ log ไม่ได้**: ไม่มี endpoint แก้/ลบ log ใดๆ (เอาปุ่ม "ลบ log ทั้งหมด" ของหน้าเดิมออก)
- **บันทึกไม่สำเร็จต้องไม่ทำให้งานหลักพัง**: เขียน log หลังตอบผู้ใช้แล้ว (fire-and-forget + จับ error)
- **ระยะเก็บ**: 2 ปี (ตั้งได้ด้วย `LOG_RETENTION_DAYS`) ลบของเก่ากว่านั้นอัตโนมัติวันละครั้ง
- ตาราง log ใช้ id แบบ BIGINT AUTO_INCREMENT (ไม่ใช่ 18 ตัวแบบตารางอื่น) — ปริมาณสูงมาก ไม่ควรต้องล็อก tb_maxID ทุกครั้งที่บันทึก และลำดับ id = ลำดับเวลาที่บันทึก

## หน้าแอดมิน
เมนู "Log ข้อมูล" เดิม (บิต loginLogs) → 3 แท็บ: ประวัติการใช้งาน / ข้อผิดพลาดของระบบ / การเข้าสู่ระบบ
ค้นหา + กรองตามช่วงวันที่, ผู้ใช้, ประเภทเหตุการณ์, ผลลัพธ์, ชนิดข้อมูล/id · กดดูรายละเอียดเห็นตารางค่าก่อน/หลัง
