# ต่อไปต้องทำอะไร: บอกขั้นถัดไปของทุกโปรเจกต์

สถานะ: **ทำเสร็จครบ N-1 ถึง N-4 31 ต.ค. 2026** (ตอบ Q1-Q4 ข้อ ก) · ผลที่ข้อ 11

ที่มา: ผู้ใช้ "ตอนนี้ผมไม่รู้เลยแต่ละโปรเจคทำอะไรต่อ มีวิธีไหนบ้างที่เราจะบอก user ได้ว่าต่อไปต้องทำอะไร" (31 ต.ค. 2026)

## 1. ปัญหา

- หน้าโปรเจกต์มีการ์ดหลายใบ (งาน · การเงิน · Fastwork · ส่วนแบ่ง · ความต้องการลูกค้า · กิจกรรม) แต่ไม่มีที่ไหนสรุปว่า **ต่อไปต้องทำอะไร** ต้องเปิดอ่านทีละการ์ดแล้วคิดเอง
- รายการโปรเจกต์บอกแค่สถานะ + % ความคืบหน้า · แดชบอร์ดมีแถบต้องจัดการแบบรวมทั้งบริษัท ไม่บอกว่าเป็นของโปรเจกต์ไหน
- มีแค่งาน Fastwork ที่มี "ขั้นถัดไป" (`fastwork.service` → `next_step` · ป้าย `fastwork/_next-step.ts`)

## 2. หลักการ

- **กฎชุดเดียวที่ backend** (`project-next-steps.service.js`) ดูข้อมูลจริงแล้วคืนรายการ "ต้องทำ" ต่อโปรเจกต์ · ใช้ร่วม 4 จุด ป้ายตรงกันทุกหน้า
- **คิดใหม่ทุกครั้ง ไม่เก็บสถานะเพิ่ม** (ข้อลดข้อมูลซ้ำ) · ไม่มีตารางใหม่ ไม่มีงานตั้งเวลา
- **บอกเรื่องที่เร่งที่สุดเรื่องเดียวก่อน** ที่เหลือพับไว้ "อีก N เรื่อง"
- **บอกตามสิทธิ์ของคนดู**: ทำได้ = มีปุ่มพาไปทำ · ทำไม่ได้ = บอกว่ารอใคร ("รอผู้มีสิทธิ์ออกใบแจ้งหนี้") · ไม่มีสิทธิ์ดูเงิน = ไม่เห็นยอดเงิน (ข้อความไม่มีตัวเลขเงิน)
- **ทุกเรื่องมีเหตุผลกำกับบนจอ** (ข้อ explain rules in UI · ไม่ใช้ tooltip) เช่น "เลยกำหนดชำระ 5 วัน (ครบ 26 ต.ค.)"

## 3. รูปแบบข้อมูล (API)

แต่ละเรื่องที่ต้องทำ:

```
{
  key: "invoice_overdue",            // ชนิดของเรื่อง (ข้อ 4)
  level: "urgent" | "todo" | "wait" | "info",
  title: "ลูกค้าค้างจ่าย 12,000.00 บาท",   // ไม่มีสิทธิ์ดูเงิน = "ลูกค้าค้างจ่าย 1 ใบ"
  reason: "เลยกำหนดชำระ 5 วัน (ครบ 26 ต.ค. 2569)",
  action: { label: "บันทึกรับเงิน", href: "/sales/invoices/view?id=..." } | null,
  waiting_for: "ผู้มีสิทธิ์รับเงิน" | null,   // action = null เมื่อคนดูทำไม่ได้
  count: 1,
  sort_date: "2026-10-26"            // ใช้เรียงในระดับเดียวกัน (เก่าก่อน)
}
```

ผลต่อโปรเจกต์: `{ stage, items[] }` · `stage` = ขั้นของวงจร (ข้อ 5) · `items` เรียงตาม level แล้ว sort_date

## 4. กฎ (เรียงตามความเร่ง)

level: **urgent** = เลยกำหนด/เงินค้าง (แดง) · **todo** = ถึงคิวเราทำ (น้ำเงิน) · **wait** = รอคนอื่น/ลูกค้า (เทา) · **info** = ไม่มีอะไรค้าง

| key | เงื่อนไข (ข้อมูลจริง) | level | ข้อความ | ปุ่ม (สิทธิ์) |
|---|---|---|---|---|
| `invoice_overdue` | ใบแจ้งหนี้ issued ของโปรเจกต์ ยอดค้าง > 0 และ `inv_due_date` < วันนี้ | urgent | ลูกค้าค้างจ่าย {ยอด} · เลยกำหนด N วัน | บันทึกรับเงิน (`createReceipt`) |
| `tasks_overdue` | งานที่ไม่ใช่ done และ `task_due_date` < วันนี้ | urgent | มี N งานเลยกำหนด · เก่าสุด {งาน} | ดูงาน (สมาชิก) |
| `fastwork_overdue` | งวด Fastwork ยังไม่ส่ง และเลยกำหนดส่ง | urgent | งวด {ชื่อ} เลยกำหนดส่ง N วัน | เปิดงวด (`manageFastwork`) |
| `project_overdue` | `project_due_date` < วันนี้ และยังไม่ completed | urgent | เลยกำหนดส่งโปรเจกต์ N วัน | แก้กำหนดส่ง (PM/แก้โปรเจกต์) |
| `fastwork_record` | งวดส่งแล้ว ยังไม่บันทึกเงิน (`next_step = record`) | todo | ส่งงวด {ชื่อ} แล้ว รอบันทึกเงิน | บันทึกเงิน (`manageFastwork`) |
| `deposit_not_invoiced` | ใบเสนอราคาที่ตอบรับแล้ว งวดแรกยังไม่อยู่ในใบแจ้งหนี้ที่ไม่ยกเลิก | todo | ยังไม่ออกใบแจ้งหนี้งวดแรก ({ชื่องวด}) | ออกใบแจ้งหนี้ (`createInvoice`) |
| `work_done_not_billed` | งานทุกชิ้น done (หรือความคืบหน้า 100%) และยังมีงวดที่ไม่ออกใบ | todo | งานครบแล้ว ยังไม่ออกใบงวดที่เหลือ N งวด | ออกใบแจ้งหนี้ (`createInvoice`) |
| `requirements_review` | มีคำขอจากลิงก์ และลิงก์ของงานยังเปิดรับ | todo | ลูกค้าส่งความต้องการแล้ว อ่านแล้วปิดรับ | ดูความต้องการ (สมาชิก) |
| `expense_pending` | บรรทัดค่าใช้จ่ายของโปรเจกต์ในเอกสารที่ pending_approval | todo / wait | ค่าใช้จ่าย N รายการรออนุมัติ | อนุมัติ (`approveExpense`) · ไม่มีสิทธิ์ = wait |
| `no_tasks` | สถานะ planning/in_progress และไม่มีงานเลย | todo | ยังไม่ได้แบ่งงาน | เพิ่มงาน · ดึงจากใบเสนอราคา (ถ้ามีใบที่ตอบรับ) |
| `ready_to_complete` | งานทุกชิ้น done · ไม่มีงวดค้างออกใบ/ค้างเงิน · สถานะยังไม่ completed | todo | งานครบ เงินครบ ปิดโปรเจกต์ได้ | ปิดโปรเจกต์ (PM/แก้โปรเจกต์) |
| `shares_close` | เงินเข้าครบ ยังไม่ปิดยอดส่วนแบ่ง (Fastwork `close` · ลูกค้าตรง: ใบทุกใบรับเงินครบ) | todo | เงินเข้าครบ พร้อมปิดยอดส่วนแบ่ง | ปิดยอด (`manageProfitShares`) |
| `shares_pay` | ปิดยอดแล้ว มีผู้รับที่ยังไม่จ่าย | todo | ค้างจ่ายส่วนแบ่ง N คน | บันทึกจ่าย (`manageProfitShares`) |
| `requirements_wait` | ลิงก์เปิดรับอยู่ ยังไม่มีคำขอ | wait | รอลูกค้าส่งความต้องการ (ส่งลิงก์ไปเมื่อ …) | คัดลอกลิงก์ |
| `quotation_wait` | ใบเสนอราคาของโปรเจกต์สถานะ sent ยังไม่ตอบ | wait | ส่งใบไปแล้ว N วัน ลูกค้ายังไม่ตอบ · หมดอายุ {วันที่} | ดูใบ |
| `invoice_wait` | ใบแจ้งหนี้ค้างชำระ ยังไม่ถึงกำหนด | wait | รอลูกค้าจ่าย {ยอด} · ครบ {วันที่} | ดูใบ |
| `fastwork_receive` | Fastwork รอเงินเข้า | wait | รอ Fastwork โอนเงินงวด {ชื่อ} | ยืนยันเงินเข้า (`manageFastwork`) |
| `on_hold` | สถานะ on_hold | wait | พักโปรเจกต์อยู่ | เปิดทำต่อ (PM) |
| `next_task` | ไม่มีเรื่องด้านบนเลย | info | ทำงานต่อได้ · งานถัดไป {งาน} ครบ {วันที่} | ดูงาน |
| `renewal_due` | (หลังทำแผน [บริการรายรอบ](2026-10-31-recurring-services.md)) รายการต่ออายุของโปรเจกต์ใกล้ครบ/เลยกำหนด | todo / urgent | ต่ออายุ {ชื่อ} ใน N วัน | ไปหน้าต่ออายุ |

หมายเหตุ:

- **งวดใบเสนอราคาไม่มีวันครบกำหนด** (`tb_quotation_milestones` ไม่มีคอลัมน์วันที่) จึงไม่มีกฎ "งวดถึงกำหนดแล้วยังไม่ออกใบ" · ใช้ `deposit_not_invoiced` และ `work_done_not_billed` แทน · ถ้าอยากได้ ดู Q2
- โปรเจกต์ completed/cancelled: ไม่คิดกฎงาน · ยังคิด `invoice_*` และ `shares_*` (เงินยังค้างได้หลังปิดงาน) · cancelled ไม่มีอะไรเลย = ไม่แสดง
- Fastwork ใช้ `next_step` เดิมเป็นตัวตั้ง (ย้ายตรรกะไปฟังก์ชันกลางที่ทั้ง `fastwork.service` และ service ใหม่เรียก) ป้ายจึงตรงกับหน้า Fastwork เสมอ

## 5. ขั้นของวงจร (stepper)

| ขั้น | ลูกค้าตรง | Fastwork |
|---|---|---|
| ตกลงงาน | ยังไม่มีใบเสนอราคาที่ตอบรับ | (ข้ามไป รับงานเมื่อผู้ซื้อจ่ายแล้ว) |
| ทำงาน | มีงานที่ยังไม่ done | มีงวดยังไม่ส่ง |
| เก็บเงิน | ยังมีงวดไม่ออกใบ หรือใบค้างชำระ | มีงวดรอบันทึก/รอเงินเข้า |
| ปิดยอด | เงินครบ ยังไม่ปิดยอดส่วนแบ่ง | `close` |
| จ่ายส่วนแบ่ง | ปิดยอดแล้ว ค้างจ่าย | `pay` |
| จบ | ทุกอย่างครบ | `done` |

- ขั้นปัจจุบัน = ขั้นแรกที่ยังไม่ครบ · ขั้นทำงานกับเก็บเงินเกิดพร้อมกันได้ (เก็บมัดจำระหว่างทำ) → แสดงขั้นแรกที่ยังไม่ครบ และเรื่องของขั้นถัดไปยังอยู่ในรายการ
- โปรเจกต์ไม่มีใบเสนอราคาเลย (โปรเจกต์ภายใน): ซ่อนขั้นตกลงงานและเก็บเงิน (Q3)
- ไม่ได้ตั้งส่วนแบ่ง: ซ่อนขั้นปิดยอดและจ่ายส่วนแบ่ง
- มือถือ: แสดงแค่ "ขั้น 2/5 · ทำงาน" + แถบความยาว ไม่ใช่ลูกศรเต็มแถว (กันล้นจอ 360px)

## 6. 4 จุดที่แสดง

### 6.1 หน้าโปรเจกต์: กล่อง "ต่อไปต้องทำ" (บนสุด ใต้หัวโปรเจกต์)

```
ต่อไปต้องทำ                                   ขั้น 2/5 · ทำงาน
● ยังไม่ออกใบแจ้งหนี้งวดแรก (มัดจำ 50%)        [ออกใบแจ้งหนี้]
  ตอบรับใบเสนอราคาเมื่อ 20 ต.ค. 2569
▸ อีก 2 เรื่อง: มี 3 งานเลยกำหนด · ค่าใช้จ่ายรออนุมัติ 1
ตกลงงาน ✓ › ทำงาน ● › เก็บเงิน › ปิดยอด › จบ
```

- กล่องเทาอ่อน ขอบซ้ายสีตาม level (แดง/น้ำเงิน/เทา) ไม่ใช่กล่องไล่สีน้ำเงินใหญ่ (ข้อ stay on theme)
- กาง "อีก N เรื่อง" ด้วย `<details>` · ปุ่มสูง ≥ 44px บนมือถือ
- ทำเสร็จ (เช่น ออกใบแล้วกลับมา) โหลดใหม่ตอนกลับเข้าหน้า · การ์ดเดิมในหน้าไม่เปลี่ยน

### 6.2 รายการโปรเจกต์: คอลัมน์ "ต่อไป"

- ป้ายสั้น = title ของเรื่องแรก + สีตาม level · มือถือ: แสดงเป็น meta บรรทัดที่สองของการ์ด
- ตัวกรองใหม่: ทั้งหมด · **เลยกำหนด** · **ถึงคิวเรา** · **รอคนอื่น** · ตัวเลขบนตัวกรอง
- เรียงได้ตามความเร่ง (urgent ก่อน)

### 6.3 แดชบอร์ด: "สิ่งที่ต้องทำ" รวมทุกโปรเจกต์

- การ์ดใหม่ใต้แถบต้องจัดการ: รายการเรื่องระดับ urgent + todo ข้ามโปรเจกต์ แถวละเรื่อง "{ชื่อโปรเจกต์} · {title}" + ปุ่ม · สูงสุด 8 แถว + "ดูทั้งหมด" → รายการโปรเจกต์กรอง "ถึงคิวเรา"
- **เฉพาะเรื่องที่คนดูทำได้** (มี action) · ไม่มี = "ไม่มีเรื่องที่ต้องทำตอนนี้" + บอกจำนวนที่รอคนอื่น
- เห็นเฉพาะโปรเจกต์ที่ดูได้ (`viewAllProjects` หรือเป็นสมาชิก)

### 6.4 แถบขั้นตอน

ใช้ใน 6.1 (เต็ม) และใน 6.2 แบบย่อ "2/5" ไม่ทำหน้าแยก

## 7. เส้น API

- `GET /V1/projects/:id/next-steps` → `{ stage, items }` (สมาชิกหรือ `viewAllProjects` · เหมือนสิทธิ์ดูหน้าโปรเจกต์)
- รายการโปรเจกต์: เพิ่ม `next_step` (เรื่องแรก + level + จำนวน) ในผลของ list เดิม และรับ `?next=urgent|todo|wait`
- แดชบอร์ด: เพิ่ม `todo_items` ใน `/V1/dashboard/business` (หรือเส้นแยกถ้าช้า)
- **คิดแบบรวมชุด:** service รับรายการ project_id แล้วยิง query ต่อชนิดข้อมูลครั้งเดียว (`WHERE project_id IN (?)`) ไม่วนยิงต่อโปรเจกต์ · เป้า: 100 โปรเจกต์ ≤ 10 query · ≤ 200 ms บนเครื่อง dev
- กรองตามความเร่งในรายการโปรเจกต์: คิดเฉพาะหน้าที่แสดง ไม่ได้ เพราะต้องกรองทั้งหมด → คิดทุกโปรเจกต์ที่คนดูเห็นแล้วตัดหน้า (จำนวนโปรเจกต์ช่วงนี้หลักสิบ-ร้อย พอไหว · บันทึกไว้ถ้าเกิน 1,000 ค่อยทำตารางสรุป)

## 8. จุดที่ต้องระวัง

- **วันนี้ = เวลาไทย** (`todayBangkok`) · "เลยกำหนด N วัน" นับเป็นวันที่ ไม่ใช่ชั่วโมง · ครบวันนี้ = ยังไม่เลย
- **สิทธิ์เงิน:** ยอดเงินอยู่ใน title/reason เฉพาะคนที่ดูเงินได้ (กติกาเดียวกับการ์ดการเงินในหน้าโปรเจกต์) · เทสต์คนไม่มีสิทธิ์ต้องไม่เห็นตัวเลข
- **ลิงก์ที่ปุ่ม:** ไปหน้าที่ทำได้จริงพร้อมเลือกไว้ให้ (ข้อ prefill) เช่น ออกใบแจ้งหนี้ → `/sales/invoices/new?quotation=…` เลือกงวดไว้ · ห้ามพาไปหน้าที่คนดูเข้าไม่ได้
- **ใบเสนอราคาหลาย revision:** ใช้เฉพาะใบล่าสุดที่ไม่ใช่ superseded/cancelled
- **ใบแจ้งหนี้ที่มีใบลดหนี้:** ยอดค้าง = ยอดใบ − รับแล้ว − ลดหนี้ (ใช้สูตรเดียวกับหน้าลูกหนี้ ไม่เขียนสูตรใหม่)
- **ค่าใช้จ่ายหลายโปรเจกต์ในเอกสารเดียว:** นับเอกสารต่อโปรเจกต์ (ไม่ซ้ำ) จากบรรทัดที่ `exl_project_id` ตรง
- **งานย่อย:** นับเลยกำหนดทั้งงานหลักและงานย่อย · "งานทุกชิ้น done" ดูทุกระดับ
- **ข้อความ:** ไม่มี em dash · ยอดเงินมีหน่วย · ข้อความเดียวต่อความหมาย (ไม่บอกยอดค้างซ้ำ 2 ที่)
- **ไม่แตะ schema:** ไม่ต้องแก้ deploy_schema.sql (ถ้าเลือก Q2 ข้อ ข ต้องแก้)
