# ลงเวลาเข้า-ออกงาน · OT · หักมาสาย/ขาดงาน (แทนลงชั่วโมงต่อโปรเจกต์)

สถานะ: **A-1 ถึง A-4 เขียนเสร็จครบ + WFH (24 ต.ค. 2026)** · รอนักบัญชียืนยัน Y5-Y7 · 23 ต.ค. 2026 ผู้ใช้สั่ง "ทำเลย" = ตอบตามที่แนะนำทุกข้อ (Q1 ข · Q2 ก · Q3 ก · Q4 ก · Q5 ก · Q6 ข · Q7 ข)

ผู้ใช้ตอบ 23 ต.ค. 2026:
- ลงเวลาด้วย **มือถือ + GPS** (ไม่ซื้อเครื่องสแกน)
- ผูกกับเงิน: **คิด OT** และ **หักมาสาย/ขาดงาน**
- **ปิดการลงชั่วโมงต่อโปรเจกต์** (timesheet แบบเดิม)
- เวลาทำงาน **ต่างกันรายคน มีให้เลือก** = มีชุดเวลาทำงาน (กะ) ให้เลือก แล้วกำหนดให้แต่ละคน

## 1. ภาพรวม

```
พนักงาน (มือถือ)                       หัวหน้า / ฝ่ายบุคคล                         รอบเงินเดือน
──────────────────                     ─────────────────────                      ──────────────
กด "เข้างาน" (GPS + เวลาเซิร์ฟเวอร์) ─┐
กด "ออกงาน"                          ├─▶ กระดานวันนี้: ใครเข้า/สาย/ยังไม่เข้า/ลา
ลืมกด → "ขอแก้เวลา" ──────────────────┼─▶ อนุมัติขอแก้เวลา
ทำเกินเวลา → "ขอ OT" (ล่วงหน้า) ──────┼─▶ อนุมัติ OT                              ─▶ OT = เงินได้
                                      └─▶ สรุปรายเดือนต่อคน (สาย/ขาด/OT/ไม่ครบ)   ─▶ สาย/ขาด = หักค่าจ้างส่วนที่ไม่ได้ทำงาน
                                                                                     ปิดรอบไม่ได้ถ้ายังมีวัน "ข้อมูลไม่ครบ"/คำขอค้าง
```

## 2. ข้อมูลใหม่ (ตาราง)

| ตาราง | เก็บอะไร | หมายเหตุ |
|---|---|---|
| `tb_work_schedules` | ชุดเวลาทำงาน: ชื่อ · เวลาเข้า · เวลาออก · พัก (นาที) · วันทำงานในสัปดาห์ (7 ตัว จ.→อา.) · ผ่อนผันสาย (นาที) · กดเข้างานได้ก่อนกี่นาที · สถานะ | เช่น "ออฟฟิศ 09:00-18:00", "กะเช้า 07:00-16:00" · ปิดใช้งานแทนลบ |
| `tb_employee_schedules` | พนักงาน · ชุดเวลา · มีผลตั้งแต่วันที่ | ประวัติไม่หาย (เหมือนค่าจ้างตามวันที่มีผล) · ไม่ได้ตั้ง = ใช้ชุดเริ่มต้นในตั้งค่า |
| `tb_attendance_locations` | จุดลงเวลา: ชื่อ · สาขา · ละติจูด · ลองจิจูด · รัศมี (เมตร) · สถานะ | สาขาหนึ่งมีได้หลายจุด · ตั้งพิกัดด้วยปุ่ม "ใช้ตำแหน่งที่ยืนอยู่ตอนนี้" (ไม่ต้องพิมพ์พิกัด) |
| `tb_attendance_punches` | การกดแต่ละครั้ง: พนักงาน · เข้า/ออก · **เวลาเซิร์ฟเวอร์** · วันทำงาน · พิกัด · ความแม่นยำ GPS · จุดที่ใกล้สุด · ระยะ · นอกจุด? · เหตุผล · ที่มา (มือถือ/ขอแก้/ฝ่ายบุคคล) · IP · อุปกรณ์ | **แก้/ลบไม่ได้** · แก้เวลา = เพิ่มแถวใหม่ที่มาจากคำขอที่อนุมัติ + ทำเครื่องหมายแถวเดิมว่าไม่ใช้ (ประวัติครบ) |
| `tb_attendance_corrections` | ขอแก้เวลา: วัน · เข้า/ออก · เวลาที่ขอ · เหตุผล · สถานะ · ผู้ตัดสิน | อนุมัติแล้วสร้าง punch ที่มา "ขอแก้" |
| `tb_overtime_requests` | ขอ OT: วัน · ตั้งแต่-ถึง · เหตุผล · สถานะ · ผู้ตัดสิน · **นาทีที่จ่ายจริง** (คิดตอนคิดเงินเดือน) | การขอ = พนักงานยินยอมทำ OT ครั้งนั้น (ม.24) |
| `tb_payroll_settings` (เพิ่มคอลัมน์) | ชุดเวลาเริ่มต้น · อัตรา OT (วันทำงาน 1.5 · ทำงานวันหยุด 1.0 เพิ่ม · OT วันหยุด 3.0) · เพดาน OT+ทำงานวันหยุด ต่อสัปดาห์ (36 ชม.) · เปิด/ปิดลงชั่วโมงต่อโปรเจกต์ | ตัวเลขกฎหมายตั้งเป็นค่าเริ่มต้น แก้ได้ (รอนักบัญชียืนยัน) |
| `tb_employees` (เพิ่มคอลัมน์) | `emp_attendance_required` ต้องลงเวลาไหม | เช่น ผู้บริหารไม่ต้องลง (ข้อ 9 Q7) |

## 3. วิธีคิดรายวัน

**วันทำงานของการกด** = วันที่ของเวลาเข้างานตามกะ (กะข้ามเที่ยงคืน เช่น 22:00-06:00 นับเป็นวันที่เริ่มกะ)

| สถานะของวัน | เงื่อนไข |
|---|---|
| วันหยุด | ไม่ใช่วันทำงานของกะ หรือวันหยุดบริษัท |
| ลา | ลาเต็มวันที่อนุมัติแล้ว · ลาครึ่งวัน = เวลาที่ต้องอยู่เหลือครึ่งที่ไม่ได้ลา |
| มาทำงาน | มีเข้าและออก |
| **ข้อมูลไม่ครบ** | มีเข้าไม่มีออก (หรือกลับกัน) → ต้องขอแก้ก่อนปิดรอบ (ข้อ 9 Q4) |
| ขาดงาน | วันทำงาน ไม่ลา ไม่มีการกดเลย และวันนั้นผ่านไปแล้ว |

- **นาทีสาย** = เวลาเข้าจริง − เวลาเข้างาน (ถ้าไม่เกินผ่อนผัน = 0 · เกินแล้วนับอย่างไรดูข้อ 9 Q3)
- **ออกก่อน** = เวลาเลิกงาน − เวลาออกจริง (ถ้าออกก่อน)
- กดซ้ำได้: ใช้ "เข้าครั้งแรก" และ "ออกครั้งสุดท้าย" ของวัน · กดซ้ำภายใน 1 นาทีไม่บันทึกเพิ่ม (กันนิ้วกดสองที)

### เงิน (ทุกตัวเลข BigInt สตางค์ ปัดครึ่งขึ้น)
- **ค่าจ้างต่อชั่วโมง** = เงินเดือน ÷ 30 ÷ ชั่วโมงทำงานต่อวัน (พ.ร.บ.คุ้มครองแรงงาน ม.68)
- **หักมาสาย/ออกก่อน** = ค่าจ้างต่อชั่วโมง × นาทีที่ไม่ได้ทำงาน ÷ 60 · **หักได้เฉพาะเวลาที่ไม่ได้ทำงานจริง ห้ามเป็นค่าปรับ** (ม.76) · ไม่เกินค่าจ้างของวันนั้น
- **หักขาดงาน** = วันละเท่ากับลาไม่รับค่าจ้าง (ใช้ตัวหารเดียวกับที่ตั้งไว้: ÷30 หรือ ÷วันทำงาน)
- หักสาย/ขาด เหมือนลาไม่รับค่าจ้าง: **ลดเงินเดือนก่อนคิดภาษีและประกันสังคม** (สลิปแยกบรรทัด "หักมาสาย N นาที" / "หักขาดงาน N วัน")
- **OT** = นาทีที่อนุมัติ ∩ เวลาที่อยู่จริง (ดูจากเวลาออก) ปัดลงทีละ 15 นาที × ค่าจ้างต่อชั่วโมง × อัตรา
  - วันทำงานเกินเวลา: 1.5 เท่า (ม.61)
  - ทำงานวันหยุดในเวลาปกติ: เพิ่ม 1 เท่า สำหรับพนักงานรายเดือน (ม.62)
  - เกินเวลาในวันหยุด: 3 เท่า (ม.63)
  - OT + ทำงานวันหยุด รวมไม่เกิน 36 ชม./สัปดาห์ → ขอเกินไม่ได้
- OT เป็นเงินได้ (คิดภาษี) · นับเป็นค่าจ้างประกันสังคมไหม → **รอนักบัญชียืนยัน (Y5)**

## 4. หน้าจอ

### พนักงาน (มือถือเป็นหลัก)
- **บุคคล › ลงเวลา** (แทนหน้าลงเวลาเดิม)
  - เวลาตอนนี้ (จากเซิร์ฟเวอร์) · กะวันนี้ "09:00-18:00" · สถานะ "ยังไม่เข้างาน / เข้า 08:52 / ออก 18:05"
  - **ปุ่มกลมใหญ่ "เข้างาน" / "ออกงาน"** (นิ้วโป้งกดได้ · ยืนยันด้วยการสั่นเบาๆ + ข้อความ)
  - ระยะจากจุดลงเวลา "อยู่ในออฟฟิศ (35 ม.)" หรือ "อยู่นอกจุดลงเวลา 1.2 กม." พร้อมช่องเหตุผล (ข้อ 9 Q1)
  - GPS ถูกปิด/ไม่อนุญาต → บอกวิธีเปิดแยก iPhone/Android (ไม่ใช่ข้อความ error ลอยๆ)
  - เดือนนี้: แถบสรุป มา N วัน · สาย N นาที · ขาด N · OT N ชม. · ไม่ครบ N + ปฏิทินรายวัน กดวันเพื่อดู/ขอแก้
  - ปุ่ม "ขอ OT" และ "ขอแก้เวลา" เปิดแผ่นฟอร์มจากล่าง (เติมวันและเวลาให้จากวันที่กด)
- หน้า "ของฉัน": การ์ดลงเวลาวันนี้แทนการ์ดลงชั่วโมงสัปดาห์นี้

### หัวหน้า / ฝ่ายบุคคล
- **รออนุมัติ** (หน้าเดิม): เพิ่มกลุ่ม "OT" และ "ขอแก้เวลา" (ลาเดิมยังอยู่ · ลงชั่วโมงหายไป)
- **กระดานวันนี้** (ใหม่ · ในภาพรวมบุคคล): เข้าแล้ว / สาย / ยังไม่เข้า / ลา / นอกจุด · กดคนดูการกดพร้อมระยะ
- **สรุปรายเดือน** (ใหม่): ตารางคน × สาย/ออกก่อน/ขาด/OT/ไม่ครบ · ใช้ตรวจก่อนปิดรอบ · กดคนดูรายวัน
- **หน้าพนักงาน**: แท็บใหม่ "เวลาทำงาน": กะปัจจุบัน + เปลี่ยนกะ (มีผลตั้งแต่วันที่) · ต้องลงเวลาไหม · สรุปเดือนนี้
- **ตั้งค่าบุคคล**: หมวดใหม่ "กะทำงาน" · "จุดลงเวลา" · "OT และการหัก"

### รอบเงินเดือน
- รายคนเพิ่มคอลัมน์/บรรทัด: หักมาสาย · หักขาดงาน · OT (ที่มาของตัวเลขกดดูได้ในแผ่นรายละเอียด)
- **ปัญหาก่อนส่งอนุมัติ**: มีวัน "ข้อมูลไม่ครบ" · มีคำขอ OT/ขอแก้เวลาค้าง (ของเดือนนั้น)
- อนุมัติรอบแล้ว: การกด/คำขอของเดือนนั้นแก้ไม่ได้ (ล็อก **รายวัน** ไม่ใช่ทั้งสัปดาห์ — ปัญหาเดิมของลงชั่วโมงจึงหมดไป)

## 5. ปิดลงชั่วโมงต่อโปรเจกต์ (แบบเดิม)
ไม่ลบตาราง/ข้อมูลเก่า (ประวัติต้นทุนโปรเจกต์เดือนที่ผ่านมาคงอยู่) · ปิดด้วยค่าในตั้งค่า แล้วซ่อน/ตัดจุดเหล่านี้:

| จุด | เปลี่ยนเป็น |
|---|---|
| เมนู "ลงเวลาทำงาน" · หน้า /people/timesheet | ไปหน้าลงเวลาเข้า-ออกแทน (URL เดิมพาไปหน้าใหม่) |
| รออนุมัติ / ภาพรวมบุคคล / ของฉัน (ตัวเลขลงชั่วโมงค้าง) | เอาออก แทนด้วย OT/ขอแก้เวลา |
| ปัญหาก่อนส่งรอบเงินเดือน "ลงชั่วโมงยังไม่อนุมัติ" | เอาออก |
| การลา "ลาเต็มวันในวันที่ลงชั่วโมงไว้ไม่ได้" | เอาออก · ใช้ "ลาเต็มวันในวันที่กดเข้างานแล้ว → เตือน" แทน |
| ต้นทุนค่าแรงเข้าโปรเจกต์ (มาจากชั่วโมงที่ลง) | **ดูข้อ 9 Q6** |
| เดโมหน้า login ที่มีฉากลงชั่วโมง | เปลี่ยนเป็นฉากลงเวลาเข้า-ออก |

- API: POST /V1/attendance/wfh · POST /V1/attendance/wfh/:id/cancel · GET /V1/attendance/wfh/pending · POST /V1/attendance/wfh/:id/approve|reject · PUT /V1/employees/:id/wfh-days (จัดการพนักงาน) · /attendance/me ส่ง wfh_weekdays + wfh_requests · วันมี is_wfh · กระดานนับ wfh · ภาพรวมบุคคลนับ pending.wfh
- หน้าเว็บ: การ์ดกดเข้างานวัน WFH แสดง "วันนี้ทำงานที่บ้าน" แทนบรรทัดตำแหน่ง + ป้าย WFH · ปุ่ม "ขอ WFH" (เติมวันทำงานถัดไปที่ยังไม่ใช่ WFH ให้) + รายการ WFH ของฉัน · รออนุมัติมีแท็บ WFH · หน้าพนักงานแท็บเวลาทำงานมีการ์ดเลือกวัน WFH ประจำ (ปุ่มลัด ทุกวัน/ไม่มี) · กระดานมีชิป WFH · สรุปเดือนมีป้าย WFH · ภาพรวมมีงาน "WFH รออนุมัติ"
- ทดสอบ: test/api-attendance-wfh.test.js
- ข้อจำกัดที่รู้: ป้าย WFH ของวันคิดสดจากวันประจำปัจจุบัน ถ้าฝ่ายบุคคลเปลี่ยนวันประจำ วันในอดีตจะขึ้นป้ายตามค่าใหม่ (การกดแต่ละครั้งยังเก็บ ap_is_wfh ตามจริงตอนกด) · ขอ WFH วันนี้หลังกดนอกจุดไปแล้ว การกดเดิมยังเป็นนอกจุด · คำขอที่ค้างรอจนเลยวันยังอนุมัติได้ (ไม่หมดอายุเอง)

## แก้ GPS + แผนที่ (24 ต.ค. 2026)

- สาเหตุที่จับ GPS ไม่ได้บนเว็บจริง: `frontend/next.config.ts` ส่ง `Permissions-Policy: geolocation=()` = ปิดตำแหน่งทั้งเว็บ เบราว์เซอร์ตอบ "ไม่อนุญาต" ทันทีโดยไม่ถามผู้ใช้ · แก้เป็น `geolocation=(self)`
- หาตำแหน่ง: ลองแบบแม่นยำ (GPS) 15 วินาทีก่อน · หมดเวลา/จับสัญญาณไม่ได้ ลองแบบปกติอีก 10 วินาที (`use-location.ts` · ใช้ร่วมกับปุ่มในตั้งค่าจุดลงเวลา)
- แผนที่ `attendance-map.tsx` (Leaflet 1.9.4 + แผนที่ OpenStreetMap · ไม่ต้องมี API key · ต้องแสดงเครดิต © OpenStreetMap):
  - การ์ดกดเข้างาน: วงรัศมีของทุกจุด + ตำแหน่งของฉัน + วงความแม่นยำ GPS (เส้นประ) · บรรทัดตำแหน่งบอก "GPS แม่นยำ ±X ม."
  - ตั้งค่าจุดลงเวลา: แผนที่รวมทุกจุด (น้ำเงิน = ใช้งาน · เทา = ปิด) · ในฟอร์มแตะแผนที่เพื่อวางจุด วงเปลี่ยนตามรัศมีที่พิมพ์
  - มือถือปิดการลากด้วยนิ้วเดียว (ให้เลื่อนหน้าได้) ซูมด้วยสองนิ้วหรือปุ่ม +/- (ขยายเป็น 40px ใน globals.css)
- deploy: มีแพ็กเกจใหม่ `leaflet` ต้อง NPM install บน Plesk ก่อน build
- ข้อจำกัด: ระบบตัดสินในจุด/นอกจุดจากระยะถึงจุดศูนย์กลางเท่านั้น ไม่เอาความแม่นยำ GPS มาคิด (ในอาคาร GPS คลาด 20-50 ม. จึงแนะนำรัศมี 100-200 ม.) · แผนที่ OpenStreetMap ใช้ฟรีสำหรับปริมาณน้อย ถ้าคนใช้มากขึ้นต้องย้ายไปผู้ให้บริการแผนที่แบบเสียเงิน
