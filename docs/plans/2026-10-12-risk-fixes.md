## จุดที่ตรวจโค้ดจริงแล้ว (ปรับคำอธิบายจากแบบเดิมให้ตรง)
- **R1** แม่นขึ้น: หน้าแก้ role โหลดสิทธิ์เป็นอาร์เรย์ยาวเท่าสตริงในฐานข้อมูล (บิตที่หน้าเว็บไม่รู้จักยังอยู่) **แต่ปุ่ม "เลือกทั้งหมด/ยกเลิกทั้งหมด"**
  สร้างอาร์เรย์ใหม่ยาว `TOTAL_BITS` ของหน้าเว็บ (`settings/roles/edit/page.tsx:89`, `create/page.tsx:71`) → กดแล้วบันทึก = บิตที่เกินหายหมด
  + กรณีแท็บเก่าค้างหลัง deploy · backend (`role.controller.js` create/update) ไม่ตรวจอะไรเลย รับสตริงอะไรก็ได้
- **R2** แม่นขึ้น: pool ตั้ง `timezone: "+07:00"` + `SET time_zone` ทุก connection แล้ว → `CURDATE()`/`NOW()` ฝั่ง SQL ถูกต้อง ·
  คอลัมน์ DATE กลายเป็น JS Date เวลา 00:00 ไทย (= 17:00 UTC วันก่อน) — หน้าเว็บเดิมแปลงด้วย `timeZone: "Asia/Bangkok"` ทุกจุด (`formatDateOnly`, `toDateInputValue`) จึงแสดงถูก ·
  **ที่ผิดคือโค้ด backend ที่ใช้ `getFullYear()/getMonth()/getDate()` ของเครื่อง**: `generateDailyId.js`, `documentNumber.js` (ร่าง), `dashboard.controller.js:18-19`
- **ใหม่ R20** — ลบข้อมูลที่ถูกอ้างอิงอยู่ได้ error 500 ข้อความกลางๆ: `user.controller.js remove` ลบผู้ใช้ที่เคยสร้างโปรเจกต์/เป็นสมาชิกโปรเจกต์ → ชน FK
  (`fk_project_creator`, `fk_pm_user` ไม่มี ON DELETE) · `role.controller.js remove` ลบ role ที่มีผู้ใช้อยู่ → ชน `fk_user_role` · `error.middleware.js` ไม่มีการแปล error FK เลย
- **ใหม่ R21** — แดชบอร์ดเลือกเดือนปัจจุบันด้วยเวลาเครื่อง (`dashboard.controller.js:18-19`) → ถ้าเครื่อง production เป็น UTC ช่วง 00:00–07:00 ของวันที่ 1 จะแสดงเดือนก่อน
- **ใหม่ R22** — `isOverdue` ในแดชบอร์ด (`dashboard/page.tsx:176`) ใช้เวลาเครื่องของผู้ดู — คนในไทยไม่เป็นไร คนอยู่ต่างประเทศเห็นเลยกำหนดเพี้ยนได้ ≤1 วัน (ความรุนแรงต่ำ)

### ก2. R2 + R21 วันที่/เวลาไทยที่เดียวทั้งระบบ
**ตัดสินใจ: ไม่เปลี่ยน `dateStrings` ของ pool** — ถ้าเปลี่ยน รูปแบบวันที่ใน API ของหน้าเดิมทุกหน้าจะเปลี่ยน (ISO → "YYYY-MM-DD") เสี่ยงกว่าปัญหาที่แก้
ใช้วิธีห้ามอ่านส่วนวันที่จากเวลาเครื่องแทน:

| ส่วน | สิ่งที่ทำ |
|---|---|
| ใหม่ `backend/src/utils/bangkokTime.js` | `todayBangkok()` → "YYYY-MM-DD" · `ymdBangkok(dateOrString)` → "YYYYMMDD"/"YYYY-MM-DD" (ใช้ `Intl.DateTimeFormat` + `timeZone: "Asia/Bangkok"`; สตริง "YYYY-MM-DD" ใช้ตรงๆ ไม่แปลง) · `currentYearMonthBangkok()` · `addDays(ymd, n)` (คำนวณบนปฏิทิน ไม่ผ่าน timezone) |
| `generateDailyId.js` | ใช้ `ymdBangkok(new Date())` แทน getters ของเครื่อง |
| `documentNumber.js` (ร่าง) | ใช้ `ymdBangkok` |
| `dashboard.controller.js:18-19` | ใช้ `currentYearMonthBangkok()` |
| เทสต์กันถอยหลัง | `test/bangkokTime.test.js` ทดสอบเวลาขอบ (23:59/00:00/06:59/07:00 ไทย, สิ้นเดือน, สิ้นปี, 29 ก.พ.) · `test/no-local-date-getters.test.js` สแกน `backend/src` ห้ามมี `.getFullYear(` `.getMonth(` `.getDate(` `.getHours(` นอก `bangkokTime.js` (เจอ = เทสต์ล้ม) |
| สคริปต์เทสต์ | `npm test` รัน 2 รอบ: ปกติ + `TZ=UTC` (ผ่าน `cross-env` หรือสคริปต์ node ตั้ง `process.env.TZ` ก่อนโหลด — ตรวจว่าใช้ได้บน Windows) |
